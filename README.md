# 10g_fpga_tcp_ip_stack — 纯硬件 TCP/IP 数据面（1G 已验收，10G 已达标，PCIe 通路已打通）

## 这是什么

一块 **XCKU5P** FPGA 开发板（Kintex UltraScale+ 系列芯片，板载 2 个 SFP+ 万兆光纤插槽、1 个千兆电口、1 条 PCIe x4 插槽），
上面用 Verilog 硬件描述语言实现了一整套 **TCP/IP 协议栈数据面**：万兆光口（官方物理层 IP + 自写 64 位 MAC——
即以太网"媒体访问控制器"，负责成帧/校验的硬件模块）与千兆电口（RGMII 接口：千兆电口的标准接法）两个前端，
共用同一条 64 位数据流水线（ARM AXI-Stream 流格式：一拍拍传数据、带握手机制，每时钟周期处理一个字）。
TCP/UDP 数据段走纯硬件快路径；ARP、ping、TCP 握手等慢速控制包走用 C 语言编写、经高层综合（HLS，"用 C 代码自动生成硬件"的工具）生成的硬件协议栈。
板子插在 PC 的 PCIe 插槽上，PC 通过由 **85 个** 32 位寄存器组成的观察窗口读取板内计数器与状态（像读内存一样访问；
窗口规模随代际演进 63→…→76→85 字，现役构建 0x32）——本板没有串口，这是唯一观测手段。
项目终局目标是"TCP 卸载引擎"（TOE）：对上提供 TCP/UDP 调用接口，支撑低延迟行情接收（UDP 组播）与交易发送（TCP 少量连接）。

## 协议功能全景

| 协议 | 分层 | 实现位置 | 范围与状态 |
|---|---|---|---|
| 以太网 MAC（成帧 / FCS） | 链路层 | 自写 RTL | 10G：64 位 XGMII，线速达标（813,794.7 帧/s，载荷 9.531 Gbps）；1G：RGMII，已验收（956.0 Mbps）；**双 SFP+ 第二口已板级验证**（2026-10-27 D9R：双口同时各下行 8.94 Gbps） |
| VLAN（0x8100 / 0x88A8） | 链路层 | RTL（vlan_strip） | 已实现：识别并剥离标签；带标签帧走慢路径 |
| ARP | 网络层 | HLS 慢路径 | 已实现：请求应答 |
| IPv4 | 网络层 | 快路径 RTL（数据段）+ HLS 慢路径（其余） | 单 IP 已验收；双板 IP（IP_A / IP_B）随 C4 双栈实施，双口板级灌流已通过（D9R） |
| ICMP（echo） | 网络层 | HLS 慢路径 | 已实现：ping 应答 |
| IGMP v1 / v2 | 网络层 | HLS 慢路径 | 已实现；v3 不支持 |
| DHCP 客户端 | 应用层 | HLS 慢路径 | 已实现 |
| UDP | 传输层 | 快路径 RTL（收发主体）+ HLS echo（8080）参考实现 | 已验收：1G 956.0 Mbps；10G 线速达标 |
| TCP | 传输层 | 快路径 RTL（数据面）+ HLS 慢路径（握手等控制面） | 1G 已验收；10G 业务实测通过。含：被动 / 主动握手、数据收发、重传、窗口缩放、零窗探针、RST、孤儿会话回收、**每连接在飞上限 61,440 B（≈42 个满帧）与窗口配额管理器**；低速吞吐区机理未定位（见「已知边界」） |

慢路径整体限速 ≈1.25 Gbps（64 位字入、1 字节/拍出）：ARP / ping / 握手等控制面流量足够，不承载批量数据。

## 当前状态

- **板上现役 = 构建 `0x32`**：C4 双栈（两套快路径 + 共享窗口配额池）；快照观察窗 **85 字**（W0..W84）/ 未实现地址 `0x184`，
  板卡 `0x08 = 0`（未受控停流）、`carrier = 1/1`（两个光口链路均 up）。每次测量前重烧位流并核对 sha256 与板侧构建编号（BID），是本仓铁律
  （源：`_proj_10g/notes/p11_board_p3_0x32_20261026/burn/BURN_0x32_20261027_003211.txt`；台账 §10-165/§10-166）。
- **1G 数据面**：已板级正式验收，35 条判据全过，956.0 Mbps。
- **10G 方向**：物理层验收通过（误码率上界 4.997×10⁻¹³）→ 线速达标（813,794.7 帧/秒，线上载荷 9.531 Gbps）→
  业务实测、长时发送通过；四条真实缺陷已修复并经板级验证（时钟管理器失锁重锁、RFC 序号回绕比较、连续模式换流时序、MDIO 工具链）。
  **P11 阶段（2026-10-18 起）再进一步**：双 SFP+ 第二口接入 → C4 双栈位流线——0x2F 构建时序失败（WNS −6.456，根因 = 窗口配额
  管理器单组合链 42 级）⇒ 管理器重写为事件机 + 0x31 构建通过（WNS +0.031）⇒ 0x32 = 0x31 + HLS ROM 修复（WNS +0.019，现役）；
  构建脚本新增**时序硬门**（WNS>0 且三类失败端点全 0，不达标位流自动改名隔离、禁烧）与 **TCB 写口族定向时序门**
  （源：`_proj_10g/notes/p11_fix_0x30_0x31_20261025/README_FOR_TL.md`；`p11_fix_0x31_rom_0x32_20261026/README_FOR_TL.md`）。
- **双口板级达标（D9R，2026-10-27）**：双 SFP+ 口同时各下行 10 GB，A 口 8.9367 / B 口 8.9352 Gbps
  （host 侧合计 17.8719 Gbps），逐字节零失配、无停顿（源：`_proj_10g/notes/p11_board_p3_0x32_20261026/raw/`；台账 §10-165）。
- **E0.5 满载延迟基线（2026-10-27）**：单连接单口下行 9.44 Gbps 级 = 线上载荷天花板 9.49285 Gbps 的 99.45–99.50%
  （sink 侧墙钟 ±0.2% 误差棒；板侧以拍钟为准），TX 线 99.86% 时间在忙；四跑 24 GB + 两跑 60 GB 合计
  **216 GB 逐字节零失配**。发现**快 / 慢两个连接级稳态**（6 连接 = 3 快 3 慢，各态可在单连接内持续 ≥40 s）：
  慢态空闲的 92–93% 是在等板自己的窗口（在飞上限 61,440 B ≈ 42 个满帧），**整窗排空最坏 52 µs**
  （随机到达的附加等待 ∈ [0, 52] µs、均值约 26）——结构最坏值，不是实测尾延迟；快 / 慢态翻转机理【未定位】
  （源：`_proj_10g/notes/p11_e05_latency_20261027/README_FOR_TL.md`；台账 §10-165/§10-166）。
- **PCIe 数据通路**：「SFP+ → 板上协议栈 → PCIe → 驱动 → PC 程序」链路已打通，
  镜像载荷在 UDP/TCP 两种来源、任意字节对齐下逐字节零失配；线速档 PC 侧单探针 8.66 Gbps（入口速率的 94%）；
  URAM 板内缓冲（32 KB）把丢字节量降低 单源 56% / 4 源 33%（同会话对照归因 62% / 52%）。
- **孤儿会话修复完成**：对端失联后未被板卡回收、持续占用槽位的会话，现在有失联判据回收机制
  （回收连接状态、CAM 表项与配额），观测窗新增 W75 = 孤儿会话回收计数。板级对照验证正结果：
  修复版在失联约 61.7 s 后回收（两次独立复现）且新连接恢复 802 Mbps 满速零失配；旧版（0x28）不回收、槽位卡死。

## 已知边界（未测 / 未判定项照实，全文见 `_proj_10g/notes/P7B_OPEN_ITEMS.md` 与台账）

- **快 / 慢态翻转机理【未定位】**：满载单连接存在 9.44 Gbps（快）与 9.07–9.26 Gbps（慢）两个连接级稳态，
  与对端 ACK 稀疏程度相关但无逐包见证；候选 = 对端 ACK 路径动力学（唯一与全部板侧证据相容）/ RSS 队列与核亲和；
  p99 尾延迟【未测】（E0.5 只有占空/计数器）（源：`p11_e05_latency_20261027/README_FOR_TL.md` §3）。
- **观测口径**：W69（等窗操作点锁存）不可用——单点锁存且被"扫描拍陈旧样本"污染，W66/W67 的"非板帽侧"读数
  含约 1/16 的扫描伪拍，不能直接读作对端通告窗（源：同件 §1.1/§3.2；kimi xr11 审查 H-1/H-2 及回灌）。
- **双口窗归因**：窗口等待计数器只接了 A 口，口 B 结构性无窗归因仪器；双口同时满载的窗归因【未测】；
  8×12KB 多连接配额合同【未测】（源：同件 §3.3）。
- **低速吞吐区**（大批量传输中速率掉到 ~1 Mbps 低位的异常区间）：进入条件已证（两条连接并行抢流，两次独立复现）、
  重烧位流可清除、大接收缓冲的连接免疫；板侧机理【未定位】。"零窗占比是主因"获预注册判据支持（分水岭在接收缓冲 7000→8000），
  但 12000 档实测为第二慢区 ⇒ 零窗不是唯一轴，因果方向【未判定】。
- **P-3**（换流复位被同拍装配写覆盖）：板级判据迄今未获有效判别力【未测】，去向（继续实验 / 转设计侧）留用户裁定。
- **孤儿会话修复残余**：空闲死对端（inflight=0）不回收（F6-a 未闭）；两个长时压力臂（B5b / B5c）未跑；
  app 内部 closing/active 无快照字，自愈只有行为面证据。
- 1G 时代遗留的接收方向字节损坏专题未结（`agent_docs/ISSUE_RX_BYTE_CORRUPTION.md`，机制未证实）。
