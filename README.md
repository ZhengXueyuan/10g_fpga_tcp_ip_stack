# udp_hls_10g — 纯硬件 TCP/IP 数据面（1G 已验收，10G 已达标，PCIe 通路已打通）

## 这是什么

一块 **XCKU5P** FPGA 开发板（Kintex UltraScale+ 系列芯片，板上有 2 个 SFP+ 万兆光纤插槽、1 个千兆电口、1 条 PCIe 高速扩展插槽），
上面用 Verilog 硬件描述语言实现了一整套 **TCP/IP 协议栈数据面**：万兆光口（万兆以太网物理层 IP + 自写 64 位 MAC——
即以太网"媒体访问控制器"，负责成帧/校验的硬件模块）与千兆电口（RGMII 接口：千兆电口的标准接法）两个前端，
共用同一条 64 位数据流水线（ARM AXI-Stream 流格式：一拍拍传数据、带握手机制，每时钟周期处理一个字）。
TCP/UDP 数据段走纯硬件快路径；ARP、ping、TCP 握手等慢速控制包走用 C 语言编写、经高层综合（HLS，"用 C 代码自动生成硬件"的工具）生成的硬件协议栈。
板子插在 PC 的 PCIe 插槽上，PC 通过由 75 个 32 位寄存器组成的观察窗口读取板内计数器与状态（像读内存一样访问）——
本板没有串口，这是唯一观测手段。
项目终局目标是"TCP 卸载引擎"（TOE）：对上提供 TCP/UDP 调用接口，支撑低延迟行情接收（UDP 组播）与交易发送（TCP 少量连接）。

## 现在处于什么阶段（2026-10-16）

- **1G 数据面**：已板级正式验收，35 条判据全过，956.0 Mbps（2026-09-29）。
- **10G 方向**：物理层验收（误码率上界 4.997×10⁻¹³）→ 五个施工阶段关卡全部收口 → **线速达标**（813,794.7 帧/秒）→
  业务实测 → 长时发送 → 窗口机制分析 → 缺陷修复批次（重放越界 / 零窗探询 / 窗口守卫）→
  **四条真实缺陷全链闭环（2026-10-16）**：F-3（时钟管理器失锁重锁）、RFC 序号回绕比较、连续模式换流时序、MDIO 工具链——
  每条都是"修复 + 构建 + 板级证据"（证据形态各异：F-3 = 板上不可受控触发 ⇒ "未观测到"；RFC 序号 = 注入对照正结果；
  换流时序 = 正臂 7/7 连接全过；MDIO = 板测三条判据全中 + 变体对照）。
- **PCIe 数据通路（里程碑 P8/P9）**：用户指定的"SFP+ → 板上协议栈 → PCIe → 驱动 → PC 程序"链路已打通，
  镜像载荷在 UDP/TCP 两种来源、任意字节对齐下逐字节零失配；PCIe 用户接口已从内存映射模式改造为流模式（AXIS）并完成板级对照验证。
- **P9 增量（2026-10-13～14，PCIe 通路性能轮）**：线速档补测完成——PC 侧单探针 **8.66 Gbps（入口速率的 94%）**，
  丢字节机制定案 = 电脑读数据调用内部的固定空档，新双缓冲模式让丢字节量再降 **57–70%**；
  URAM 板内缓冲（32 KB）已实施、构建 **0x24** 并完成板级验证——单源丢字节 **−56%**、4 源 **−33%**
  （同会话对照归因：单源 −62% / 4 源 −52%）。
- **板上现役与下一步（2026-10-16 终态）**：板上现役 = `0x28`（构建编号 BID `0x28` / 快照窗口 **75 字** / 未实现地址 `0x15C`）
  + `0x08 = 0`（未受控停流）+ `carrier = 1`；两机（本机与对端 Linux 机）**保持开机**（本轮结束不关机）。
  `0x28` 新增换流四观测计数器（观察窗口 W71..W74），板级已直测"触发条件本身"
  （顺序构型在结构上碰不到触发面；并行换流构型触发面被激励）。
  **下一步 = 清理剩余未结项**（清单见 `_proj_10g/notes/P7B_OPEN_ITEMS.md`，全文以它为准）。当前最重要的五条：
  ① URAM 缓冲版（0x24）的"负对照资格"存疑【未判定】——历史"对端看到图案另一段"（相位错）构型在 0x24 上不可复现，但"两臂同绿"不区分两臂；
  ② 该历史相位错的逐代二分定位（0x1A→0x24）【未做】；③ 涓流连接（约 1 Mbps / 约 400 s，2 例）机理【未定位】；
  ④ 换流复位被同拍装配写覆盖（设计代号 P-3）的"窗口命中"无任何直接见证【未测】；
  ⑤ 快照阵列异步复位族 = 下一轮加大逻辑的第一观察对象（0x28 时序余量仅剩 1.02%，【已登记】）。
