## 这个目录是什么

这是 **XCKU5P Mini 板卡的原始资料包**（不是软件工程）：厂商提供的原理图、用户手册、芯片数据手册、
参考设计（Vivado 工程）、XDMA 驱动和调试小工具。没有 git、没有构建脚本、没有 CI。

**当前目标：在此板卡上开发 10Gbps 网络应用。** 下面所有内容按此目标组织。

### ✅ 闸 G 结果（KU5P 上的第一个真实时序基线，2026-09-28）—— **数据面在 16nm 上直接收口**

`udp_hls_10g/board/build_p6a_ku5p.tcl` + `board/ku5p_p6a_{t8p0,t6p4}.xdc`（与 K7 闸 B **逐项同构**，只换器件/前端/引脚），读数在 `udp_hls_10g/p6a_ku5p_verify/`：

  前置闸 U1 的答案：**16nm -1 速度等级吸收有余**，P6b 的"数据面切 156.25MHz"不再是阻断级风险。

## 10G 硬件约束（最重要的一条）

用户手册明确写着：

> 因板卡采用核心板＋底板模式受限于连接方式与 PCB 板材原因，Aurora 64B/66B **仅能在最高
> 12GHz 速率下稳定运行**（测试代码即为 12GHz 速率）；ibert 眼图测试可在 16GHz 速率下稳定运行。
> 客户自行准备光模块时若使用频率低于 10GHz 可使用 SFP 光模块与线缆，如果使用频率高于 10GHz
> 则只能使用 SFP28 光模块与线缆

对本项目的含义：

- 10GBASE-R 线速率 **10.3125 GBd**，走的就是 64b/66b —— 与手册里 12GHz 的 Aurora 64b66b
  结论同一物理机制。**10.3125 < 12，理论上可通过，但裕量只有 ~14%，属于贴边设计。**
- 瓶颈是**核心板↔底板的板对板连接器 + PCB 板材**，不是 FPGA。这是物理层的硬限制，
  改逻辑、改均衡参数都救不回来。若 10G 链路误码率不达标，先怀疑这里，别先怀疑代码。
- 光模块/线缆选型：**10G 及以上必须用 SFP28 模块和线缆**，普通 SFP 只能用在 10GHz 以下。
- 关于 bring-up 顺序的建议：先用现成的 iBERT 工程把 GTY 眼图打开（16GHz 都能稳，10G 有余量），
  确认物理链路 OK，再上协议层。

  （`gt_refclk1_P = V7` 与 `aurora_rxp[0] = Y2`），极易混淆。

  （iBERT 本可在 GUI/Tcl 里改参考钟频率，但本机因缺器件数据改不了 —— 见第 3 条）；
  **RGMII 以太网不受影响**。
- **不影响别的子系统**：Y1(100 MHz 差分) → `SYS_CLK_P/N`(T25/U25, bank65)，兼作 DDR4 MIG 的 `sys_clk`；
  Y4(25 MHz 无源晶体) 只给 RTL8211E；**PCIe 参考钟来自金手指**（J10 A13/A14 → `MGT224_CLK0` → AB7/AB6）。
- 全板**只有三处 refclk 有源**：quad224 = 金手指、quad225 = Y2、quad227 = 走底板；
  其余 quad 的 REFCLK1 及 quad226 的 REFCLK0 **原理图上无网络名（悬空）**。
- ⚠️ **SFP 控制脚的实际映射（2026-09-27 板级实测更正 —— 厂商两份 XDC 都错）**：

  | 信号 | **实测正确** | 厂商 XDC 写的 |
  |---|---|---|
  | `SFP1_TX_DIS` | **C11** | B11 |
  | `SFP1_RX_LOS` | **B11** | C11 |
  | `SFP2_TX_DIS` | **D9** | C9 |
  | `SFP2_RX_LOS` | **C9** | D9 |

  证据 = **三态判别实验**：只驱动 B11/C9 低 ⇒ 4 个 GT 全黑（RX_BER 0.50）；**四个脚全驱动低 ⇒ 链路立起**
  （未接线的 X0Y6/X0Y7 同时仍是 0.49，完美对照）；**只驱动 C11/D9 低 ⇒ 链路依然立起**。
  ⇒ 两份厂商 XDC（iBERT 例程 + 参考设计 `PCIe.xdc`）**都把每对脚对调了**；作废的 `Aurora_sfp.xdc`
  写的 `J8/P8` 更是**物理不可能** —— Vivado 封装模型显示 **J8 与 P8 在这个器件上是 GND 球**。
  ⚠️ **后果严重**：按错的映射做设计 ⇒ **`TX_DIS` 悬空、被 10k 上拉拉高 ⇒ 光模块发射永久关闭**
  ⇒ 现象是"两个方向全黑"，**极易被误判成"板子做不了 10G"**。

### `Demo/XCKU5P_PCIe_DDR4_ETH_aurora_12g/` —— 主参考设计（厂家出厂测试代码）

Top 模块 **`DDR_PCIE_ETH_SFP_TOP`**，源文件在 `src/`，Vivado 工程在 `vivado/ku5p/`
（注意 srcs 目录名拼写为 `..._arurora.srcs`，少一个 `o`，是原厂笔误，别当成自己搞错了）。

```
DDR_PCIE_ETH_SFP_TOP                     src/adv_prj/TEST_PRJ/TEST_PRJ_lib/hdl/
├── pcie_ddr_bd_wrapper  (Block Design)  ← XDMA + MIG DDR4
├── K7_test_TOP                          ← Aurora64b66b + Ethernet，K7 移植来的
│   ├── Aurora64b66b_TOP                  2 lane, 12Gbps, GTY X0Y4/X0Y5
│   └── Ethernet_TOP                      软 RTL 协议栈
└── io_trig                              ← 驱动全部 105 根 io_nor 的 200ms 方波（点灯测试用）
```

**Block Design `pcie_ddr_bd`**（唯一一个 BD）：

- `xdma_0` 4.1：Gen3 x4，AXI 128-bit，AXI 时钟 250MHz，Device ID `0x9034`，QPLL1
- `ddr4_0` 2.2：MIG，`MT40A512M16HA-075E`，16-bit，1200MHz（DDR4-2400），AXI 128-bit
- `axi_interconnect_0` → `auto_cc`（时钟转换）→ DDR4；XDMA M_AXI 映射到 DDR4
  偏移 `0x0`，范围 512M
- 外部端口：`pci_exp`、`pcie_sys_clk`(100MHz)、`c0_ddr4`、`sys_ddr_clk`(100MHz)、
  `user_lnk_up_0`、`pcieReset`(ACTIVE_LOW)、`o_clk`(100MHz)、`ddr_rst`、`c0_init_calib_complete_0`
- BD 内含 MicroBlaze MCS 跑 bootloop，那是 **MIG 校准控制器，不是用户逻辑**

**以太网协议栈（`src/adv_prj/TEST_PRJ/ETHernet/`）—— 全软核，手写 RTL，8-bit 数据通路**：

```
RGMII_Tri (IDDR/ODDR, BUFIO/BUFR)
  → GMII2RGMII_Drive (RGMII_RAM 跨时钟 FIFO)
  → UDP_Stack_Module
      ├── Ethernet_MAC  (MAC_rx/tx, CRC32_D8, mac_arp_ip_mux)
      ├── Ethernet_IP   (IP_rx/tx)
      ├── Ethernet_UDP  (UDP_rx/tx, udp_ready)
      ├── Ethernet_ICMP (ICMP_rx/tx)
      └── Ethernet_ARP  (ARP_rx/tx, ARP_Table)
```

- 协议栈参数：端口 8080，目标 IP `192.168.31.3`，板卡 IP `192.168.31.100`，
  MAC `01:02:03:04:05:06`
- **没有 MMCM/PLL**：整条以太网通路跑在 PHY 回送的 RGMII RX 时钟 `i_rxc` 上
  （千兆时 125MHz），与 Aurora/DDR4/PCIe 完全独立，`RGMII_RAM` 是唯一跨时钟点
- `Ethernet_TOP` 内部把 `eth_rstn`/`eth_mdc`/`eth_mdio` **硬接成 1**，MDIO 没有真正驱动

**对 10G 的可复用性判断（关键）**：

- ❌ **MAC 层往下全部不可复用**：`RGMII_Tri` / `GMII2RGMII_Drive` / `MAC_rx` / `MAC_tx`
  是 8-bit GMII @125MHz 的 1G 实现。10G 是 64-bit XGMII @156.25MHz，且需要 GT + PCS/PMA。
- ⚠️ **ARP / IP / ICMP / UDP 层理论上可复用，但都是 8-bit 逐字节**，直接搬到 10G 会成为
  吞吐瓶颈。要么整体加宽到 64-bit，要么在 XGMII 和 8-bit 栈之间插宽度转换 FIFO
  （代价是延迟和缓冲深度）。
- ✅ 参考设计里**没有**任何 1000BASE-X / SGMII / PCS-PMA 路径，一张白纸，不用考虑兼容旧路。

## 已知陷阱

1. **`io_nor[104:0]` 占掉 105 根引脚**，只是被 `io_trig` 当成 200ms 方波点灯总线。
   新设计要引脚先删它。

2. **SFP 控制信号在 RTL 里被硬接成常量**：`Aurora64b66b_TOP.v` 中
   `SFP1_RX_LOS` / `SFP2_RX_LOS` / `SFP1_TX_DIS` / `SFP2_TX_DIS` 全部 `= 0`。
   约束把这些信号驱动到了真实引脚，但值是常数 —— 想真正控制 SFP 得改 RTL。

3. **`Aurora_link_LED` 在顶层悬空**（`.Aurora_link_LED ()`），且它和 `SFP1_RX_LOS` 等
   被排在 `io_nor` 总线里。当前顶层**没有 Aurora link 状态指示**，调试时别指望那个 LED。

4. **HDL 源码是 Mentor HDL Designer 2021.1 生成的**（`K7_test_TOP.v` 等文件头有标注，
   `adv_prj` 下有 `.bd`/`struct.bd` 结构文件）。手改这些 `.v` 后若有人用 HDL Designer
   重新导出，改动会被覆盖。大规模改动建议逐步脱离 HDL Designer 流程。

5. **顶层命名与文件位置有错位**：`Aurora64b66b_TOP.v` 躺在 `Aurora8b10b_lib/` 目录下，
   但它包的是 64b66b 核；同名老文件 `Aurora8b10b_test.v` / `IP_TEST.v` / `Aurora_ip_TOP.v`
   引用了**不存在的** `Aurora8b10b_TOP`，是死代码，别看错文件。

6. **工程里有未加入的文件**：`CRC_Data_Process.v`、`udp_ready.v`、整个
   `TEST_PRJ_lib/mig_DDR3_B2/`（K7 的 DDR3 MIG）等都躺在磁盘上但不在 `.xpr` 里。

7. **`pcieReset` 极性**：BD 端口声明为 `ACTIVE_LOW`，经 `util_vector_logic_0` 反相后送
   `ddr4_0/sys_rst`；而顶层的 `ddr_rst` 输入硬接 `1'b0`。移植时注意别搞反。
