每个里程碑除了实现，还要主动开**审查 agent** 和**测试 agent**，不要只写代码自测。

**Why:** 用户 2026-08-28 指出"你从来不开审查和测试的 agent，以后也要开"。此前 tcp_tx_frame 的 tail_d 位宽截断、snd_nxt 竞态两个真 bug 都是测试 agent 抓出来的。

**How to apply:** 结合"功能确定的小任务优先用 agent team"的既有约定：RTL 主设计可由主会话完成，但 (1) TB/模型/回归跑活用测试 agent，(2) 每个模块完成后开独立审查 agent 读 RTL 找竞态/位宽/边界问题（主会话自查容易盲区），(3) 报告要求短（≤400 词）、不贴代码。参考 [[perfv-udp-eco-migration]]。

## 并发 agent 的两条纪律（2026-09-29 P6b 实战，各踩一次）

1. **文件所有权必须互斥，且派单时显式列出"别人正在写什么"**。
   我让一个 agent"扫描全仓 243 个门 bat 装守卫"，它扫到了另一个 agent **当天新建**的 harness ⇒
   两边各自**整文件重写**了同一个文件 ⇒ 事后**无法判定谁写了什么**（"是否同版"只剩 mtime + 内容推断）。
   **推论：整文件重写会毁掉证据链** —— agent 重写自己的 harness 之前必须先留存旧版（或把改动做成补丁）。
   ⚠️ 但**不要**把"越界"当既成事实：本例里硬化 agent 的 363 文件记录 + `--dry` 复查证明越界**并未发生**
   （所有权冲突清单 = 0 条）—— 两个 agent 的说法矛盾且无法裁决，**如实记录冲突，不要替任何一方下结论**。
2. **不要把"当前没有并发"这类**时间窗口**说给一个稍后才执行的 agent 听**。
   我告诉某 agent"现在没有 xsim 在跑"，它开工时另一路已经起来了 ⇒ 它准确报备"并发实况与假设不符，
   且我的 TaskStop 时刻与其结束重合，**无法完全排除我终止了它的后续步骤**"。
   ⇒ 并发窗口是**易变事实**，要么让 agent 自己现查，要么把"先确认无并发"写进它的第一条任务。

**Why:** 这两条都让一次本该干净的验证失去了"可独立复算"的属性 —— 与工程里那条
"证据必须新于源码"是同一族：**证据与被验对象的绑定关系，和证据本身一样重要**。

## 派文档任务的第三条纪律（2026-09-29 P7b 实战，我踩了）

**"订正已有陈述" 与 "新增章节 / 里程碑" 是两件必须分别指派的事。**

我让一个 agent 做"文档订正"，指令里写了"**只改已被证伪的事实陈述，不要新开一节**" ⇒
"**新增 P7b 里程碑**"这件事**没有任何 agent 拥有** ⇒ 整轮漏掉，直到**用户指出"README 没更新"**。

**How to apply:** 派文档任务时把两类分开点名：
① **订正**（改的是**已存在且被证伪**的句子）；② **新增**（README 状态块 / 里程碑表行 /
PORT_NOTES 的里程碑节 / 归档索引）。**"这一轮做了什么"必须有一个明确的 owner** ——
它不会因为"别人把旧句子改对了"而自动出现。

同轮另一个同族问题：**"笔记里有数字" ≠ "主文档被更新"**。P7b 的 8 份笔记写得很全，
而 README / PORT_NOTES 一个字都没动 —— **笔记是证据，主文档是入口**，两者不互相替代。

**Why:** 与前两条同族 —— 都是"**没有人负责的那一格**"：并发那两条是"没人负责的文件"，
这条是"没人负责的章节"。派单时**逐个格点名**，比"把这块做一下"可靠。
