## 2. 审查口径（Tier A 全六条；Tier B 按 §1 豁免只核 ②④⑤）

1. **零黑话**：对绰号清单（在飞 / 刀作轮次名 / 闸 N / 门全绿 / 有牙 / 哑门 / 空判据 / 飞了等）grep = 0
   （glossary.md 以翻译条目形式除外）；技术词（AXIS/XDMA/WNS/URAM 等）首次出现处带一句平白解释。
2. **事实与事实源一致**：关键事实标注（源：文件§节）；「未测」不写成「已测」；不代行 PASS/FAIL 裁定。
3. **结构与索引一致**：README 树状图与真实目录一致；新增/移动文档后索引页同步。
4. **链接可达**：相对链接 0 死链（检查器：提取 `](...)` → 相对解析 → 目标存在；行内代码段排除）。
5. **与最新进度不矛盾**：进度/指标读数与台账、里程碑件、桥内增量一致；冲突时并列登记不擅自裁决。
6. **收口定义**：Tier A/B 变更**未经 Kimi 组复核不视为收口**；复核结论三态：
   **通过** / **需修**（附 文件:行 + 依据）/ **协调**（双方口径冲突，升 owner 裁）。

## 3. 通知格式（变更方 → kimi-tl）

- bridge 消息：`kind=chat`（有问题用 `correction`），`to=kimi-tl`，**必填 `ref`** = 提交号 或 `文件:行`；
- body 四段：① 变更摘要（改了什么/为什么）② 影响面（动了清单里哪些件）③ 自测结果
  （黑话 grep / 链接检查原始数字）④ 一句明确结论（自判是否需要复核重点看某处）。
- 复核时延：Kimi 组轮询 ≤5 分钟回执；紧急标 `ack_required=true`。
- 收到我方「需修」回执后：变更方修复并复报，复核通过才算收口。
