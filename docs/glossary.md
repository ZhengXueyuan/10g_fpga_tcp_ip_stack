## 一、技术词

| 词 | 平白解释 |
|---|---|
| **FPGA** | 现场可编程门阵列：一种可以通过"烧录"改变内部电路的芯片。本项目用它实现整个 TCP/IP 协议栈。 |
| **XCKU5P** | 本板用的芯片型号（Kintex UltraScale+ 系列，`xcku5p-ffvb676-1-e`）；板上还有两个 SFP+ 万兆光口、一个千兆电口、PCIe 插槽。 |
| **RTL** | 寄存器传输级代码：用 Verilog 写的硬件描述，综合后变成 FPGA 里的真实电路。 |
| **HLS** | 高层综合：用 C/C++ 写算法，工具自动转成硬件。本项目的慢路径协议栈（ARP/ICMP/握手等）就是这样做的。 |
| **AXIS / AXI4-Stream** | ARM 定义的一种"数据流"接口标准：一拍拍地传数据，带 valid/ready 握手。本仓数据面统一为 64 位 AXIS 字流。 |
| **AXI-MM / AXI4 Memory-Mapped** | 带地址的读写总线（像访问内存一样访问外设）。 |
| **AXI-Lite** | AXI-MM 的简化版，用于配置寄存器。 |
| **XDMA** | AMD 的 PCIe DMA IP：负责板子与 PC 内存之间的高速搬运，也提供 user BAR 寄存器窗口。 |
| **BAR** | PCIe 的"基地址寄存器"：把板上一块地址空间映射到 PC，程序像读写内存一样访问板内寄存器。 |
| **BRAM** | 片内块状 RAM（FPGA 自带的大容量快速存储）。本设计用掉 348/480 = 72.5%。 |
| **URAM** | 比 BRAM 更大但更"死板"的片内 RAM（本芯片共 64 个，目前用 1 个 = PCIe 镜像板内缓冲的 32 KB 缓存，自构建 0x24 起；其余 63 个仍空）。 |
| **LUT / FF** | 查找表（组合逻辑）/ 触发器（寄存器）：衡量设计占用芯片面积的两个基本单位。 |
| **WNS / WHS** | 最差建立时间余量 / 最差保持时间余量（单位 ns）：数字电路时序收敛的指标，**正数越大越好**；余量为负 = 电路可能跑错。 |
| **CDC** | 跨时钟域：信号从一个时钟域传到另一个时钟域，处理不当会导致数据损坏。 |
| **RGMII** | 千兆以太网的电口接口标准（4 位数据 × 双沿 × 125 MHz）。 |
| **GMII** | 千兆以太网接口标准（8 位数据 × 125 MHz），RGMII 的内部等价形态。 |
| **10GBASE-R** | 万兆以太网的物理层编码标准（64b/66b 线路码，10.3125 Gbit/s）。 |
| **PCS / PMA** | 物理编码子层 / 物理介质接入子层：PHY 芯片里负责编码、成帧、并串转换的部分。本项目用 AMD 官方 IP 实现。 |
| **XGMII** | 万兆以太网的 64 位并行接口（每拍 8 字节）：PCS 与 MAC 之间的分界线。 |
| **GT / GTY** | FPGA 里的高速串行收发器硬核（SerDes），10G 光口靠它。 |
| **gearbox** | 速率变换 gearbox：64 位内部数据与 66 位线路码之间的宽度适配器。 |
| **BER** | 误码率：传错的比特占总比特的比例。 |
| **PRBS** | 伪随机二进制序列：自检常用的"看起来像随机数"的测试码流。 |
| **FCS / CRC** | 帧校验序列（循环冗余校验）：以太网帧尾的 4 字节校验和。 |
| **FIFO** | 先进先出队列：硬件里跨模块/跨时钟域缓冲数据的标准结构；FWFT = 首字直通（队首数据恒可见）。 |
| **II = 1** | 硬件流水线术语：每 1 个时钟周期吐出 1 个结果（Initiation Interval = 1）。本仓数据面每一级都做到 II=1。 |
| **TOE** | TCP 卸载引擎：把 TCP 协议处理从 CPU 卸载到专用硬件（本项目的终局形态）。 |
| **TCB** | 传输控制块：每条 TCP 连接的控制状态（序列号、窗口、重传状态等）。 |
| **CAM** | 内容寻址存储器：查"四元组（源/目的 IP+端口）→ 连接 ID"的硬件查表结构。 |
| **MSS** | TCP 最大段长度（本项目 = 1460 字节，以太网 1500 MTU 减去 IP/TCP 头）。 |
| **RTO** | 重传超时：发了数据很久没收到确认就重发的定时器。 |
| **dup-ACK** | 重复确认：TCP 收到乱序/丢失段时发的重复 ACK，连续 3 个触发快速重传。 |
| **BDP** | 带宽时延积：带宽 × 往返时延 = 线路上"在飞"的字节数；窗口小于它就跑不满带宽。 |
| **persist（零窗探询）** | TCP 对端把接收窗口通告成 0 时，发送方定期发 1 字节探询帧问"窗口开了吗"的机制。 |
| **wu** | window update：板子主动发 ACK 告知对端"我的接收窗口重开了"（`rtl/app_ctrl.v` 里的机制名）。 |
| **wscale** | TCP 窗口缩放选项：把 16 位窗口字段扩大 2^n 倍；**本项目刻意不回这个选项**（= 窗口硬顶 65,535）。 |
| **pcap** | 抓包文件格式（tcpdump/tshark 的产物），本仓大量板级判据以 pcap 复算为准。 |
| **ILA / VIO** | Vivado 的片上逻辑分析仪 / 虚拟 IO（调试核），上板抓波形用。 |
| **QSPI** | 板载非易失配置存储器（掉电不丢）；本仓铁律 = 绝不写 QSPI，只走 JTAG 易失烧录。 |
| **JTAG** | 调试/烧录接口：把位流临时烧进 FPGA（断电即失）。 |
| **SLVERR** | AXI 总线的"从机错误"响应；读未实现地址会收到它（读出 `0xffffffff`）。 |
| **MMIO / 寄存器窗口** | 用读写地址的方式访问硬件内部状态（本项目 76 个 32 位快照字就是这么读出来的）。 |
| **Xilinx/AMD 原语** | 芯片厂商提供的底层硬件单元（RAMB36E2、CARRY8 等）。 |

## 二、项目绰号（黑话 → 平白话）

> 以下每条**左侧加粗的黑话词**在全仓其余文档里大量使用；本文件是 docs/ 层唯一引述它们的地方。

| 黑话 | 平白翻译 | 出处 |
|---|---|---|
| **门** | 一条"仿真自检"：一段测试脚本，跑一次给出通过/失败判决（如"全链门 106 条判据 0 失败"）。 | 根 README.md「怎么跑 · 门矩阵」节 |
| **闸（闸 0～闸 4）** | P7b 施工规格里的**阶段关卡**：每个关卡是一次有正式判据表的板级验收（选型 / 自环 / 真网卡裁决 / 全链检查 / 整体验收）。 | `agent_docs/P7B_SPEC.md` §0/§5；`P7B_GATE4_ACCEPT3.md` |
| **闸 4 收口** | 整体验收的最后一轮（第三轮）——把判据表定稿。 | `_proj_10g/notes/P7B_GATE4_ACCEPT3.md` §0 |
| **刀（xx 刀）** | 一批**捆绑在一起的改动**（一个"刀次"），通常 = 一次修复 + 一次构建 + 一次板级验证（如"缺陷刀 0x1C"）。 | 台账 §9（"本刀"全节使用） |
| **在飞** | 任务**已派出、还没回来**（agent 已领活、结果未回）。 | 台账 §2/§10（"在飞的两支"/"在飞清单"） |
| **有牙 / 无牙** | 判据**真能判红** = 有牙：把缺陷代码换回去它必须失败（"反例双跑有牙"）；**结构性必然通过**（怎么跑都是绿）= 无牙。 | 根 README.md「已完成」表（"反例双跑有牙"）；`P7B_BIZ_WINDOW.md` §5 |
| **哑门** | 形同虚设的检查：脚本**不置失败退出码**，无论结果如何都报成功（"PASS(哑门)"= 人工读了它的判据行才算数）。全仓曾查出 8 条，其中 1 条掩盖了真失败。 | `_proj_10g/notes/P7B_REGRESSION.md` §5 |
| **空判据** | **结构性必然通过的判据**：比如"在没有流量的窗口里要求失配计数 = 0"——它不可能失败，因此不构成证据。 | `_proj_10g/notes/P7B_OPEN_ITEMS.md` §0 第 2 行；台账 §6 纪律 |
| **门全绿** | 矩阵里**所有检查都通过**；注意本仓的教训是"全绿可能只是矩阵没看你"（清单里没收录被改文件）。 | `agent_docs/PORT_NOTES.md` 各节标题；`P7B_STAGEA_MILESTONE.md` §1.3 教训 1 |
| **飞了** | 含义待考：本仓权威件中未检索到该词的定义或用法（仅作为"可能见过的黑话"列此备查）。 | 全仓 grep 0 命中 |
| **收口** | 把一个轮次/一条缺陷线**正式关账**：修复 + 构建 + 板级证据 + 文档订正全部落库。 | 台账 §7/§10 各节 |
| **负对照臂** | 对照实验的"反例组"：故意用**修复前**的代码/位流重跑，必须得到失败——证明实验有判别力。 | 根 README.md「已完成」表（"反例双跑"） |
| **判据** | 验收标准：一条可判定真假的检查项（"期望来源"列注明它为什么算数）。 | `agent_docs/P7B_SPEC.md` §6；`P7B_GATE4_ACCEPT3.md` §2 |
| **FROZEN / 冻结校验** | 回归矩阵收尾时校验"被测源码与基线逐字节一致"——防止"测的代码和声称的不是同一份"。 | 根 README.md「怎么跑 · 门矩阵」节 |
| **台架 / 对端机** | 测试环境：一台跑 Linux 的真 PC（10G 网卡 + 自写收发工具），扮演通信对端；"台架帽" = 工具/网卡自身造成的速率天花板（曾被三层证伪逐层排除）。 | 根 README.md「P7b-长流刀」段（"台架帽逐层证伪"） |
| **板上 / 板级** | 在真实 FPGA 板子上（而非仿真里）测出来的；"板级 PASS" = 真板验收通过。 | 全文通用 |
| **BID** | BUILD_ID：烧进位流的版本号（十六进制，如 0x23）；位流文件大小恒定 ⇒ 只能靠 BID + sha256 分版。 | `_proj_10g/notes/P7B_A7_HANDOFF.md` §2 |
| **W0…W75** | 观测快照的"字"（每个 32 位寄存器）：W51 = 下行载荷字节、W55 = 重传次数、W70 = 镜像丢弃字节、W71..W74 = 换流四观测计数器、W75 = 孤儿回收计数……现役共 76 字。 | `_proj_10g/notes/P7B_BIZ_WINDOW.md` §1 |
| **恒等式（口径）** | 两个量**按定义必然相等**（如 `P ≡ 156.25e6/fps`）：它成立不构成"独立互证"，引用时别把换算式当测量值。 | 台账 §6 纪律；根 README.md 2026-10-10 订正 |
| **相位（phase）** | 字节对齐位置：帧长对 8 取余的余数（0 = 每帧正好整数个字）。P8 镜像修复前"相位 ≠ 0 且密集"会恒丢 50% 数据。 | 台账 §10-20-2（审查 ⑤-1） |
| **幽灵（ghost）** | "重放越界"缺陷线上表现的俗称：流里混入"上一圈"的旧字节（seq 超前于实际已写数据）。 | 台账 §9-1（`e_ghost` 判据） |
| **墙是窗 / BDP 墙** | 速率瓶颈归因结论：读数上不去的第一层原因是 **TCP 接收窗口（BDP）** 而不是链路或数据面。 | 根 README.md「现在是什么状态」② |
| **产品级缺陷 / 已定案** | 影响真实使用的缺陷 + 已完成判决性归因（"不是我们的 RTL"这类 A/B 定案）。 | 根 README.md「P7b-BIZ Stage 2」行 |
| **收口轮 / 里程碑文档轮** | 一个轮次结束后专门改文档、把结论落进现役文件的轮次（本仓惯例：施工轮与文档轮分开）。 | `_proj_10g/notes/P7B_STAGEA_MILESTONE.md` 抬头 |
| **代差 / 几何** | 观测窗口的"代"：每扩一次窗口（加字）算一代（61 字 → 63 → 70 → 71 → 75 → 76），工具默认值必须跟着换。 | `_proj_10g/notes/P7B_BIZ_WINDOW.md` |
| **扫尾账 / OPEN_ITEMS** | 未解决项汇总表（`_proj_10g/notes/P7B_OPEN_ITEMS.md` §0），每条四格：现状 / 依据 / 为什么没解决 / 下一步。 | 同文件 |
