### 3.2 H3 判决读数

- **设计件证伪器 ①**（"对端窗 ≥8 MSS 仍爬（`W55 ≥20/s` **且** `held ≥20%`）⇒ H3 被否"）：**未发生**。B3e 的 ACK 窗 **95.2% ≥8 MSS**，而 **held = 0.2%**、速率 **4.13 Gbps** ⇒ **H3 未被证伪**。
- **设计件证伪器 ②**（`start_data ∧ retx_active` 计数）：需构建仪器 I1，本轮**未测**。
- **免疫阈值（速率口径）**：**rcvbuf 5840 → 8760 之间**（有效窗主导 2 MSS 不变，但**零窗占比 18.1% → 0.1%**）。
  - ⚠️ **设计件的"ΔW55 首次跌到 0"严格口径【未观测到】**：B3c/d/e 仍有 337–1921/s 的重放会话。**但**这些会话的"首发→覆盖"延迟 = **0.03 ms**（B3a/b 的 RTO 环 = 20.06 ms）⇒ 它们是**快重放**，不是自持 RTO 环。⇒ **建议把"免疫"判据从 `ΔW55=0` 改为 `held 延迟 ≈20 ms`（或 `held ≥20%`）**。
- **新量化（机制旁证）**：`W20 − W52 = k × W55`，**k = 1.0（1 MSS）/ 2.0（2 MSS）/ 2.8–3.1（≥3 MSS）** ⇒ 一次回卷重放的帧数随有效窗增长（1→2→3 帧/会话），与"重放整段 `[snd_una, snd_nxt]`"的机制一致【已证（环口径）】。
- **新分离量（未预注册，登记）**：B3b 与 B3c 的**主导窗相同（2 MSS）**，但速率差 **47×**（34.8 vs 1637 Mbps）；两者最锐的差别是**零窗 ACK 占比 18.1% vs 0.1%**。"最小有效窗是否触 0"比"主导窗大小"更像慢/快的真正分水岭 ⇒ 下一轮建议**以零窗占比为轴**再做一格（例如 rcvbuf 7000/8000 夹逼）。

### 3.3 决策树（设计件 §5.2）落格

```
B3 结果：对端有效窗 1 MSS ⇒ 爬（W55≈50/s、held 59.8%、20.06 ms）；2 MSS ⇒ 过渡（7–62 Mbps）；
         ≥2–3 MSS（rcvbuf≥8760，零窗≈0.1%）⇒ 快（1.6–4.1 Gbps、held ≤2.7%、0.03 ms）
 └─ ⇒ 命中"对端窗 ≥2–3 MSS 时免疫、≤1 MSS 时爬"分支 ⇒ H3（回卷双段环）成立【零构建层】
```
⇒ 下一轮修法方向（设计件 §5.2 ①②③）保持有效；一次构建只做 **I1+I2** 当"修法有牙"的见证。

### 3.4 ⚠️ 读数纪律

- `W55` **不是**单义的"爬行"指标：它把 RTO 会话与快速重放会话混在一个全局计数里（慢盆 50/s 与快档 1672–1921/s 都计入）。**判爬行必须配 held 延迟**（20 ms vs 0.03 ms）。
- 首发段数在**大窗快臂**里可达 8（B5/B3c-e）⇒ 该指标只在 **1-MSS 窗**下有判别力（设计件的 anchor 是 1-MSS 构型）；不要把它当"免疫"的判据。

## §7 对设计件的订正（新读数，必须回灌）

1. **`W63/W64` 真值（盆内）**：设计件 §1.2 表写 8.4–19.8% / 0.003–11.5%，并以此为 H6 的前提。**环读数 = 0.9999 / 3.3e-5**（B2/B3a/B4 逐字一致）。⇒ **H6 的前提不成立**；盆内 app 几乎 100% 在 `frm_wait`。快态对照 = W63 22–26% / W64 64–71%。
2. **H4 判别器不足**：设计件 §4.2/§4.3 用"冻结前最后 ACK 的 win"分 H4a/H4b。本轮 18/18 的最后 ACK=1460，**但**最后数据之后仍收到 **1–2 条 win=0 窗更新**（18/18）⇒ H4a 的"扫描采到 0 相"材料存在。**H4a/H4b 都没有被排除**；要分离必须上 I3（`stat_rto_disarm_wnd0`）。
3. **免疫阈值口径**：`ΔW55=0` 在 ≥3 MSS **未观测到**（B3c-e 有 337–1921/s 快重放）；**held 延迟 20.06 ms vs 0.03 ms** 才是 RTO 环的干净签名。建议下一轮判据改为 **held 延迟 ≈20 ms**（或 held% ≥20%）。
4. **冻结带**：设计件的"8–15 ms（10/10）"在本轮 = **0.13–14.98 ms（18/18）**；<20 ms 的关键性质成立，但不应对"8–15"这个带做机理引用。
5. **H3 的 `k` 值**（新）：重放帧数/会话 = 1（1 MSS）/ 2（2 MSS）/ ~3（≥3 MSS）——`W20−W52` 与 `W55` 的比值给出，可直接用于 I2 的判据设计。
6. **零窗占比**（新，未预注册）：1 MSS 38–40% → 2 MSS（5840）18.1% → 2 MSS（8760）0.1% → 快。它是 B3b/B3c 同主导窗却差 47× 的唯一明显分离量 ⇒ **建议作为下一轮的"物理量轴"**。

## §8 偏离登记（按发生顺序）

## §9 未决 / 未测（不许当已答）

1. **H1 的池值**（`pool/winq/redge/stat_pool_exhaust`）零构建**读不到** ⇒ H1 作为 TX 爬行原因**未判定**；需 I6 或 AXI-Lite 桥。

4. **`W55` 的触发分解**（RTO vs dup-ACK 快重放）无逐触发计数；`k` 值只能间接推断重放粒度。
5. **大窗进入【未观测到】**（B5）——不是"已证不可能"；若进入后 <1 s 自清，B5P（6 连 ≈3 s）会漏检。**自清**仍【未测】：本轮最长连续在场窗 ≈ **10:03–10:22 = 19 min**（B1 进入 → 第一次烧录，期间 B1/B2/B3/B4 连续无烧录），**未观测到自清**（与 G 轮的 ≥14 min 一致）。
6. **零窗占比作为轴**是**未预注册**的新发现；需专门夹逼（如 rcvbuf 7000/7500/8000）确认因果方向（是零窗导致慢，还是慢导致零窗）。
7. **读/身份门是否影响盆**（设计件 §6-2 B7）**未测**——本轮所有臂都带身份门与 3 Hz 级快照读取。
8. **B2 的 burst = 29.3%** 略低于 30% 线（同盆其它连接 35–56%）；burst 单量不作为 H3 判据（held/速率/W55 已分离），但如实登记。
9. **`W57/W58`**（retx_hi / retx_active）在 3 Hz 环下不可判（会话 ~20 ms–ms 级）；只有事件锁存（I 类）才有用。
10. **B3b 的 2-MSS 过渡态**只有 2 条连接样本；"7 vs 62 Mbps"的双峰机理未定位（可能 = 零窗占比的时间变化）。
11. **对端窗直方图的采样面**：pcap snaplen=128 只保头 128 B，`win` 字段完整；但环（CAP）溢出未发生（全臂 `dropped=0`）。
12. **`B3a` 的 SYN win=4380 而 ACK 窗恒 {0,1460}**：即"rcvbuf 4380 仍只通告 1 MSS"——与设计件 §1 的订正①一致（物理量 = 有效窗，不是 rcvbuf），但 **4380 档为何 0% 2-MSS** 未定位（truesize【推断】）。
