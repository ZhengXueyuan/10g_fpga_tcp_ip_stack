## 1. 方法与构型

- 两个 netns：`nsa` = `enp1s0f1np1` `192.168.100.1/32` ↔ 板 `192.168.100.2`；

- sink：`/tmp/p7b_biz/p7b_tcp_sink`（md5 `f62299291fcb9e02afe109c4ea1f90ab`，173,576 B），

  `maxbytes=24000000000`（24 GB）、`taskset -c 0,1`、`--no-pin`（见证 `UNPINNED=1`）。
- 网卡：两口 `Speed 10000Mb/s / Full / Link detected: yes`；`Adaptive RX: off / rx-usecs 0 /

### 1.1 指标定义（与 P7b A7 同口径）

| 量 | 定义 | 说明 |
|---|---|---|
| `ΔW65/ΔW43` | TX 空闲占空 | `W65=mac_tx_idle`；**`W43` 是 tx 域拍钟**（每拍无条件 +1，**不是 tx 字数**，P7b A7 全局经验 #77） |
| `ΔW66/ΔW65` | 空闲里“只差 `wnd_open`”的比例 | `W66=tx_stat_winstall` |
| `ΔW67/ΔW66` | 等窗拍里“板帽侧”的比例 | `W67=tx_winstall_cap`，判据 `win_wnd_eff >= RING_CAP`（同一注册样本） |
| `ΔW66/ΔW43` | 等窗占 tx 拍钟比例 | 等窗绝对量 |
| `(ΔW66−ΔW67)/ΔW43` | **非板帽侧**等窗占比（含扫描伪拍） | **不能读作对端通告窗**；W67 只在 episode 内可靠，伪拍修正见 §3.2 |
| `W43/W20` | 等效帧周期（拍/帧） | `W20=mac_tx_frames`；几何值 193 |
| `ΔW68/ΔW20` | 每帧推进 ACK 数 | `W68=rx_stat_ack_adv`；`tcp_rx.v:160-164` 有自登记双计边角 ⇒ 带未量化正向偏差 |
| `W27/W28` | CDC 占用历史最大（字） | **sticky since reset**；深度 256；本轮只看“是否刷新” |
| `W69` | 等窗拍操作点锁存 | **不可用**：单点锁存 + 扫描伪拍污染；只登记原始值（§3.2） |

时间基：**`ΔW43 / 156.25 MHz`**，差值全部 mod 2³²；`ΔW5/ΔW43` 只作跨域交叉核
（本轮 1.0000094，即 FE 与 tx 同标称、9.4 ppm 差）。

⚠️ **计数器污染（审查 H-1/H-2）**：`W66/W67/W69` 经“扫描拍陈旧 win 样本”进入伪拍 ——
win 口跟随 `win_id` 晚 1 拍（`tcb.v:151-157`），扫描每 16 拍插 1 拍（`tcp_tx_frame.v:579,619-620`），
扫描后下一拍的 win 口仍是被扫空槽 `{0,0}` ⇒ 若恰有帧待发，该拍计 W66、W67 归非板帽侧、W69 锁 `{0,0}`。
⇒ **W69=0 不等于“对端零窗”**；非板帽侧列含伪拍，不能直接当对端窗。详见 §3.2。

## 3. 结论

### 3.1 【已证·板级·raw】

1. **单口 9G 级下行的两个可复现态**：
   - **快态**（E05 / E05D / E05M）：9.4405 / 9.4437 / 9.4453 Gbps（±0.2% 墙钟；= 线上载荷天花板 **9.49285** Gbps 的 **99.45–99.50%**；三值互差全在误差棒内），
     TX 空闲 **0.143 / 0.142%**（E05/E05D）与 **0.080–0.135%**（E05M 四窗口），等窗只占拍钟
     **0.101%**（E05/E05D，10.9/10.6 ms per ~10.7 s）与 **0.044–0.094%**（E05M 四窗口）；
     E05/E05D 板帽侧占等窗 61.7–61.8%、E05M 19.4–59.4%——快态内该占比可变，但绝对等窗量仍 ≤0.10% 拍钟。
   - **慢态**（E05B / E05C）：9.2560 / 9.0701 Gbps，TX 空闲 **2.035 / 4.978%**，
     等窗占拍钟 **1.830 / 4.589%**，板帽侧占等窗 **92.0 / 93.1%**。
   - 同一 bitstream、同一 sink 参数、同一网卡配置；**慢态（E05L）与快态（E05M）都各在单连接内连续 4 个 10 s 窗口稳定（≥40 s）**；
     6 个连接 = **3 快 3 慢**（2+2 个 24 GB 短跑，1+1 个 60 GB 长跑），**未观察到连接内翻转**。
2. **快态下窗口/BDP 不是吞吐墙**：等窗只有 0.101% 拍钟（其中约 1/3 是扫描伪拍，H-1；
   真窗口等待更小）；`ΔW65/ΔW43=0.143%`，即 TX 线 99.86% 时间在忙。P7b A7 在 5.7–9.3 Gbps
   看到的 `ΔW66/ΔW65=0.88–0.90` 只在**慢态**重现（本轮 0.90–0.92）。
   ⚠️ W65 只数 MAC FSM `S_IDLE` 且 FIFO 空（`mac_tx_10g.v:53-66,350`）；`S_IFG/S_FLUSH` 发 `/I/`
   不算空闲 ⇒ **99.86% 忙与 99.45% 线上载荷的差 = 这个口径缝**，不是额外死拍（L-2）。
3. **慢态下窗口门是空闲的第一来源**：89.95–92.19% 的空闲拍是“只差 `wnd_open`”，
   其中 92.0–93.1% 归属**板自己的 `WIN_CAP`**（W67 判据 `win_wnd_eff >= RING_CAP`），
   不是对端通告窗。⚠️ 剩余 7–8% 的“非板帽侧”主要是扫描伪拍（H-1）：按慢态
   `ΔW66/16` 估算，真实对端窗等待 ≤3.1–3.2 ms；“W69=0”**不能**读作对端零窗（§3.2）。
4. **板内 CDC 队列没有堆起来**：`W28` 历史最大 36/256 字（14.1%），`W27` 6/256；
   全部 12 个窗口（4 个 24 GB + 8 个长跑窗口）均未刷新峰值。⇒ 本构型下没有“TX CDC 被填满”的证据。
5. **整窗排空的最坏值**（不是 p99，也不是附加等待的下界）：`WIN_CAP = 61,440 B` =
   **42.08 帧 × 1460 B**；在实测 9.44 Gbps 下排空需 **52.07 µs**（慢态 53.1–54.2 µs）。
   ⇒ 随机到达的新消息若排在已满窗口之后，**附加等待 ∈ [0, 52] µs、均值约 26 µs**；
   52 µs 是“恰好整窗排空”的最坏值。前提 = ACK 回路以线速返回且窗口立即重开；
   还未计 app 队列与本机/对端调度。
6. `W68/ΔW20`（推进 ACK/帧）：快态 0.2119–0.2274（E05M 长跑 0.2128–0.2134），
   慢态 0.1322–0.1684（E05L 长跑 0.1667–0.1680）；慢态的 ACK 更稀。**相关，不是因果**（见 §3.2）。
   ⚠️ 该比值有 `tcp_rx.v:160-164` 自登记的“ACK drain 与 w5→fend 撞 snd_una 多计一次”边角
   ⇒ 带**未量化正向偏差**（发生率未量）；只作形态量，不作精确分母（L-1）。

### 3.2 【未定位】

- **快/慢态翻转的机理**：6 个连接 = 3 快 3 慢（2/2 个 24 GB 短跑 + 1/1 个 60 GB 长跑）。
  按审查 M-4 更新假设清单：
  ① **“sink 供给变慢 → 缩窗”降为排除**：慢态 `W67` episode 内 `eff=61,440` ⇒ 对端
     `snd_wnd ≥ 61,440` ⇒ 1 MB rcvbuf 从未压穿（W67 episode 内可靠；非板帽残差主要是伪拍）。
  ② **RSS 队列/核亲和**：NIC 12 个 RX 队列（审查 M-4），6 个连接散列其中；快慢态与队列分配
     同构是候选；本轮**未登记**每连接 RSS 队列/软中断，不能判定。
  ③ **ACK 路径动力学（delayed-ACK/NAPI）**：唯一与全部板侧证据相容的候选家族；
     **缺对端 pcap ⇒ 不能判定**。
  ④ “CPU 调度/对端负载”无 loadavg/softirq 取证 ⇒ **降为未证**。
  ⑤ 热/频已排除（最慢 E05C 反而最高频）。
  注意：两口中断合并已关（`Adaptive RX: off, rx-usecs 0`），所以**不是** P7b #68 的“中断合并帽”。
- **`W69` 不可用 + 扫描伪拍（H-1/H-2）**：W69 是“最近一次等窗拍”的单点锁存，且被扫描拍
  陈旧 win 样本污染 —— win 口跟随 `win_id` 晚 1 拍（`tcb.v:151-157`），扫描每 16 拍插 1 拍
  （`tcp_tx_frame.v:579,619-620`；`rb_id` 扫描 mux 在 `:706-708`），扫描后下一拍 win 口仍是
  被扫空槽 `{snd_wnd=0, snd_nxt=snd_una=0}` ⇒ 若恰有帧待发，该拍计入 W66、W67 归“非板帽侧”、
  W69 锁 `{0,0}`。⇒ **W69=0 不能读作“对端零窗瞬间”**；`0xf53cf000` 也不能单独读作“板帽 episode”。
  其中 `0xf53cf000` = {inflight 62,780, eff 61,440}，与 cap-blocked episode 相容（42×1460=61,320
  < 61,440；43×1460=62,780 ≥ 61,440；低 16 位上限 62,939，无回绕），但单点锁存不能证明每个事件都如此。
  本轮 W69 原始值：**E05C_MID1 与 E05L_L1/L3/L4 = `0xf53cf000`，其余 MID/L 快照 = 0**；
  **只登记、不作判据**。伪拍率约 1/16（审查 RTL 估算）：快态 E05/E05D 伪拍 ≈ **545K/529K 拍**
  （≈W66 的 **32%**；≈`ΔW20/16`），慢态伪拍 ≈ `ΔW66/16`（**6.25%**）⇒ E1 的态分类阈值必须带
  这个地板（L-4）。⚠️ 本件未做逐拍仿真复现，伪拍量化采用审查估算。
- **慢态的因果方向**：sink 侧 `slot_wait_spins` 快态 13.8k/41.1k、慢态 9.9k(E05B)/8.39M(E05C)，
  与“生产端（recv）供给变慢”一致，但生产端变慢既可能是板发得慢的结果，也可能是对端读得慢
  的原因 ⇒ **未分离**。⚠️ 这不等于“对端缩窗”：W67 episode 内 `eff=61,440` 已把缩窗链排除
  （M-4）；剩余候选是接收/ACK 动力学，需对端 pcap 才能判。
- **不是热降频/频率单调**：sink 结束 `CPU_FREQ_KHZ` = 快态 E05 3,797,776 / E05D 3,700,244，
  慢态 E05B 3,797,732 / E05C 3,800,242；**最慢的 E05C 反而是四跑最高频**，E05D 快态反而 3.70 GHz
  ⇒ 频率/热与快慢态**不相关**（不能据此解释）。

### 3.3 【未测】

- **p99 / 尾延迟**：E0.5 只有占空/计数器，**没有**注入小消息或 ping/SYN 的往返时延；
  不能把 52 µs 的整窗排空最坏值当作实测 p99。
- 双口同时 9G 下的 E0.5 计数器（D9R 只给了吞吐，没有取 W65–W69）。⚠️ **口 B 结构性没有
  W66–W69**：`wrapper_p4.v:3353` 的 `stat_winstall/stat_winstall_cap/o_win_at_winstall` 全空接
  ⇒ 双口构型天生没有窗归因仪器；要做双口 E0.5 需先接线（M-6）。
- 8×12KB 合同（多连接 app）下的窗口分配；本轮是现役单连接路径。
- **E1 态分类阈值**：必须 ≥ **1/16 扫描伪拍地板**，否则快态的伪拍会被读成“等对端窗”（L-4）。
- **6 连接协变量未登记**：每连接 RSS 队列/peer loadavg/softirq 均未记录；每态仅 1 条 60 GB 连接（L-6）。
- **sink 构建产物**：已补 `artifacts/p7b_tcp_sink` + `.cpp` 与 `SINK_BUILD.txt`（md5 对齐
  `f6229929…` / `dd3adfbe…`）；**未重跑构建**，二进制来源仍是“对端产物 + 源快照”（L-5）。

## 4. 对“缩小时延”研究的意义

1. **不要再把“数据面产字率不足”当作第一瓶颈**：快态 TX 线 99.86% 忙，等窗仅 0.10% 拍钟
   （含约 1/3 伪拍，真窗口更小）；
   满载时限制在“线已被占满 + 窗口排队”，不是发生器产字率。⚠️ 这不等于“流水线级延迟已无余量”
   —— 每级流水对单条消息的固定延迟仍要靠 E1 的逐级戳/p99 判定，本件没有测。
   ⚠️ 本件**没有** W51/W52 app 产字计数器的直接量；快态剩余 ~0.04% 拍钟的“非窗口空闲”可能
   是簇状停顿，**未表征**（L-3）。
2. **窗口/BDP 仍是延迟项，但要分态说**：
   - 快态：它对**吞吐**几乎无影响（0.10% 拍钟），但 61,440 B 的在飞上限使随机到达的
     新消息附加等待为 **[0, 52] µs、均值 ~26 µs**（52 µs = 整窗排空最坏值，不是下界）；
   - 慢态：它是**空闲的第一来源**（90–92%），且 92–93% 是板帽侧 ⇒ 若产品运行点落在慢态，
     抬窗/改窗口管理才有明显收益。
3. **E1 必须先能分辨快/慢态**：6 个连接 = 3 快 3 慢；**E05L/E05M 证明两种态都能占满整条 60 GB 连接（各 ≥40 s）** ⇒ 若 E1 只跑一条连接，可能整段落在同一态并把该态误读成“板内流水延迟”。E1 的判据应同时记录 `ΔW66/ΔW65`、`ΔW67/ΔW66`、`ΔW68/ΔW20`
   与 sink 的 `slot_wait_spins`，并在**不同连接**上重复到至少各态一次（不能只靠同一连接内的长窗翻转）。
   ⚠️ 态分类阈值必须 ≥ **1/16 扫描伪拍地板**（H-1/L-4），否则快态的伪拍会被算成“等对端窗”；
   6 连接的 RSS 队列/peer loadavg/softirq 协变量本轮未登记（L-6）。
4. **E1a 的优先级应由 E1 的 p99 决定，而不是由快态那 29% 的空闲决定**：快态 W66 只解释
   70.9% 的空闲，但剩余部分绝对值仅 ~0.04% 拍钟；且 W69 在 0x32 不可用。要逐拍归因仍需
   E1a 的 4 个计数器（`win_open==0` / `frm_wait` / `txcdc 空拍` 等），本轮**未构建**。
   ⚠️ 若要彻底消除 1/16 扫描伪拍，需在 E1a 设计里单独加“扫描 polluted 拍”标记/计数器；
   这是 E1a 的设计取舍（1 拍/16 空闲拍的结构本身不改，吞吐影响 ~0.03%）。

## 6. 本件不主张什么

- 不主张“9.44 Gbps 是板上限”（只是本轮单口单连接实测；**D9R 双口各 8.94 Gbps 是另一构型**，
  其降速归因见 B 段 host SMT 聚合；**与每口 48 KB 配额无关** —— 48 KB 是 RX 池 `WQ_CAP`
  （`wrapper_p4.v:448-453`），TX 帽每口独立 61,440，M-5）。
- 不主张“窗口/BDP 已不重要”（慢态 3/6 个连接里它是空闲第一来源；52 µs 是**整窗排空最坏值**，
  随机到达附加等待 [0,52] µs）。
- 不主张“W69 或‘非板帽侧’列等于对端窗”（W69 单点锁存 + 扫描伪拍；非板帽列含伪拍，H-1/H-2）。
- 不主张“快/慢态由对端 ACK 造成”（只有 ACK/帧相关，无逐包见证；6 连接协变量未登记）。
- 不主张“E0.5 已给出延迟”（p99 未测；E1/E1a 未做）。
