### 0.1 ⛔ 派单写的"既有收口方向 = 事件脉冲清（小改）"**与一手来源不符**

**(ii) mac_rx_64 同源同拍复位**。"事件脉冲清"这一说法出现在**三处二手件**：

1. `_proj_10g/notes/P7B_OPEN_ITEMS.md:68`（§0 表第 17 行，逐字「**事件脉冲清（小改，需构建）**」）；

   它挂的"坑 14"（仓根 `CLAUDE.md:587-589`）= `app_ctrl` 的跨会话 FIN/RST 标志清理，**与时钟域重启无关**；
3. **`_proj_10g/notes/P7B_TL_LEDGER_20261010.md:302`**（§10-2 缺陷总账 F-3 行，逐字
   「小改（**事件脉冲清**）→ 缺陷批构建」）—— ⚠️ **台账是 compact 后续接点，权威性高于 OPEN_ITEMS**
   ⇒ 只订正 OPEN_ITEMS 是不够的（见 §6-(g) 的**交办 TL 订正清单**）。

**旁证（本轮现读主树）**：`grep -rn "脉冲清" rtl/` 的命中全部是**跨会话状态清理**类

## §1 机制复核（每条标【事实】(带现读 `file:line`) 或【推断】(带证伪路径)）

### 1.1 触发链（代码级）

1. 【事实】DP 域时钟 = `clk_gen_p6b` 的 `clk_dp`（156.25 MHz；`rtl/clk_gen_p6b.v:14,193-217`）。
   `LOCKED` 在"输入钟抖动/瞬断、频率漂移、PWRDWN/RST、温度/电压越界"时瞬时掉低（`:76-77`）。
2. 【事实】`rst_dp` 的置位源含 `locked`：`wire rst_async = (~locked_raw) | rst_ext;`（`:228`）；
   `rel_sr` 4 级 + `rst_dp = ~rel_sr[3]`（`:230-237`）⇒ **失锁立刻异步置位，重锁后再数 4 个 `clk_dp` 释放**。
3. 【事实】`dp_rst_n = ~dp_rst_dp`（`board/wrapper_p4.v:716`）复位的 DP 功能面（本轮现读，
   `grep -c "rst_n *(dp_rst_n)"` = **22** 处；点名）：`u_vlan_strip` `:936` · `u_classify` `:959` ·

### 1.2 ⛔ 关键更正 1：FIFO 不是"内容保留"的冷冻库（**读数已按 §0.0-C4 订正**）

`agent_docs/P6B_CDC_AUDIT.md:40` 的 F-3 行原话是"**FIFO 的指针与内容保留**"。
**指针那句对**（§1.1-4）；**"内容保留"对"钟在跳"的硬件情形是错的**：由 §1.1-6/7，失锁窗口内
DP 侧一直在排空它 ⇒ 释放瞬间 FIFO 队首 = "释放那一刻线上正在收的那一帧的中段字"（FE 一直在写，
§1.1-4 写侧不受影响），**不是**失锁前的存底。

**t9 的仿真模型里**（停 DP 钟 + 断言 `dp_rst_dp`，`tb_f3_restart.v:247-253`）= **停钟子情形**
（钟停 ⇒ 排空也停）⇒ 窗口内 FE 推入的字**被保存**，释放后被交付。**但"保存的是哪一批字"要按日志读**：

- 停钟时刻已推 **`W_snap = 26`** 字（`case_old/xsim_old.log`）；
- 交付的片段 = 源帧3 的内容字节 24..63 = **交付流第 27..31 字**
  （复算：每帧交付 **8 字**（64 B 内容、FCS 已剥）—— 判据 `fe_acc = 96 = 12 × 8` 且 WHOLE 帧 `len = 64`；
  帧 3 占第 24..31 字 ⇒ 字节 24..63 = 第 27..31 字）；
- **27 > 26** ⇒ 这 5 个字是**窗口内（快照之后、恢复之前）推入**的，**不是失锁前的存底**。
  （复核建议的替代表述与本复算一致；v1 那句"失锁前就在 FIFO 里的那 5 个字"**作废**。）

⚠️ 顺带：`stale_words = max(0, dw_all − pushes_after) = max(0, 69 − 70) = 0` 是**钳位到 0**
（原式 = −1）⇒ **它不能当"无陈字"的唯一判据**（v1 `EVIDENCE_INDEX.md` §2 口径 2 已写明，
本件重申）。抓缺陷的是 **J1（`stale_frag`）+ 逐帧内容比对**。

⇒ **两种子情形（钟停 / 钟不停）都会产生"帧中重启"**，且**本修法对两者都成立**（门只看释放后的字流，
不看窗口里发生了什么）—— 这条是修法设计的关键属性，写在 §2.4-I3。

### 1.3 ⛔ 关键更正 2：DP 重启清掉的**不止"帧对齐"**

由 §1.1-3：一次失锁 = **绝大多数 DP 功能面复位**，含 `tcb`（TCP 连接状态）、`tcp_tx_frame` 的
ring/seq 状态、`app_ctrl` 的连接表、慢路径 HLS 实例…。⇒ 后果**远大于"丢/重一帧"**：
对端看到的是一个**静默丢状态的 peer**（连接要靠 RTO 才收敛）。

- 【事实】上述复位面（§1.1-3 现读行号）；**反例**：`u_slow_cfg` 在 DP 重启后**存活**（`:2055/:2057`）。
- 【推断】对端语义 = 在途 TCP 连接失效、需要重建；10G 线上先表现为"零窗口/无 ACK 响应"直到对端 RTO。
  **证伪路径**：在 §3 的全链门里注入一次失锁，观察 `tcb` 的 `state` 与 `app_ctrl` 的连接事件 FIFO
  是否被清（本刀的附带读数）。
- ⛔ **本刀不修这一半**（也修不了）。**建议单列登记**（§6-(e)），别把它塞进 F-3 的收口口径。
- ⚠️ **反例登记（§0.0-C5）**：`u_slow_cfg`（配置适配层）不吃 `dp_rst_n` ⇒ 它跨重启存活。
  **是否 intended 未判**（不在本件范围）。若将来给 `tcb`/`tcp_tx_frame` 加"跨重启存活"的状态，
  必须重新审这条（同族先例：`retx_ram` 的 **mem 不随复位清**而索引/有效位随复位清 ⇒ 旧数据不可达、
  当前无害；若把有效位做成非复位量就会变成与 F-3 同族的"存储保留/状态清零"错配）。

### 1.4 危害的实际形态（含 rx_classify v2 的重新评估，不改）

- 【事实】t9 变体 A 的片段：`len=40`、`crs=1`、`tuser=0`（`case_old/xsim_old.log`）⇒
  一个**没有 SOP、却带 `tcrs=1`** 的短帧 ⇒ "坏帧带 `tcrs=1`"这条完整性属性被打穿。
- 【事实】`rx_classify` **完全不看 `tuser`**（`rtl/rx_classify.v:98-107`；复位后 `widx <= 0` `:111`）。
- 【推断（比审计件更精确）】片段 ethertype 是垃圾 ⇒ 通常 `RT_SLOW`（`:107`），随后靠慢路径解析器兜底丢；
  **但存在小概率"伪 fast 段"**（三个位置恰好命中 `0x0800 / 6 / 非 ctl`）≈ 2⁻¹⁶·2⁻⁸·(7/8) ≈ 1.3×10⁻⁸
  （**量级，未实测**）。**证伪/证实路径**：在 §3 的门里构造该字节图案（一次 xsim 定案）。
- 【事实】危害**有界**：每次失锁只影响"释放瞬间正在收的那一帧"（≤1 帧）+ 下游 FCS/长度/协议三层兜底。

### 1.5 TX 方向（同一个触发，另一侧，不改）

- 【事实】`u_txcdc` 读侧 = `tx_fe_clk`、复位只接 `reset_n`（`board/wrapper_p4.v:2778`）⇒ DP 失锁期间
  **FE 侧照常读**（`:2778` 的 `.rd_en(m_tx_tvalid && m_tx_tready)`、`assign m_tx_tvalid = ~tx_fifo_empty;` `:2786`）；
  `mac_tx_*` 的复位是 `tx_mac_rst_n`/`reset_n`（`:2803`/`:2827`），**不受 `dp_rst_n` 影响**。
- 【事实】残帧安全网 = F-2 的 `S_FLUSH`（`rtl/mac_tx_64.v`；覆盖性论证第 ③ 条逐字在
  `agent_docs/P6B_CDC_AUDIT.md:151-152`："唯一'TLAST 永不到来'的情形 = DP 被复位/弃帧 ⇒ 冲刷会连
  下一帧整帧一起吃掉（代价 = 丢 1 帧，**有界、自愈、有计数**）"）。
- 【推断】⇒ **TX 方向不需要改 RTL**：一次失锁的 TX 后果 = 一个 runt（对端按 FCS 丢）+ 一个被 flush 的整帧，
  两者都有计数（`stat_flush_words/stat_flush_done`、`stat_abort`）。
  **证伪路径（便宜）**：§3 的 TX 臂（J7）判"恰 1 runt + flush 计数 > 0 + **0 幽灵帧**"。
  **未观测到 ≠ 不存在**：本轮**没有**跑过任何 TX 侧失锁实验。

### 1.6 "事件脉冲清 / 清 FIFO"为什么**不**解决问题（实测依据，不改）

| 路线 | 结果 | 出处 |
|---|---|---|
| 只复位读侧（单侧清） | **违反硬契约**：`stale_words=26` | `t9 case_new` |
| 两侧同源同拍复位（FIFO 清空） | **仍然**交付帧中截断片段（`trunc_with_crs=1`），且 FE 侧 8 帧丢弃 | `t9 case_both` |
| 现状（什么都不动） | 交付帧中截断片段（`trunc_with_crs=1`） | `t9 case_old` |

**机理**：清 FIFO 只清"存下来的字"，**清不掉"线上正在发的这一帧"** —— 释放后 FE 立刻把该帧的
**中段字**推回来（§1.1-4：写侧从不参与 DP 复位）。⇒ **只有"以 SOP 为界的重同步"能在入口处判别帧边界**。

### 2.4 不变量（本修法"为什么安全"的全部内容；门要逐条判；**与 v1 逐字相同，仅 I4 的数字按 C6 订正**）

- **I1（默认关 = 逐位等价）**：`RESYNC_EN=0 ⇒ fwd ≡ 1'b1` ⇒ `acc_f ≡ acc` ⇒ 8 处替换在综合期
  **常数折叠回原式**；`resync` 无扇出（唯一作用点被常数真短路）⇒ 被优化掉；`rsw ≡ 0` ⇒ 计数器被优化掉。
  复核已独立扫过四个方向（**X 传播**下 `1'b1||x=1'b1`、`0&&x=0`、`x&&1'b1=x` 均成立；复位路径
  `:133-140` 语义兼容；表达式级常数非 generate；综合折叠）**无反例**。
- **I2（错被限制在"少收字"）**：新逻辑**只可能减少**被收下的字集合，且**只在 `resync==0` 期间**
  （从释放到第一个 SOP）；一旦 `resync==1`，`fwd==1` ⇒ 所有表达式与旧文逐字等价。
- **I3（与"钟停/钟不停"无关）**：门只看"释放之后"的字流，不看失锁窗口里 DP 有没有排空
  （§1.2）⇒ **两种子情形都被同一逻辑覆盖**。
- **I4（不可能死锁）**：`resync==0 ⇒ state==S_PASS ∧ m_axis_tvalid==0 ⇒ od_free==1 ⇒ s_axis_tready==1`
  ⇒ 丢弃支永远走得动（不依赖下游）；丢弃在下一个 `tuser` 拍结束（≤1 帧时间：**10G ≈1.22 µs、
  1G ≈12.18 µs** —— ⚠️ v1 写的"都是 ≤1.3 µs"是 10× 笔误，见 §0.0-C6）。
- **I5（守恒）**：`rst_n=1` 时 `acc ≡ acc_f + rsw`（划分）；`rst_n=0` 时 `acc ≡ acc_f ⊆ rsw=acc`
  （复核给出代数证明）⇒ 上游弹出数 = 交付数 + `stat_resync_words`，逐字可对（见 §3.3-J4）。

### 3.1 注入方案（**I-1 行按 C8 订正**）

## §4 代价与风险

### 4.1 时序（**预算，不是读数**；同 v1）

- 现役基线（`0x24`）：DP 域 WNS **+0.066**（派单给定值），DP 余量 ≈1%。
- 新逻辑落 DP 域 `vlan_strip` 的两条组合锥：① `s_axis_tuser → fwd → acc_f → load_*/FSM/hold` 使能/数据锥
  （+1 级 AND/OR）；② 同源 → `rsw` 计数器使能（只驱动 1 个 32 位计数器）。
  ⚠️ **`s_axis_tready`（`:105`）不在改动面** ⇒ "tready → `u_rxcdc.rd_en` → LUTRAM 组合读 → 头字 →
  下游"这条跨模块组合链**零新增级数**（Policy D 的附带好处）。
- 判据（落地后）：新构建 DP 域 WNS + **DP 前 10 报告面里 `u_vlan_strip/*` 的条数**；
  若进前 10 ⇒ **Plan B**：把门做成**寄存输出**（`fwd` 也寄存一拍 = +1 拍 RX 延迟，+2 FF；
  `vlan_strip` 是 1-deep 弹性、上游 256 深 FIFO 吸收；不改变帧几何）。
- 结论：**风险中低**（现役 DP 最差族是既存的 `u_tcp_tx/u_fifo_b→tcb`，不是 RX 入口）。

## §5 构建/板测计划

### 5.1 构建批次建议（同 v1 + BID 按 C11）

**建议：独立构建（不与其它 RTL 刀同批）**：
1. 本刀的判据在**仿真侧**（§3），板级只有"回归未受伤"一条正能量 ⇒ 构建的主要产出是
   "网表差异被限定为这一刀"，便于时序归因。
2. DP 域余量只有 ~1%（`0x24` 的 `+0.066`）⇒ 与别的刀同批会让"余量变化"不可归因。
3. 同批省一次构建，但换不回"事后 A/B 还要再构建一次"的代价（回退点是一行，但**位流**必须重建）。
- **BID = `0x25`**（⚠️ 本轮协调者裁定分配：本件 `0x25` / RFC 件 `0x26` / 换流门件 `0x27` ⇒ **不撞号**）；
  几何**不变**（71 字 / `0x14C`）。
- 构建入口 = **`board/run_build_p7b_ku5p.bat`**（⛔ 不许走 GUI 重编 `vivado_prj` 里那份
  `imports/board/wrapper_p4.v`——"永久禁发"陷阱仍在）。
- 归档纪律：`create_project -force` 会摧毁上一轮取证 ⇒ **归档写进构建脚本本身**。

### 5.2 板级可测性（诚实结论，同 v1）

- ⛔ **失锁在板上无法受控触发**：参考钟 = 板载 Y1 常亮；`MMCME4_BASE.RST` 在 RTL 里**硬接 `1'b0`**
  （`rtl/clk_gen_p6b.v:211`）；`rst_ext = ~reset_n` 走 PCIe 复位且**会同时复位 FIFO**（不构成 F-3 场景）。
- ⇒ **板级判据 = "未观测到"**（≠ F-3 不存在；本刀的收口依据是**仿真侧**读数）。
- 板上**能做**的三件事（都不判 F-3 本身）：
  1. **身份门**：`0x04 = 0x25` / 71 字 / `0x14C` 回 `0xffffffff` / `LnkSta x4` / 2 BARs；
  2. **回归未受伤**（本刀主正能量）：既有板级长跑逐字复现 —— TCP 连续下行 `9.1–9.3 Gbps`、
     `mism_bytes=0`、UDP 300 s `9.5336 Gbps / 809,577.8 fps`、双向 `8.9–9.0 Gbps`；
     期望**逐字不变**（I2：稳态 `fwd==1 ⇒ acc_f≡acc`）。⚠️ 读数带 `PIN_CPU=` 见证、核对核号；
     对端网卡中断合并状态现记（全局 #68）。
  3. **冷启动零影响**：上电时 DP 与 FE 同起 ⇒ 释放后首个交付字必是 SOP ⇒ 门不被激励。

### 5.3 与其它在飞项的排批（同 v1）

- ⛔ **不与 persist/0x1E 那类"已收口但未进位流"的刀混**（会毁掉各自的 A/B 锚）；
- ⚠️ 若用户要求"搭车"，本刀**可以**搭（只用参数不加宏），但**必须**把 §4.3-① 的清单写进构建脚本
  注释，并接受"余量变化不可归因"。
