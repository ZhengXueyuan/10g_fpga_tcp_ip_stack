## §2 前件（0x28 臂 = C1a）——【已证】读数 + 两条口径的分歧

**显式 PRE（gen=2）→ POST（gen=588）**：

| 量 | PRE | POST | Δ |
|---|---|---|---|
| W71 `stat_up_ev`（raw ev_up） | 0 | 0x90 = **144** | **144** |
| W72 `stat_sw_req`（同槽存活） | 0 | 0x2f = **47** | **47** |
| W73 `stat_sw_apply`（sw_apply 拍，**含补应用**） | 0 | 0x2f = **47** | **47** |
| W74 `stat_up_pend`（异槽存活） | 0 | 0x60 = **96** | **96** |

- **task 口径前件**：`ΔW71 > 0` ✓ ∧ `ΔW72 > 0` ✓ ⇒ **成立**。
- **三态恒等式（task 逐字 `ΔW71 = ΔW73 + ΔW72 + ΔW74`）**：**不闭合**（144 ≠ 47+47+96 = 190，残差 46）。
  **原因是 RTL 语义、且事先有登记**：`stat_sw_apply` 计**一切 `sw_apply` 拍（含登记后的补应用）**，
  而恒等式的第一项按脉冲级分解是 **`Δ(ev_up ∧ sw_apply)`**（`rtl/app_pattern.v:561-574` 注释逐字）；
  本轮实测 `Δ(ev_up∧sw_apply) = 144−47−96 = 1`（**推导量**），⇒ 补应用 = `47−1 = 46` 次。
  ⇒ 口径 = **"字面三项式不闭合（差 46）；RTL 文档化的四项式闭合"**；⚠️ 与 `p9_p3win_redesign` §3④
  "凡引 `ΔW73` 必须注明含补应用"一致 —— 本轮为该注脚提供了**首个含补应用的实测实例**。
- **轨迹（快照环，逐秒）**：事件以"每分钟若干小簇"形态到达；逐秒 `ΔW71 = ΔW72 + ΔW74`（±当拍应用 1）
  在几乎每个区间成立；`ΔW72` 约每 **2.56 s** 一次（47 次/125 s）。代表行（原文 `raw/C1A_snap.log`）：
  `t=86.81 dW71=2 dW72=1 dW74=1` / `t=108.98 dW71=3 dW72=1 dW74=2` / …
- **时基自证**：环上 `ΔW5 = 19,517,192,967` 拍 / 124.907 s = **156.2538 MHz**（+0.0024%）⇒ W5 = 156.25 MHz 拍钟
  【已证，可复算】；`ΔW43/ΔW5 = 0.9999951`（两口径独立核；W43 = 156.2523 MHz）。
- ⚠️ **设计件 §2.1(a) 期望门口径**：`E = N_同槽 × P = 47 × 5.0e-3 = 0.24 ≪ 3` ⇒ **不达标**。

`breaks==0` 率：**0x28 = 0/16（0%）** vs **0x24 = 2/40（5%）**。样本小（Fisher 精确 p ≈ 1.0，**不构成差异**）；
⚠️ 0x28 臂的事件级前件已达标（见 §2）但同样只有 16 候选 ⇒ 两臂在此读数上**不具可分离的统计功效**【未判定】。

### 4.5 为什么"字面达标"要打折（形态分析；全为【推断】+可复算依据）

1. **K0 的取值分布**：38 条 breaks≥1 的候选的 K0 **不是帧对齐的**（C1b2 的 26 条遍布 0.9M–780M；
   三臂全体 = **88 – 2,043,805,696**）；而 2 条 breaks==0 的 K0 **恰=1460 = 1 帧**（帧栅格上的最小非零值）。
   若这两条是 P-3 覆盖写命中，其 K0 应来自**同一任意相位分布**；**两条独立命中落在同一栅格值的概率
   ≈ 1/κ（κ = K0 覆盖的帧栅格数 ≈ 616 … 1.4M）⇒ ≲1e-6 量级**。⇒ 观测到的 breaks==0 总体
   **不像**从"任意相位"分布抽取的。
2. **退化情形**（产生同签名的良性机制）：**"干净重启（SEED）后第 1 帧被发给旧 4-tuple、新连接从第 2 帧接入"**
   ⇒ 新连接首字节 = `pattern[1460]`、此后无重启 ⇒ **完全一样的字节签名**。C1b2 的 handoff 链（§5-④）
   显示 conn237 是**当轮第一次 handoff**、且其数据窗与 conn0 的窗**零间隙相接** —— 与"conn0 拿第 1 帧、
   conn237 拿第 2 帧"逐条相容。
3. **仪器盲区（设计件未覆盖的方向）**：读数 B 只看**首 64 KB**；而实测"重启间距"分布 = **4.3 KB–62.5 KB**
   （38 条候选的首断点）⇒ 64 KB 窗对"有没有重启"的**假阴性率≈5%**（恰与观测到的 2/40 同量级）。
   ⇒ **"64 KB 内无重启" ≠ "过不存在重启"**；且在高速档 64 KB ≈ **0.1–6 ms 的墙钟**（见 §5-④ 速率），
   窗口期极短。
4. **设计件自身条款**（照录）：读数 B 必须把"跳变"与"重启"分开分类 ⇒ 命中签 = "**全流 coherent ∧ 无重启**"。
   ⛔ 本轮**办不到"全流"**：dump 上限 64 KB（工具参数 `--prefix-kb`），且**首个 dump 之前的流不可见**
   （若上一次 handoff 的续接已带跳变/重启，无法复核）。**"全流"读法 = 【未测】。**

### 4.6 推荐分离实验（不实施，供排期；逐条可落地）

1. **抓"前一位持有者"的尾部**：churn 加"**末 64 KB 环形前缀**"（dump 尾而非首）⇒ 若 handoff 良性，
   前持有者尾部应含"**针 + 恰 1460 B**"；若真命中，其尾部应为**无重启的续接**。⇒ 单参数增量。
2. **同槽事件的相位直读**（设计件 §3⑤ 的备用刀）：`stat_p3_win_ev` 计数器（0x28 可测）——
   把"命中率"从模型换成直读；⛔ 仍不能替 0x24 的 A/B 见证。
3. **降低速率重跑**（把 app 限速/加 gap）⇒ 让 64 KB 覆盖更长的墙钟窗，逼近"全流"。
