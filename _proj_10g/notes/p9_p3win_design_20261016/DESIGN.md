## §1 窗口命中条件的形式化（0x24/legacy；逐条 `file:line`，行号两代并列）

### 1.1 命中式
命中 ⟺ 存在一拍 T，**同时**满足（「现仓」行号；0x24 代行号见 §0-1）：

| # | 条件 | 现仓锚点 | 说明 |
|---|---|---|---|
| C1 | `ev_up`（raw 1 拍脉冲）有效，且 `ev_slot == act_id` | `:547` `same_slot` | 只认 raw；pending 到不了（§0-3①） |
| C2 | `active == 1` | `:548` `idle_now` | 空闲到达 ⇒ `up_ok` 走 `!active` 臂，但那一拍 `asm_go=0` ⇒ 干净 |
| C3 | `seg_sent == 0` ∧ `frm_wait == 0` | `:549` `up_ok` 第二臂 | **窗口的物理来源** |
| C4 | `!op_pend` ∧ `!pw_valid` ∧ `!closing` | `:625` `asm_go` 三项 | 三者缺一 ⇒ `asm_go=0` ⇒ 无装配写 ⇒ 干净 |
| C5 | `(frm_inflight \|\| tx_ok \|\| remain==0)` | `:625` 尾项 | 帧首 `frm_inflight = op_sent = 1` ⇒ 恒真 |
| C6 | `tx_lfsr` 位置 ≠ 会话起点（旧流位置 > 0） | `:1034` | **可见性**：位置 = 0 时覆盖与干净复位逐字节不可区分（xsim 实证：R5 impl 报告 §5-3 = "u_swc0 打到第 1 帧装载拍对 P-3 是空判据"） |

T 拍上的机制链（全部现仓行号）：`up_do=1`（`:550`）⇒ 换流块写 `tx_lfsr <= SEED`（`:832`）；同拍 `a2_hold=1`（`:623`，`ev_restart = sw_apply ≡ up_do`）⇒ `a2_ldw=0`（`:629`）、`wc_go=0`（`:664`）⇒ 装配落**逐字节支**（`:1025`），其 `tx_lfsr <= xs_next(tx_lfsr)`（`:1034`）**块序在后 ⇒ 盖掉 SEED**（Verilog 同块多次非阻塞赋值 = 后者胜）。净效果 = **"行政副作用全生效、图案流没重开"**（`DESIGN_v2` §1.4(P-3) 逐字）。

### 1.2 唯一性：为什么是"1 拍/帧"（附录 A 的结论）
`seg_sent == 0` 的拍每帧只有两处：**帧首 opener 拍**（`op_pend=1` ⇒ `asm_go=0` ⇒ 干净，pending 也在此被消费）与其**下一拍 = 首个载荷字装载拍**（`pw_valid=0`、`op_pend=0` ⇒ `asm_go=1` ⇒ **唯一可覆盖拍**）。此后 `pw_valid≡1` 到帧尾（A2 的"消费+预取同拍"路 `:1112` 保持 pw_valid），且 `seg_sent>0` ⇒ `up_ok≡0`。⇒ **窗口 = 1 拍/帧（A2 构建）**。

### 1.3 概率模型（本设计的所有密度估算都用它）
P(命中 | 事件落于该拍) ≈ 1/帧周期拍数 = `fps / 156.25e6` = **`W51速率[B/s] / (1460 × 156.25e6)`**：

| app 速率 | 帧周期（拍） | P(单事件) | 95% 命中所需事件数 ≈ 3/P |
|---|---|---|---|
| 9.14 Gbps（满速） | 199.7 | **5.0e-3** | ~600 |
| 4.0 Gbps | 456 | 2.2e-3 | ~1,360 |
| 887 Mbps | 2,057 | 4.9e-4 | ~6,200 |
| 52 Mbps（B4 涓流首连） | 35,100 | 2.9e-5 | ~105,000 |
| 1 Mbps（B4H3 实测均值） | 1.83e6 | 5.5e-7 | ~5.5e6（不可行） |

⚠️ 三条口径：① 事件相位按独立均匀取（本构型无锁相机制【推断】）；② 只对"事件到达时 app 处于健康中段"成立（§2.0 的未证前提）；③ `W51` 均值会掩盖停滞分布 ⇒ 必须与 `W63`（`stat_frmwait_cyc`）联读。**B4H3 复算**：11 事件 × 5.5e-7 ≈ 6e-6 ⇒ 两臂同绿是**结构性的**（不是"修复无关"的证据）。

### 1.4 可观测代理（板上能读什么 / 读不到什么）
- ⛔ **板上没有"命中"直读**：命中与未命中的差别只发生在"同一拍块序覆盖"⇒ 现有 75 字窗口（全为累计量）**结构性不可见**。
- **前件见证（板上，`0x28` 臂）**：`ΔW72(sw_req)+ΔW74(up_pend)` = 同槽/异槽"存活到达"事件数（源 `rtl/app_pattern.v:544-592`；三态恒等式 `ΔW71 = Δ(当拍应用)+ΔW72+ΔW74` 自洽 ⇒ 事件确实送达 app）；`ΔW51/ΔW5` = app 装配速率（P 的分子）；**`ΔW63`（`stat_frmwait_cyc`，`0x11C`）= 停滞拍数（去饥饿判据）**；`ΔW52` 帧数；`ΔW15`（fast path 发字节）/`ΔW51` = 重复率；`ΔW55` 重传次数；`ΔW20`/`ΔW43`/`ΔW5` = MAC/线侧几何与时基。
- **前件见证（板上，`0x24` 臂）**：**无 E12**——`0x13C..0x148` 在 0x24 几何里是 **MIR 四字**（⛔ 不许读成 E12；B4 已按此显式改写 KW）；可用 `W51/W52/W63/W64/W55`（`0x11C/0x120` 在 0x24 存在）⇒ **同槽事件数在 0x24 上不可直测**，只能由 `0x28` 同构型外推（B4 同款口径，如实标注）。
- **命中签名（对端/工具面，唯一可靠）**：sink 每连接 `first_mismatch / mism_bytes`（§3）；`align_check2` 的 `K0 / breaks / verified_prefix`（K0 三列）。
- **可选（需新构建，非本轮）**：一个**纯观测**计数器 `stat_p3_win_ev` = Σ(`ev_up ∧ same_slot ∧ active ∧ !closing ∧ !frm_wait ∧ !op_pend ∧ !pw_valid ∧ seg_sent==0`)——在 `SWC_OK=1` 构建上**安全**（I1 已保证不可能覆盖）且把**"命中"变成板上直读**（0x28 上即可量 hit rate，不必靠 0x24 的相位错反推）。若走此路：与 E12 同批、纯观测、不进任何控制锥（纪律同 E12）。

## §2 构型设计（对端侧，参数逐字）

### 2.0 共同前提与本轮主题（机制判据）
**命中类事件 = 「app 在帧中段（健康装配）」× 「同槽新连接 ADD」同时成立。** 两个分量各有实证边界：
- 「同槽」要求该槽先释放、再被新连接拿到最低空闲槽（`hls/src/layer_tcp.cpp:142`；B4 §4.3 的【推断】降级口径同）。**已证可造**（B4H3：10/12 事件 same_slot）。
- 「健康装配」要求 `tx_ok[act_id]==1`（源 `rtl/app_ctrl.v:557-572`：`state==ESTAB ∧ 在飞 < min(snd_wnd, WIN_CAP=61440) ∧ !fin_req/!fin_sent/!rst_req/!rst_sent`）。**B4H3 实测不成立**（~1 Mbps，主停 `frm_wait`）。

⇒ 三条互相独立的机制假设，**下一轮用读数分开**（这是本设计的骨架）：

| 假设 | 内容 | 预测读数（`0x28` 臂） | 后果 |
|---|---|---|---|
| **H1** | 对端杀旧连接后板侧**不发 DEL / DEL 晚于 ADD**（S0C 当年形态）；且旧会话 TCB 仍 `ESTAB` + 余窗（对端窗大、在飞少）⇒ app **继续满速装配** ⇒ ADD 落在健康中段 | `ΔW72>0` ∧ `W51` 高速率 ∧ `ΔW63/ΔW5` 低 | **命中类可达** ⇒ A/B 有判别力 |
| **H2** | ev_down 先到 ⇒ app `closing→idle` ⇒ ADD 时 app 空闲 | `ΔW72≈0`、`ΔW73≈连接数` | 每次干净应用（= B1/S2 形态）⇒ **本构型无判别力**（结构性缺席 ⇒ 空判据；不许读成"缺陷不存在"） |
| **H3** | 同槽事件有，但 app 一直停滞（卡 closing/frm_wait，B4H3 现状） | `ΔW72>0` ∧ `W51` 低 ∧ `ΔW63/ΔW5` 高 | 全干净 ⇒ 需先"去饥饿"（构型 B/旋钮） |

### 2.1 构型 A（主推）：单 sink「满速流 → 立即 abort → 重连」快循环
```bash
/tmp/p7b_biz/p7b_tcp_sink --host 192.168.100.2 --port 8080 \
  --rcvbuf 1048576 --conns 100000 --seconds 120 --maxbytes 2097152 \
  --poll-ms 300 --stall-n 2 --check lane8 --abort-rst
```
（旋钮：`--abort-rst` = `SO_LINGER{1,0}` ⇒ close 发 **RST**；**FIN 臂** = 同参数**不带**该开关；可选 `--local-port 40000`（同 4-tuple 臂，见 §2.3）· 可选 `--reconnect-delay-ms {0,0.5,1,3,10}` 延迟梯）

- **设计意图（逐项对应 §2.0）**：① `--rcvbuf 1 MB`（远超板侧自帽 `WIN_CAP=61440 B`）⇒ 板内 `tx_ok` 的门在正常工况恒真（in-flight ≈ BDP，远小于 60 KB），**且**对端停止 ACK 后旧会话仍余窗 ⇒ H1 的 α 场景可成立；② `--maxbytes 2 MB` ⇒ 每个 incaration 是一次 ~2 MB 的满速突发（满速 1.8 ms / 4 Gbps 4 ms），abort 落在装配中段（帧相位随机）；③ RST 而非 FIN（FIN 路已由 B1 证为"干净应用"族）；④ 立即重连 ⇒ ADD 落在 abort 后 ~0.1-0.3 ms（板侧握手实测 `conn_ms≈0.1`）。
- **预期事件密度**：每循环 ≈ 0.1-0.2 ms（connect）+ 1.8-4 ms（读）+ 0.3 ms（abort/重连）⇒ **~2-5 ms/循环 ⇒ 200-500 事件/s ⇒ 120 s = 2.4×10⁴ … 6×10⁴ 事件**。按 §1.3：若 `W51` 维持在 4 Gbps ⇒ 期望命中 = N × 2.2e-3 ≫ 1（3×10⁴ 事件 ⇒ 期望 ~66）；即便 `W51` 只有 887 Mbps ⇒ 期望 ~15。
- **前提**：`net.core.rmem_max ≥ ~512 KB`（请求 1 MB×2；见证 = `sysctl -n net.core.rmem_max` 落盘；不够就 `sysctl -w …`——本板自帽 60 KB ⇒ 只要 ≥ 120 KB 就够）。
- **风险（逐条，全部可观测）**：① RST 被板侧当"需 DEL"⇒ 落 H2（看 `ΔW72`）；② 同 4-tuple 臂板侧可能把新 SYN 当噪声（无 ADD ⇒ 无事件）【未证】；③ 板侧 HLS 对 ~500 SYN/s 的处理能力【未证】（看 sink `conn_ms` 分布 + `fail_conns`）；④ sink 每连接建 2 线程（含绑核）+ 打印 ⇒ 高频下自身开销【未证】（退路 = `--no-thread`，或 `--maxbytes` 翻倍降频）；⑤ 高事件率下 HLS 事件 FIFO/`up_pend` 覆盖（B4 注释：`up_pend_id` 单寄存器后写胜）⇒ 见证 = 三态恒等式是否仍闭合。
- **失败形态的可观测签**：`ΔW72≈0`（H2 或没建上）· `W51` 低（H3）· `fail_conns>5`（台架饱和）——三种都判**该臂无判别力/需重配**，不判缺陷。

### 2.2 构型 B（对照/兜底）：双 sink 错开 + 短 stall（B4H3 的"去饥饿"变体）
```bash
SINK_EXTRA='--poll-ms 200 --stall-n 2' bash k0_arm_b4_multi.sh <TAG> 2 0.4 1048576 40 120 200000000
```
（与 B4H3 逐字差异**只有两处旋钮**：`--rcvbuf 2920 → 1048576`（检验"微窗饥饿"假设）· `--poll-ms 1000→200`/`--stall-n 3→2`（周期 3 s → 0.4-1 s，事件密度 ×3-7））
- **价值**：这是**唯一已证能产同槽事件**的配方（B4H3 10/12 事件）；`--rcvbuf` 一改即同时检验"停滞是否由微窗造成"（若 `W51` 抬起来 ⇒ 事件虽少但每事件 P 变大）。
- **预期事件密度**：每 sink 0.4-1 s/事件 × 2 sink ⇒ **2-5 事件/s**（120 s ≈ 300-600 事件）。按 §1.3，若 `W51` 到 1-4 Gbps ⇒ 期望命中 = 300 × (7e-4 … 2.2e-3) ≈ **0.2-0.7**（**临界**）⇒ 本构型的角色是"事件类发生器 + H3 去饥饿检验"，**不是主猎场**；要它当主判据需把 stall 周期再压缩（`--poll-ms 100 --stall-n 1`）或加 sink 数。
- **风险**：若 `W51` 仍 ~1 Mbps ⇒ 该族**结构性把"同槽事件"与"停滞"绑在一起**（H3 成立）⇒ P-3 在此族不可达，且这是**真结论**（P-3 观察面在纯对端侧有结构性上限）。

### 2.3 构型 C（并入 A 的可选臂）：同 4-tuple 重连
`--abort-rst --local-port 40000`（新连接复用旧四元组 ⇒ 板侧 CAM/HLS 层面直接命中同槽，不依赖"最低空闲槽"分配器）。两类结局都可判：板侧认新 SYN ⇒ `ADD(同槽)`（最理想，且**不经过槽释放这一环**）；板侧当噪声丢弃 ⇒ 无事件（`ΔW72=0`，sink 侧表现为建连后零数据）。⚠️ 与 `--abort-rst` 配套（RST 关闭无 TIME_WAIT，端口可立即重用）。

## §3 两代可分签名（判别表）

命中类事件（§1.1 的 C1-C6 同时成立）在两代上的分岔：

| 维度 | **0x24**（未修，legacy 路径） | **0x28**（已修，`SWC_OK=1`） |
|---|---|---|
| 事件拍反应 | `up_do=1` ⇒ 当拍应用；`tx_lfsr<=SEED`（`:832`）**被逐字节支 `xs_next`（`:1034`）覆盖** | `ev_same_act` ⇒ `sw_pend + closing<=1`（`:884`/`:910`）⇒ W3 收尾（`drop_pw` 因 `seg_sent==0` 成立，`:516`；`close_send` 发 0 载荷 tlast）⇒ `active=0` ⇒ `sw_apply` 干净重开 |
| 新连接首载荷 | **旧流位置续延**（相位错；**无内部断点**） | `pattern[0]` 起（干净） |
| **sink 行（主判据）** | `first_mismatch=0` ∧ `mism_bytes ≈ bytes − bytes/256` | `first_mismatch=-1` ∧ `mism_bytes=0` |
| align（副判据） | `K0>0` · `breaks=0` · `verified_prefix=n`。实测样本（S0C）= **37,960 = 26×1460（恰整帧倍）**；源读推演另有 **`+1` 变体**【未证】（现仓 `:1112` 的 a2 支会清 `stg/bcnt` ⇒ 预装字节是否被吃，纸上不能裁）⇒ **以工具读数为准**。⚠️ `K0>4 MB` 时 `align_check2` 的 `find` 失败（头上限）⇒ 记"**无读数**"，不许记 0 | `K0==0` · `breaks=0` · `verified_prefix=n`（K0 三列**全过**） |
| 板侧 E12 | **无仪器**（0x24 几何里 `0x13C..0x148` = MIR 四字） | `ΔW72 ≥ 1`（该事件计入 `stat_sw_req`）+ 三态恒等式闭合 |
| ctl pcap | 事件前后**板侧零控制帧**（B4H3 实测形态） | 同上 + **老帧收尾 = 线上会出现一个 0 载荷数据帧**（54 B 头；R5 impl 报告 §5-7 同族机制）——`0x28` 上"命中类事件"的**唯一线侧可见痕迹**【推断】 |
| 后续连接 | **逐周期独立**：下一次干净应用即回到 `pattern[0]`（命中只污染**当周期那一条连接** ⇒ 每事件 = 一次独立 Bernoulli） | 恒洁净 |

**读数优先级**：① sink 每连接 `first_mismatch/mism_bytes`（**主**，工具已在役，不需对齐）；② align `K0` 三列（**副**；本构型每周期 ~2 MB ⇒ 第 1-2 个命中周期可测，之后超 4 MB 头）；③ 板侧 `ΔW72/ΔW51/ΔW63` 只作**前件**见证（§1.4）。

## §4 板级协议草案

**臂表**（同会话、紧挨、逐臂一烧；**两代同参数**）：

| 臂 | 位流 | 构型 | 时长 | 目的 |
|---|---|---|---|---|
| **A0** | `0x28` | 构型 A（`--abort-rst`） | 120 s | 前件见证 + 洁净期望 |
| **A1** | `0x24` | 构型 A（同参） | 120 s | **缺陷臂** |
| A0′/A1′ | 两代 | 构型 A 的 **FIN 臂**（去 `--abort-rst`） | 各 60 s | abort 类型因子 |
| B0/B1 | 两代 | 构型 B（同参） | 各 120 s | 兜底（同槽事件发生器 + 去饥饿检验） |
| （可选）C0/C1 | 两代 | 构型 C（`--local-port`） | 各 60 s | 同 4-tuple 通路 |

**步骤**：环境前置（`P7B_LOOP_HANDOFF.md` §6 新块 + NIC 四行 + `rmem_max` 见证）→ 部署（md5 见证）→ **烧 0x28 + 身份门**（`BID=0x28`/75 字/`0x15C`）→ 快照环 + 两路抓包 + PRE → 跑 A0 → POST + nstat → **烧 0x24 + 身份门**（`BID=0x24`/71 字/`0x14C`，KW 按 §2.4-2）→ 跑 A1 → …（B/C 同理）→ **收尾 = 烧回 0x28 + `0x08=0` + 核 `carrier=1` + 0 残留进程**。

**判据（口径，不裁定）**：
- **前件（每臂必过，否则记"无判别力"）**：`0x28` 臂 **`Δ(W72+W74) > 0`** ∧ **`W51` 均值 ≥ 1 Gbps** ∧ 三态恒等式闭合；**建议门：`Δ(W72+W74) × P(W51速率) ≥ 3`**（预期命中 ≥3 —— 这是"若 H1 成立则必现形"的门槛）。任一不满足 ⇒ 该臂记 **"无判别力"**（`0x24` 的阴性结果**不许**当证据；全局 #92 口径）。
- **缺陷臂**：`0x24` 臂 ≥1 条连接满足 `first_mismatch ≥ 0` ∧ `mism_bytes ≈ bytes − bytes/256` ⇒ **"命中已现形"**（并可复算 align `K0`）；**0 条 ⇒ "本构型下未命中"**（⛔ 不许写"不存在"、"缺陷已被证伪"）。
- **洁净臂**：`0x28` 臂全连接 `first_mismatch=-1 ∧ mism_bytes=0`（期望值；B4 已 11/11）⇒ 若出现反例，先查构型污染（如 pcap 相位/涓流）再登记。
- **预算**：每烧 3-5 min；每臂 2-3 min；**A0/A1 优先（~25 min）**，B/C 只在 A 落 H2/H3 时跑；全做 ≈ 8-12 跑 / 40-70 min。日志体积（3×10⁴ 连接 × ~400 B ≈ 12 MB stdout/臂）**登记**。
- **杀停准则**：`fail_conns>5` · 快照环异常 · 连续 ≥3 周期 sink 收 0 字节（app 未被服务/未切换）⇒ 停臂重配。
