# port0 (.2 / app_multi8) 数据停顿调查（2026-11-06，进行中）

> 状态：**根因未定位**；现场证据已抓（V2 轮），诊断构建 **0x3D** 在跑（W98/W99）。
> 本文只记录【已证】读数与【推断】假设，假设均标注可证伪点。

## 1. 现象（【已证·板级】）

- `.2` 口一轮 8×256MB：TCP 三次握手全部成功（`conn_ms` 0.09–0.17 ms），但部分/全部连接
  **收不到任何数据**（`bytes=0` 或部分后停）；对端窗口恒 65535、无 RST、无重传帧。
- 抓包（`/tmp/wedge.pcap`，板 0x3C 楔死态单连接）：SYN / SYN-ACK / ACK 后 **板侧 9 s 零数据帧**，
  第 9 s 对端发 FIN（sink 超时），板回 FIN-ACK ⇒ 慢路径/HLS 活着，**只有快路径数据不出**。
- 同刻 `.4` 口（port1，独立实例）**8.8 Gbps / mism=0** ⇒ 不是 MAC/GT/线/对端。
- 一次严重楔死态（02:51–02:56）持续 ≥5 min，单连接 0 字节；重烧清除。

- **W66/W67（帧器窗口门）冻结** ⇒ 不是"在窗口门等"（winstall 只数**帧首启动点**的等窗拍）。
- **W68（tcp_rx 推进 ACK）冻结**、**W55（retx）冻结** ⇒ 快路径无在飞数据、无 ACK 处理、无重传。
- **W51=0x3d**（5 槽"可接收新帧"）、**W52 estab=5** ⇒ app_ctrl 侧仍有 5 条 ESTAB；
  但 8 条连接里 2 条完成、6 条停顿 ⇒ **app 的信用位与快路径实际放行不一致**。

## 3. 关键结构（源码，【已证·源码】）

- `tcp_tx_frame.tready`（`rtl/tcp_tx_frame.v:731`）：
  - 帧首拍（`recv_first=1`）要求完整启动门：`wnd_open && !tx_blk_sid && !ack_pend_r &&
    !svc && !ring_eval && !scan_now && !rx_flush && !fifo_full && !bank_rdy[rx_bank]`；
  - **帧内拍（`recv_first=0`）只要求 `!fifo_full && !bank_rdy[rx_bank]`** ⇒ 一旦开帧，
    后续拍不再看连接状态。
- ⇒ 若某槽 `wnd_open`/`tx_blk` 与 app_ctrl 的 `app_tx_ready` 不一致，该槽的帧会**开了头**，
  但若 TX 引擎不排空该 bank（`bank_rdy`）或 FIFO 满，`tready` 掉 ⇒ **整条 app TX 合并总线
  被这一帧占住（AXIS 不可撤）⇒ 所有槽饿死**。
- `tx_arb`（`rtl/tx_arb.v`）：一旦选中某流即锁定到 TLAST；慢流若中途断 valid 会永久锁死
  （但 `slow_tx_adp` 是**整帧缓冲后才可见**，`rtl/slow_tx_adp.v:10`，慢流结构性不断供）。
- `slow_cfg_adp`：ADD 逐字段写 TCB，每字段等 `cfg_gnt`（tx>rx>cfg）；`ev_up` 在
  **最后一字段（wscale）落地拍**发出 ⇒ app_ctrl 认为 ESTAB 时，TCB 字段**理论上**已配全。

## 5. 假设（未证，按可证伪点排序）

1. **H1 快路径 TCB 与 app_ctrl 视图不一致**（`snd_wnd=0` / `tx_blk` / `state≠ESTAB`），
   app 照常呈交帧 ⇒ 帧首被接（若不一致发生在首拍判据**之前**不会开帧；更可能发生在
   `wnd_open=1` 开帧后、TX 引擎不排空 ⇒ FIFO 满 ⇒ 帧内停）。
   证伪/证实 = W98/W99 的 `wnd_open`/`tx_blk_sid`/`rb_state`/`rx_state`/`fifo_full`。
2. **H2 RX_FLUSH 死锁**：`len_over/len_bad` 进入 RX_FLUSH 后等 `fifo_empty_rx`，而该 bank
   无 `bank_rdy` ⇒ TX 引擎不排空 ⇒ 永久等。证伪 = W98 的 `rx_state==RX_FLUSH` 且 `fifo_full`。
3. **H3 TX 引擎卡在 T_DONE**（等 `m_axis_tready`），下游 arbiter/MAC 不收。
   证伪 = W99 的 `tx_state` + `m_axis_tvalid/tready`；若 `tvalid=1/tready=0` ⇒ 指向下游。
4. **H4 换烧 warm-up**（HLS/BRAM/对端瞬态）：只解释"高发窗口"，不解释单次楔死持续。

## 6.5 修复 0x3E（构建 PASS + 板级验证通过）

- `rtl/tcp_tx_frame.v`：参数 `DRAIN_EN`（port0 = 1 / port1 = 0，常数折叠）+
  `drain_r`/`drain_cnt`：帧挂起（`rx_state==RX_IDLE && recv_first && s_axis_tvalid`）且
  **`st_ok==0`** 持续 **65536 拍（≈419 µs @156.25MHz）** ⇒ 置 `drain_r`，
  把该帧所有拍**接收并丢弃**（`tready=1`；`wr_act`/`wr_tap`/收帧体/E1a `first_present` 均以
  `!drain_r` 门控），到 `tlast` 复位。判据**不接** `app_tx_ready` 输入（0x3D 实测该槽 app 侧
  ready 亦为 0；419 µs 远长于 DEL→ADD 过渡；少一根 16 位输入 = 少一层布线/时序代价）。
- **代价** = 该连接丢一帧（其 TCB 已死、本来发不出去）；**收益** = 端口不再楔死。
- 判据要求 `st_ok=0`（TCB 非 ESTAB）⇒ 活连接的窗口关闭（窗口=0 时 `st_ok` 仍=1）不触发。
- **构建**：尝试 A–F（策略/简化/DRAIN_EN/probe 轮换），最终 **F = `Congestion_SpreadLogic_high`
  PASS**：WNS **+0.038** / WHS +0.010 / 三类端点 **0/0/0**；位流
  **`572a7e91697d98805b1dfb9dc738a12ad5bcb375c1551a9c5d32b086df36ed2b`**（15,431,261 B）；
  BID **0x3E** / NW **98** / UNIMPL **0x1B8**。读数 = `build_ok_0x3E/`。
- **板级（已证）**：烧录身份门全中（BID 0x3E / NFF=0 / 2 BAR / 两 carrier=1）；
  换烧周期 **64 轮 × 8×256 MB = 512 连接，64/64 轮 `OK=8 STALL=0`**（零停顿）。
  原件 = `raw/burn_cycle_0x3E_cycle*.txt`（10 个文件、共 64 条轮记录，逐条 grep 计数）。
- **同会话 A/B**：同一换烧周期工装（同端口 `.2`、同 8×256 MB、同堆叠 sink），
  0x3D 两窗口合计 **48 轮 / 35 个停顿连接**（窗口 1：19/24，窗口 2：16/24），
  0x3E **64 轮 / 0 停顿**（512/512 连接收满）⇒ 行为面成立（详见 §6.6 汇总表）。
- **上一层根因（源码复核，2026-11-07）**：HLS 的 DEL 只有三条合法路径 ——
  `T_SYN_RCVD` 收到对端 FIN、4 元组命中 RST、同四元组 bare SYN 回收
  （`hls/src/layer_tcp.cpp:656 / :685 / :756 / :778`），全部按 `cid` 定位、**不存在跨槽误清**；
  `slow_cfg_adp` 的 DEL = CAM 该槽清零 + TCB `state=0` + `ev_down`（`rtl/slow_cfg_adp.v:15,172-181`）。
  ⇒ **楔死的"上一层"不是错误的 DEL，而是关闭路径与在途帧的协议竞态**：连接合法关闭
  （对端 FIN/RST/完成 maxbytes 后 close）时，app 在共享 TX 总线上仍有一帧未及交接
  ⇒ TCB 已清、帧无人接收。**排水 backstop 因此是结构性修法，而不是绕过一个错误状态源。**
- **未覆盖**：帧内形态（`recv_first=0`，由 FIFO/bank 门决定）——本轮 0x3D 现场未观测到该形态。
- ⛔ **2026-11-07 12:4x 订正（0x3E 排水判据有缺陷：多连接同时活着时从不触发）**：
  `frame_pending` 直接用了 `!st_ok`，而 `rb_id` 在 `svc/ring_eval/scan_now/probe` 拍被
  仲裁**借走**（`rtl/tcp_tx_frame.v:727` 的 mux）⇒ 那些拍的 `st_ok` 属于**别的连接**。
  `scan_now` 每 16 拍 1 次（`tick_cnt == 4'd15`，`:600`）且 `scan_id` 轮转；只要任一条
  ESTAB 连接被扫到 ⇒ `st_ok=1` ⇒ 旧代码走 `else` 把 `drain_cnt` 清零 ⇒ **计数器永远
  到不了 65535**。⇒ 排水只在"全表非 ESTAB"（其余连接都已关闭/空闲）时才能攒满。
  **板级证据 A（0x3E，同时 8 连、无错开；`raw/sim_conns_0x3E_and_0x3D.txt`）**：
  sim1 8/8、sim2 8/8、sim3 6/8（2 停顿）、sim4 8/8、sim5 8/8、sim6 5/8（3 停顿）、
  sim7 8/8、**sim8 0/8（8 条全停，bytes 0–5840，4.0 s 不恢复，随后单连接立即 8.45 MB OK）**。
  **板级证据 B（0x3D 同时连复现，`raw/sim_stall_0x3D_run1.txt`）**：4 轮 =
  8/8、8/8、8/8、**2/8**；R4 停顿现场 `W71=0x94103884` 冻结 4 拍：
  `st_ok=0 / tx_blk_sid=1 / recv_first=1 / tvalid=1 / tready=0 / wnd_open=1 /
   acks_ok=1 / start_id=5`；同刻 `W52` 低半 = **6 ESTAB**、`W51=0x5f`
  ⇒ 正是"别的槽 ESTAB ⇒ 扫描拍复位计数"的现场。
  ⇒ **§6.5 的"64 轮零停顿"必须降级为"错开工装下触发器未命中该缺陷"，
  不能读作"排水已工作"**（0x3E 在"其余连接已关闭"的收尾窗能恢复，与"全表非 ESTAB
  时计数才能攒满"的模型逐条吻合）。
- **修法 0x3F（构建中）**：只在读口**确实指向本帧槽**（`rb_id == s_axis_tid`）时采样
  `st_ok`；`svc/scan/probe` 借走拍**保持**计数；明确观察到本槽 ESTAB
  （`rb_is_tid && st_ok`）才清零；`!frame_live`（帧真的不在，含 `ack_pend_r`）清零。
