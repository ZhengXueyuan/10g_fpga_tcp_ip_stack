## 1. 分级发现

### 高

---

**H-1｜`slot_dead` 电平语义 ⇒ 跨 pass 连环误杀窗**

- **位置**：审查件 §1.2-3（"建议在 pass 开头先应用掩码，再处理本帧"）。
- **事实链**：
  1. 设计语义 = 电平采样：HLS 每个 pass 开头读 `i_slot_dead`，位=1 即 `state=T_FREE; retrans_pending=false`。
  2. 置位（app_ctrl `ho_fire`）与清零（"cfg ADD 命令字到达 demux 时"）之间有一条**数十拍量级**的链：HLS `cfg_write(ADD)` → `slow_cfg_adp` S_RECV 逐词 8 词 → TCB/CAM 写 → demux 清 `slot_dead` 位。
  3. HLS 小帧（SYN 类 ~14 词）pass 周期与上述链同量级 ⇒ 中间 **1–N 个 pass** 里 `slot_dead[S]` 仍 =1，而槽 S 可能已被新 SYN 重建（pass N 掩码后 tcp_find 见 T_FREE → 分配 → SYN-ACK）。
  4. 后续 pass 开头掩码把**刚合法重建的半开槽反复杀掉**（`retrans_pending=false` 掐断 SYN-ACK 重传）；对端第 3 段 ACK 若落在 CAM 建立前 ⇒ fast 丢 ACK ⇒ 半开卡死至下一次老化。
- **后果**：偶发秒级建连延迟 / 连接卡死——与现役 .2 口停顿缺陷**同族**（合法事件与在途状态的竞态）。
- **件内盲区**："pass 开头先应用掩码"只解了同 pass 内的执行顺序，未解跨 pass 的电平滞留；对清零链的拍级延迟预算零讨论。
- **建议方向**（供开发组选裁，审查方不定案）：掩码改**边沿语义**（HLS 只对 0→1 跳变响应一次，响应后自清或回 ACK）；或给出清零链延迟预算并证明 < 1 个 HLS pass 周期。
- **处置**：＿＿＿＿

---

**H-2｜槽号空间映射整块缺失（16 位物理槽 ↔ 8 位 HLS cid ↔ demux 端口）**

- **位置**：审查件 §1.2-2 / §1.2-3。
- **事实**：C4 架构下 8 个 HLS 槽按 `slot_port` 属主动态分到两端口（`wrapper_p4.v:2843`"槽属主映射"、`:3960`"H-2: 不用 cfg_slot_port——它在 ADD 路由拍就翻转"）；每端口独立 `u_tcb`/`u_tcb2`（各 16 深，`tcb.v:9 N=16`）；app_ctrl 为 16 物理槽视图（`c_rcv_nxt[0:15]`、`orph_*[15:0]`）；HLS `MAX_TCP_CONN=8`（现役构建宏覆盖，`layer_tcp.cpp:13-14` 默认 3）。
- **三个具体空白**：
  1. `ho_fire` 的 scan_id（物理槽）→ `i_slot_dead` 位（HLS cid）的**换算关系未写**；
  2. "cfg ADD 到达 demux 时立即清"——demux 按 local_ip 路由、**知道端口**，但清 16 位中的**哪一位**未写：裸 cid 索引会撞车（port0 槽 3 的 ADD 会清掉 port1 槽 3 的 dead 标志 ⇒ 该半开槽泄漏继续）；按物理索引清则需要 demux 输出端口维（机制存在：a1/a2 两路 ev，wrapper :3360，但设计件未接）；
  3. 跨端口共享索引使 H-1 的连环杀更严重（一端口的合法重建会滞留另一端口的同号 dead 位）。
- **后果**：照件施工时槽号语义必然实现错或竞态 undefined。
- **建议方向**：设计件必须补一张"物理槽(p,s) ↔ HLS cid ↔ demux 端口"三方映射表，并明确清零动作的索引空间与端口来源。
- **处置**：＿＿＿＿

---

**H-3｜R3-1b 同 pass 双 tcp_send 洞（单独上不闭环）**

- **位置**：审查件 §2.1 R3-1b（"把 :257-260 整块前移到 :157 之前"）。
- **事实链**：
  1. 补做 A 的 `tcp_rx_process` 内 `tcp_send` 置 `tx_req.request`；
  2. 随后本帧 B 走 `udp_echo.cpp:182` 分支，**该分支只查 `mac_tx_busy`**——A 的请求尚未使 busy 立起（`mac_tx_process` 已在 :142 执行完，busy 下拍才变）；
  3. ⇒ B 直接 `tcp_rx_process`；若 B 也触发 `tcp_send`（B=SYN）⇒ **第二次 tcp_send 覆写共享 TX 区，A 的 SYN-ACK 丢失**。
  4. 原设计无此洞：补做（:257-260）与下一帧处理天然隔 pass。
- **旁证**：:160-162 的"新帧完成即作废 pending"注释证明该次序是**有意防错帧设计**（frame_buf 头区将被本帧覆盖）——R3-1b 动了有意防护之一但未给替代论证。
- **结论**：
  - R3-1b + 补做门控加 `!tx_req.request`（或补做了就强制 B 进 pending）后，**只修**"忙窗恰在 B 完成前结束"的同 pass 竞态；
  - 忙窗内两帧（ARM_B2 / §0-88 同时 SYN）**必须 R3-1a（2 深 FIFO + 帧拷贝）才闭环**——与件内"R3-1b 修不了 ARM_B2"自承一致，但"闭环在 R3-1a"这点件内排序段没有明说。
- **建议方向**：R3-1b 条目内补互斥门控条件；§0 结论表"风险极低"改判。
- **处置**：＿＿＿＿

**M-1｜"静默拆除"与复用 orphan 机自相矛盾（双释放路径交互未论证）**

- **位置**：§1.2-1 / §1.2-3。
- **事实**：`app_ctrl.v:1642` 的 `orph_fire` 分支进入 orphan FSM (a)–(d) 后 **`o_ev_down` 必然发出**（`:1674-1682` notify_pend → orph_down_r 必经）⇒ `slow_cfg_adp` 收 ev_down 发 DEL ⇒ **HLS 槽经 ev_down 路径释放**。于是 HLS 槽有**两条释放路径**（i_slot_dead 掩码 + ev_down DEL），设计件把 i_slot_dead 当主机制、称拆除"静默"，与 orphan 机机制矛盾；两路径的时序交互（ev_down 晚到是否杀新槽：fire→ev_down ≈ 10–20 拍 vs 对端 SYN 重传 ≥1 s ⇒ 实际安全）**论证缺失**。
- **建议方向**：明确 ho_fire 是否复用 orphan 机的 notify 段；若复用，论证 i_slot_dead 的必要性（提前量价值）或改真静默（需新通知路径设计）。
- **处置**：＿＿＿＿

**M-2｜R3-2b 可接受，但两个关键消解论据缺席**

- **位置**：§2.2 R3-2b。
- **事实**：256 拍陈旧窗（= 每槽扫描轮询周期，`app_ctrl.v:103-104`）有两个反洞机制件内未写：
  1. **ADD init 立即刷新该槽快照**（`app_ctrl.v:1185` `c_rcv_nxt[init_head] <= rc_rcv_nxt`）⇒ "同四元组快速重连 + 旧 FIN"场景在重连瞬间快照即新值，旧 FIN（旧连接晚期 seq）必被拒——**该场景实际闭合**；
  2. 混合数据连接合法 FIN 的 false-reject（rcv_nxt 前进 vs 快照滞后）**被 RST 无校验分支兜底吸收**（代码注释自承"PC 侧 close 最终靠 RST 兜底完成"，layer_tcp.cpp T_SYN_RCVD FIN 分支注）。
- **后果**：方案判"可接受"成立；但施工验证时若不知道②，会把 false-reject 误判为新缺陷返工。
- **建议方向**：把①②写进设计件判据与验证清单（板级注入伪造 FIN + 快速重连臂）。
- **处置**：＿＿＿＿

**M-3｜`ack_obs` 的 OVL 依赖未传导**

- **位置**：§1.1 / §1.2-1。
- **事实**：`ack_obs` 在 `` `ifdef TCP_TX_OVL `` 分支内，`else` 分支恒 0（`tcp_rx.v:620-623`）⇒ 非 OVL 构建下 `ho_ack_seen` 永不置位 ⇒ 半开老化会把**所有**半开槽（含正常重试中的）在 3.44 s 拆掉。现役构建 OVL=1 无即害，但件内"端口存在性门仿 wrapper:4042-4046"清单漏了 OVL 条件。
- **处置**：＿＿＿＿

**M-4｜ev_up 复位机制表述失真**

- **位置**：§1.2-1（"1 s/3 s 的 SYN 重传会在到期前重新 ev_up 复位"）。
- **事实**：SYN 重传复位 ho_cnt 不是自动的，是经 bare-SYN 回收（`layer_tcp.cpp:657-677` DEL+ADD 重建）才有新 ev_up ⇒ **fast 侧每 1 s/3 s 闪断一次 CAM/TCB**。半开态无在途数据 ⇒ 安全，但应注明机制与代价（且与 M-1 的 ev_down 路径叠加：回收时 DEL 的 ev_down 会发）。
- **处置**：＿＿＿＿

## 2. 对委托方三个重点问题的直接回答

1. **slot_dead 清零竞态（优先条）：有洞。** 不在"同 pass 掩码 vs 新 SYN 初始化的顺序"——那一步（先应用掩码、后 tcp_find）本身无洞；洞在 ① 掩码**电平语义**的跨 pass 滞留（H-1）与 ② 16↔8 位槽号空间未定义（H-2）。优先打 H-1/H-2。
2. **R3-1b：单独上不闭环。** 同 pass 双 tcp_send 洞（H-3）必须先补互斥门控；§0-88 / ARM_B2 的闭环要靠 R3-1a（2 深 FIFO + 帧拷贝）。
3. **R3-2b：可接受。** 但须把"ADD 即刷新快照（app_ctrl.v:1185）"与"false-reject 由 RST 兜底"写进设计件判据（M-2），否则验收时必误判。
