# P8 阶段三 采集侧 8B/拍 —— 选型 (动手前写清)

## 缺陷 (板级实测)
镜像采集侧结构上限 4 B/拍 (32 位写口 + 跨拍累加器), 对 app RX 口的 8 B/拍连续吐字 ⇒ 恒丢 50%
(板级三条独立签名: 计数恒半 / 偶数组全收奇数组全丢 / first_mismatch 恒 8)。

## 需求 (定量)
- 写侧: 源 ≤8 B/拍 (一次源拍最多 8 B) 必须**整拍吸收** ⇒ 写口 = 64 位 (1 拍 1 字)。
- 读侧: "8 B/拍持续源 ⇒ drop_bytes==0" 这条新正判据 (派单 §3①) 要求**持续**吞吐:
  源上界 = 8 B/拍 × 156.25 MHz = **1.25 GB/s** = 312.5 M 逻字/s (2 逻字/源拍)。
  单 32 位出口 = 1 字/rd 拍 × 250 MHz = **1 GB/s < 1.25 GB/s** ⇒ 单出口结构上不够。
  ⇒ DMA 排空口必须 **2 逻字/拍** = 2 GB/s (> 1.25 GB/s, 余量 1.6×)。
  ⚠️ 派单里写"2×32/拍 = 1 GB/s 余量足够" —— 算术: 2×32 bit/拍 = 8 B/拍 × 250 MHz = **2 GB/s**
  (不是 1 GB/s; 1 GB/s 是"1×32/拍"的值)。结论 (余量足够) 成立, 数值按 2 GB/s 记。

## 候选
A. **64 位 FIFO (WIDTH=64) + 读侧 64→2×32 拆分 (stash) + DMA 口 2 字/拍 + 环写口 64 位**  ← 选它
B. 双 32 位 FIFO (偶/奇字分 lane), 读侧交替, DMA 口两 FIFO 同拍各弹 1 字
C. 只改写侧 (64 位 FIFO), 读侧/DMA 口仍 1 字/拍 —— 不选 (新正判据结构上过不了)

## 对比与理由
| | A (64b FIFO) | B (双 32b FIFO) | C (只改写侧) |
|---|---|---|---|
| 写侧 | 64 位累加器, 1 字/拍 | 64 位累加器 + 双 FIFO 派发 + 各自 full 门 | 64 位累加器 |
| 读侧 | 单 FIFO 读口 + 1 字 stash | 两个读口 + sel 交替 | 单读口 1 字/拍 |
| CDC 顺序 | **单条灰码链 ⇒ 顺序由结构保证** | 两条独立 2FF 链 ⇒ 同拍写的 A/B 可见性可能差 1 个 rd 拍 ⇒ 需跨链顺序守卫 | 单链 ✓ |
| 持续吞吐 (DMA) | 2 字/拍 = 2 GB/s ✓ | 2 字/拍 = 2 GB/s ✓ | 1 GB/s ✗ |
| 4 字节粒度 | 变 **8 字节** (K%8 前置) | 保持 4 字节 | 变 8 字节 |
| level 单位 | 2×occ + stash (9 位需 clamp ≤511) | occA+occB (天然) | 需 ÷ 口径 |
| 门改动面 | p6e 的 4B 注入期望须改 8B 对 | 期望值基本不动 | 期望值基本不动 |
⇒ **A 胜**: 唯一"顺序由结构保证"的方案 (B 的跨链 1 拍可见性偏差 = 静默乱序风险, 不值得换 TB 少改几行)。
C 被新正判据直接否决。

## A 的代价 (如实登记)
- K%4 → **K%8** 前置条件 (尾部 1–7 B 停在累加器, 与既有 1–3 B 同性质) ⇒ 工具 `--bytes` 硬门
  与字节账协议要 8 对齐 —— **属读侧/工具同步项, 本轮不做, 只报告** (派单 §5 禁止读侧同步)。
- `MIR_STATUS.level` 语义**单位不变** (仍是 32 位字), 但内部 = 2×occ64 + stash_v, 满量程 clamp 511
  (只少报不多报 ⇒ "读恰好 level 字"协议安全)。
- 新增 u_mir 端口 `dma_data[63:0]` (DMA 口 2 字/拍) ⇒ wrapper 接线 + 环写口 64 位 (端口变化**报**)。
- FIFO 256×64 (LUTRAM, FWFT=1) ≈ 256 LUT (原 256×32 = 128 LUT)。
