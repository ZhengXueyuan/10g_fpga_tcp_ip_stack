## 高发现速览（阶段二开工前必须折叠）

1. **RFC §7.2 板测注入式符号反了**〔BUNDLE_RFC〕：`seq = rcv_nxt − Δ, Δ≥2³¹` ⇒ `d_mod = 2³²−Δ < 2³¹`，按设计件自写的分歧域口径**永远在等价域外**；复算 rcv_nxt=0x100 时两臂逐位相同 ⇒ A/B 实验为空判据。正确式 `Δ∈(0,2³¹)`（已验证 Diverge 方向①）。连带 §1.5/§7.2「分歧域=d_mod≥2³¹」单侧刻画漏行 4 域（扫描 89 万反例对）。
2. **换流门修法两个一票否决级洞（H-1/H-2）**〔BUNDLE_UPOK〕：按设计件字面方程，(a) `ev_up` 在 closing=1 或 active=0 态到达被静默丢弃（sw_now 门槛+登记被堵死）——closing 态到达是顺序重连常态，构成对 A3 已修场景的回归；(b) E4「块体一字不动」使应用拍 `act_id<=up_slot=up_pend_id`（陈旧/复位值 0），E6 的 `sw_slot` 无人消费 ⇒ 换流应用到错误槽。**两门洞均不在任何门臂覆盖下**。
3. **换流门门臂 u_swc1 是空判据（H-3）**〔BUNDLE_UPOK〕：单事件帧中段 ev_up 在旧 RTL 于下一帧 opener 拍被干净补做 ⇒ 旧 RTL 也绿，「旧 RTL 必红」不成立；P-1 单事件延后对对端字节流不可见（断点形态须 P-3 前缀+后续干净 apply 组合）。

## 中发现择要

- **RFC「双向」结论需降级表述**：反向域数值分歧真实，但行为后果限闭窗瞬态且该域 ACK 是 RFC 对不可接受段的 prescribed 响应（rcv_wnd≤1 才分叉）；§0 与台账 §10-55(a) 同权并列会误导施工轮。
- **RFC G 臂 snd_wnd 终态写死错误**（§5.4 写 0x2000，实际 0x4000）⇒ 照写进门判据则 G 臂假红。
- **RFC §5.5 模型规格在 w6a 支锁存 wnd_l 而 RTL :766-771 不锁**（机制不镜像，本激励被同值掩盖）。
- **F-3 M1**：§1.2 称 t9 变体 A 片段「逐字对得上失锁前 FIFO 里的 5 个字」与日志矛盾（stale_words=0 钳位、重启边界后推入）；修法本身不受影响（I3 覆盖两子情形），但证据读数错。
- **F-3 M3**：G2(c) 点名仪器（rx_stat_*）全在 FE 侧统计口，对「DP 侧交付 tcrs=1 帧中片段」结构性失明；TB 无 vs_tuser/逐帧内容仪器 ⇒ G2 按现写判据抓不住差异，判别力全靠 G1+witness。
- **F-3 M2**：「事件脉冲清只出现在 OPEN_ITEMS」为假——台账 :302 同样带错，§6-(g) 订正计划漏它。
- **换流门 S-0 复算翻案**：conn0 `off=2920` 是抓包头部丢失伪影（syn=0+seq 连续性强制）⇒ 原报告 3/6 成立，设计件「实为 4/6」微勘误错误；§5.1 R=2920 残差上界失去实测依据，§1.6 算术不闭合（411106−26≠2）。库内无法终裁（S0A sink 未归档），补件路径见 BUNDLE_UPOK。
- **mdio M1**：结构论证覆盖范围被写大——`vio_phyad` 的 VIO-out→端口网段无测试无覆盖，bit0-stuck 故障与「广播应答」逐位不可分；阶段二报告应登记「VIO 网段未覆盖」。
- **mdio M2**：收尾「身份门」实为观察式（burn_arm.sh:85 只 echo 无 exit 1）⇒ 收尾恢复身份不符不会自动红，需轮内显式核 ID_RC=0/Width x4/0x04=0x24。
