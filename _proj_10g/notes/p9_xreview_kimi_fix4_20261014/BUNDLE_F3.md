## 结论摘要

设计件的机制主干经逐条现读核实成立：一手件方向归属正确（neg_ctrl 属实）、编辑锚点 100% 精确、
I1–I5 的默认关=逐位等价论证在常数折叠、X 传播、复位路径、综合语义四个方向上都推不出反例，
tcrs=1 路径与"失锁清整个 DP 状态含 TCB"的机制链均与 RTL 现读一致。发现的问题集中在**证据读数

症状结构性失明，该判据按现写抓不住缺陷；④ §1.1-7 把"窗口内持续弹字"标为无条件【事实】，与
P6B_SPEC 自己"dp_clk 会停"的模型冲突。以上均不伤及修法本身（I3 两种子情形都被覆盖），但
①③ 两条会被下游引用时放大，建议实施前订正。

## 发现清单

### 中

**M1. DESIGN §1.2 对 t9 变体 A 的读数与日志原件自相矛盾（"失锁前就在 FIFO 里的那 5 个字"不成立）**
- 设计件原文（DESIGN.md:111-113）："t9 的仿真模型里'内容保留'是成立的…t9 变体 A 交付的片段内容
  逐字对得上**失锁前就在 FIFO 里的那 5 个字**"。
- 现读 `agent_docs/audit_scratch/t9_f3restart/case_old/xsim_old.log:42-43`：
  `F3 STALE-CONSERV dw_all=69 pushes_after=70 => stale_words=0`（=钳位到 0，原式 = 69−70 = −1）；
  审计件自己（`P6B_CDC_AUDIT.md:185`）对变体 A 的注 =「0（**DP 跟得上 ⇒ 重启瞬间 FIFO 近空**）」。
  ⇒ 交付的 5 个字（源帧 3 偏移 24）属 `pushes_after=70`（重启边界**之后**推入），重启瞬间 FIFO
  "近空"；"帧 3 在失锁前开始收"≠"这 5 个字失锁前就在 FIFO 里"。
- 影响面：§1.2 的核心结论（两种子情形都产生帧中重启、I3 覆盖两者）**不受影响**；但该件位于
  "关键更正"节，且被 EVIDENCE §8 矛盾表第 3 行引用 ⇒ 下游照抄会把一个被原件否定的读数当证据。
- 建议：把该句改为"t9 模型 = 钟停摆子情形：窗口内排空停止，交付片段 = 窗口内推入的帧中字
  （非失锁前存底；源帧 ∈ 失锁前开始的帧）"。

**M2. §0.1"事件脉冲清这个词只出现在 P7B_OPEN_ITEMS.md"为假 ⇒ §6-(g) 订正范围不完整**
- 现读：`grep -rn "事件脉冲清" _proj_10g/notes/` 另命中 `P7B_TL_LEDGER_20261010.md:302`
  （§10-2 F-3 行：「小改（事件脉冲清）→ 缺陷批构建」）；另两处非 F-3 语境
  （`P7B_L_INSTRUMENT_DESIGN.md:479`、`P7B_WU_P1P2_SNAP.md:97`）可不算。
- 影响面：neg_ctrl 的**判定**不受影响（OPEN_ITEMS/B6 确为二手错概括），但"只出现在"是全称声称，
  且 §6-(g) 的订正动作只列 OPEN_ITEMS 两处 ⇒ 订正执行后门台账 §10-2 仍携带同一错误，
  而台账是 compact 后续接点，权威性高于 OPEN_ITEMS。
- 建议：§6-(g) 补第三处（台账 `:302`），或改为"按 §0.1 的措辞把三处一起订正"。

**M3. G2(c) 判据判别力缺口：点名仪器对缺陷症状结构性失明**
- 设计件 §3.2-G2(c) 点名仪器：`u_dut.rx_stat_frames / rx_stat_crc_err / rx_stat_drop_full|partial`。
  现读 `board/wrapper_p4.v:790-832`：这些线全部接在 **mac_rx（FE 侧）** 统计口上。
  缺陷症状 = "DP 侧交付一个 tuser=0 起、tlast+tcrs=1 收尾的帧中片段"：FE 侧 CRC 本来就是对的
  （tcrs=1 正是 mac_rx_64 在真帧尾算的，`:241/:276/:329`）⇒ `rx_stat_crc_err` 不增；片段不是
  MAC 丢帧 ⇒ `drop_full/partial` 不增；`rx_stat_frames` 数的是 FE 收帧，与 DP 侧交付形态无关。
- 现读 `_proj_10g/p7b_chain/sim/tb_p7b_chain.v`：`grep -n "vs_tuser|vs_tdata|rx_mon|FRAG|frag"` **0 命中**
  （仅 :44 一处注释提及 rx_stat_frames）⇒ 该 TB 没有 DP 侧逐帧内容/tuser 仪器。
- 结论：G2 按现写判据，"缺陷被修好"与"缺陷仍在"给出**同一份读数**——判别力实际来自
  (b) `stat_resync_words>0`（只证门运行过，不证无片段）与 (d) 既有判据（看不见本缺陷）。
  设计件自己把 G1 标为"主承重"是对的，但 G2(c) 的具体仪器清单给了下游"G2 能抓缺陷"的错误印象；
  §6-(f) 只登记了"判据落点需现读"，没有点名"已点名仪器看不见该缺陷"。
- 建议：G2 增加 DP 侧逐帧首字 tuser 见证（如事件后第一个 `vs_tvalid&&vs_tready` 拍采样
  `u_dut.vs_tuser`，必须 ==1；或对 `u_dut.vs_t*` 做逐帧记录按内容解码），否则把 G2 降级为
  "回归 + witness"门并明说它不判 F-3 本身。

**M4. §1.1-7"复位窗口内 DP 侧仍在持续弹字"标为无条件【事实】，与一手规格模型冲突**
- 设计件 §1.1-7（:100-101）："【事实】由 5+6：**复位窗口内 DP 侧仍在持续弹字**"。
- 前提 = "窗口内 dp_clk 仍在跳"。现读 `agent_docs/P6B_SPEC.md:774-775`（一手）对同一事件建模：
  「若 `locked` 抖动（100MHz 参考钟丢失），**dp_clk 会停 ⇒ DP 侧不推进** ⇒ FE 侧的 `full` 最终拉高
  ⇒ `u_mac_rx` 丢帧」⇒ 钟停子情形窗口内**不弹字**（FIFO 积满走背压丢帧）。
- 设计件 §1.2/I3 自己承认两子情形（"门只看释放后的字流"对两者都成立）⇒ 结论不受影响；
  但 §1.1-7 的【事实】标签越界，且与同件 §1.2 内部张力。这是"未观测/未证"处的如实性问题
  （真机失锁时 clk_dp 是停是抖，xsim 不可判，设计件 §0.4 对板级倒是如实写了"未观测到"）。
- 建议：改为"【事实】窗口内凡 dp_clk 仍在跳的区间持续弹字（s_axis_tready 不看 rst_n）；
  若失锁致 dp_clk 停摆则不弹字（SPEC :774 模型）——两子情形 I3 均覆盖"。

### 低

**L1. J2 的 tuser 腿可能被 TB 记录器簿记伪影架空**
- DESIGN §3.2-J2：「重启后交付的第一个帧是 `whole` 且 `tuser=1`（t9 已打印 `dtuser[]`）」。
