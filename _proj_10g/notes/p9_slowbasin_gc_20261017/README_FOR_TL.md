- 板：0x28（BID 0x28 / 75 字 / `0x15C`）· 收尾态 `0x28 + 0x08=0 + CARRIER=1` · 两机未关机

⛔ 本轮不出 PASS/FAIL 裁定；只报读数。用词纪律：**【已证】/【未判定】/【未定位】/【未测】**。

## 4. ⭐ 清除判定：重烧 = 清除【读数成立】；洪泛 ≠ 清除

- **G3（烧 0x28 → A′）**：**快**（853.4/842.3/959.6 Mbps）——与 G2（同一 A′ 构型、烧前 4.5 min）二值分明 ⇒ **重烧 = 清除事件（读数层）**。
  - 注意 G3 的对照强度：A′（rcvbuf 2920）**正是**会在盆内爬行的构型，所以"烧后 A′ 快"不是构型效应。
- **G4（洪泛后 → A′）**：**慢** ⇒ **洪泛不是清除事件（读数层）**。
- ⭐ 关键新读数（本轮把"洪泛"这个候选**从机制上拆掉**）：**洪泛本身在盆内就"免疫"**：
  - G4F 在**盆内**（前 26 s 的 probe 慢、后 2.6 s 的 probe 慢）跑了 6,747 连接全速（5.67 Gbps，逐连 2.0–6.8 Gbps，dup=0）；
  - G4C 进一步隔离变量：**只把 rcvbuf 换成 1 MB**（其余同 A′）⇒ 盆内 5.3/6.8/9.4 Gbps。
  - ⇒ **慢盆只惩罚小窗（rcvbuf 2920）连接；大窗连接在盆内走全速通路**。历史 P3A0（同洪泛构型、01:19 全速 36,809 连）也因此**不能**再算作"清除证据"——它只是同一种免疫。
  - 板侧环在此给出旁证差异：洪泛中 `W55≡0`（20 ms 重传钟不出现）、`W20=500,254 fps`、`W67/W66=0.94`（板帽侧窗口停）、`W69={62780,61440}`。**⛔ 但必须写清**：`W55` 是否只在"病态连接"上走表**未定位**，所以"洪泛时盆仍在场"的直接证据**只有**前后两侧 A′ 都慢（26 s / 2.6 s 的夹逼）+"杀/空转都不清"（G4b→G4w）。**【未判定】**：是否存在"洪泛瞬间清盆、2.6 s 内又进入"的绕法——按现有进入/清除知识（进入需真异槽并行、且洪泛是单 sink 顺序）判为**极不可能，但未证伪**。

4. **新增仪器**（不改变既有判据）：`ss -tinH` 逐秒内核态**每 socket 字节计数器**（`raw/basin_*_ss.log`；用于独立于 pcap 的爬速见证）+ nstat 扩列（PureAcks/HPAcks）+ `tools/shapes.py`（逐连接形态表）。
