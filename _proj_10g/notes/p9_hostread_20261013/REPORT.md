### A. 高项（逐条：原句 → 订正 → 证据）

**H-1｜§0「背景泛洪 全程 ~4.91 Gbps / ~404 kfps…只有 P9 轮的一半」→ 作废。**
- **订正**：环境常态 = **满速泛洪**，两轮背景**同档**，跨轮比较按同负载读。20 窗原始件逐窗复算 = **9.26–10.72 Gbps / 762.9–882.8 kfps**（跨窗空档 >1 s 者 9.55–10.62 Gbps / 786.0–874.5 kfps；唯一例外 `CAPD→A1N2` = 2.16 Gbps / 177.8 kfps，该跨度含 A1N 零交付窗，不是泛洪减速）。
- **证据**：① 订正轮自算（每窗 `NIC_PRE/POST` + `T0`/`=== END` 时间戳）；② 复核现测（REVIEW §6）= 9.82 Gbps / 808,791 fps；订正轮现测（对端只读，2026-10-13）= 9 个 ~9.76–9.81 Gbps 样本（1/2/3 s 窗）+ 细探针 4.8 s span 均值 10.23 Gbps / 842.5 kfps（NIC 口径）。
- ⭐ **成因形态已实测钉死（新观测）**：对端 NIC `port_rx_bytes/packets` 是 **~1 s 级 latch 统计** —— 0.05 s 采样下读数**冻结**、每跳恰 ≈**1.2277×10⁹ B = 808,790–808,791 pkt × 1518 B**（9 跳跳幅离散度 ≈0.002%），跳间隔 **0.94–1.04 s**（两轮细探针 40/90 采样共 9 跳）。⇒ **短窗速率只能落在「整数个量子 ÷ 窗长」的离散格点上**；订正轮 13 个短窗（10 个 ~2 s + 2 个 ~1 s + 1 个 ~3 s）实测复现 **4.90 Gbps（1 量子 @ 2 s）** ×2 与 **11.26 Gbps（≈2.3 量子；计数虚高 `+15%`，与 J0 旧案同族）** ×2。§0 的 `4.91 Gbps / 404 kfps` 与「**1 量子 @ 2 s**」（1.2277e9 B ÷ 2 s ×8 = 4.911 Gbps；808,790 pkt ÷ 2 s = 404.4 kfps）**逐字同形**。
- ⚠️ **判定**：原句是否为该相位样本、还是时间基/算术错，**无档（与低-7/低-8 同族）⇒ 不可判定**；可判定的是：**它不能当「全程」读数**，「P9 的一半」不能作测量条件。**顺带（对全轮 NIC 口径有效）**：每窗 NIC 速率都带端点量化 **±19.6/dt Gbps**（16.7 s 窗 ±1.2、6.7 s 窗 ±2.9）⇒ 逐窗散布大部分由此解释；结论方向不受影响（无一处接近 4.91 的持续值）。**"单次 2 s NIC 窗不是速率的连续测量"** 与本项目「计数器有刷新量子」的通用教训同族。

**H-8｜§3「环安全：每块 ≤4 MiB（≤1024 描述符）⇒ 两笔在飞 ≤2048 = 环全宽」→ 作废（机制误述，且该约束不必要）。**

- 残余（如实登记，**不设门**）：块序 = desc_lock 先到先得 +「另一线程已在锁上等」的结构性偏置（A 必须先返回、做 epilogue；δ 只是加保险、与块时**无耦合检查**）；**块交换对字节记账完全不可见**（`pc` = 流序前缀和）⇒ **只有开内容判据的窗能抓**。

### 2.4 C-C1c 驱动源码**只读**核查（原件 = `runs/driver_{cdev_sgdma,libxdma}.{c,h}`；对端现役驱动 = 该树构建）
1. **每次 read() = 一整张 SG 表 + 一串串行传输**：`char_sgdma_read_write` 先 `char_sgdma_map_user_buf_to_sgl`（`get_user_pages_fast` **按 4 KB 页** + `sg_set_page` **逐页一条**）→ `dma_map_sg` → 传输循环（每段 ≤ `engine->desc_max`；`enable_st_c2h_credit=0` ⇒ **desc_max=0x800=2048**，`/sys/module/xdma/parameters/` 实测）**每段"建表→排队→等完成"**（下一段的表在上一段完成后才建）→ 返回前 `char_sgdma_unmap_user_buf`（**逐页 `set_page_dirty_lock` + `put_page`**）。

## 3. 修复（**按主导成分**）

**诊断结论（数据 + 驱动源码双证）**：读循环总空档 = **固定 ~58 µs/read（等待/唤醒/段边界）** + **~34 µs/MiB（逐 4 KB 页 SG/映射/解映射/put_page；其中 ~3/4 为"页条目级"成本，大页只吃掉 1/4）**；两者都在 `read()` 调用内部；"每 MiB 项"在 **AIO 路径被搬进引擎 service 上下文、直接挡住引擎重启** ⇒ **AIO 只能去掉固定项**（实测 3.21%→**1.13%（AI4）/1.09%（AI2M）**，订正低-1；且不随块径变）。

**修复主臂 = `--dual 2`（两线程交错同步读；块径任意，见下环安全订正）**：奇偶分块 + 起步错拍 δ（默认 2 ms），使"上一条 read 的 epilogue"与"下一条 read 的传输"**重叠**（同步路径的 epilogue 在**用户线程**，不占引擎 service 上下文 ⇒ 重叠有效）。
- **环安全（⛔ 订正 H-8：机制已按驱动源码重导；该约束既不成立、也不必要）**：`xdma_xfer_submit` 在【建表→排队→**等完成**】全程持有 `engine->desc_lock`（`driver_libxdma.c`：:3553 lock → :3560 建表 → :3584 排队 → :3594-3600 等完成 → :3680 解锁；解锁只在错误分支 :3562/:3586/:3676 与 `while(nents)` 之后）⇒ **同一引擎上任一时刻至多一笔 transfer 在环**（第二线程连建表都要等锁）⇒ `--dual` **不可能**加宽在飞描述符，**与块径无关**；且单笔 transfer 本身被 `transfer_init` 双向钳在环宽内（:2967-2969 `min(剩余, desc_max=0x800=2048)` + :2998-2999 环边界钳）⇒ **环不可能溢出 ⇒ 不需要块径几何门**（工具对 `--dual` 无几何门 = **正确行为**）。⛔ 原句「每块 ≤ 4 MiB（≤1024 描述符）⇒ 两笔在飞 ≤ 2048 = 环全宽」**作废**（既与驱动事实不符、也不必要）。真实并发收益来自 desc_lock **之外**：prologue（GUP/SG/map，`cdev_sgdma.c:414` 在 submit 前）与 epilogue（逐页 unmap，:422 在 submit 返回后）与另一线程的传输重叠。**`--aio` 的闸（`depth×(chunk/4096) ≤ 1536`）理由不同**：`xdma_xfer_submit_nowait` **不持 desc_lock**（:3824 起）⇒ 多笔真同时在环 ⇒ 保留。
- **顺序（⛔ 订正 H-8 残余如实登记，不设门）**：单流按提交序落各块缓冲；提交序 = desc_lock 先到先得 + 「另一线程已在锁上等」的结构性偏置（A 必须先返回、做 epilogue；δ 只给起步保险、与块时**无耦合检查**）。⚠️ **块交换对字节记账完全不可见**（`pc` = 流序前缀和，与块序无关；式A/式B/dW70 全不变）⇒ **只有开内容判据（不用 `--no-verify`）的窗能抓** —— 原句「乱序会被内容判据抓住（可检测、不静默）」**只在 verify 打开时成立**（本轮 dual 主臂 A1/A4/A1N2/D1M/D4M 均为 `--no-verify` ⇒ 结构性无此判据；dual 窗里只有 CAPD/ORD1 满足 = 订正 H-7b）。
- **登记（本轮未做，留待裁定）**：① 驱动侧修法 = 把 `char_sgdma_unmap_user_buf`（或 `set_page_dirty_lock`）移出 `engine_service` 上下文（deferred work）⇒ 理论上再吃掉 ~34 µs/MiB；源码已在（`dma_ip_drivers-patched`），但**重编+重载内核模块超出"宿主读循环"范围且会动台架共享件**，故不动。② 板内缓冲（URAM）加大 2 KB FIFO 即可吸收块边界窗口；属 RTL/位流改动，本轮禁。
