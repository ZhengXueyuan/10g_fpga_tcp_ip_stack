### 1.2 「idle」的定义与「三点对账」（任务 2 的机理部分）

从 `analyze_readlog.py` + 工具源码钉死口径：
- `entry = (ddma×4 + dw70)/dt`（区间 = 相邻两条 READLOG 完成时刻之差，`dt = t_i − t_{i−1}`）；
- `idle = dw70/entry`（**丢字节反解**，不是直接测量）；
- 工具侧 `gap_us = t_pre(i) − tm1(i−1)`（上一条记录 MMIO 结束 → 本条 read 发起；**不含本行 MMIO**，含采样开销）——**与 §1 口径句逐字相符** ✓；`read_us = t_post − t_pre`；`mmio_us` = 本行现场读自身。

**三点对账的代数**：记每 read 交付 `Δdma×4 = chunk`（我在原始件里逐条核过：1 MiB 档 `ddma=262144`、32 MiB 档 `ddma=8388608`，**每条都成立**），则
`chunk/entry + idle = (chunk + dw70)/entry = dt`（entry 的定义式），而 `dt = gap + read + mmio`。
⇒ 「read_us 中位 ≈ chunk/入口率 + idle」**在结构上等价于**「read_us ≈ dt − (gap+mmio)」，即它主要是在复述 readlog 自身的记账（#76 型）。实测三点偏差 +5.3 / −5.2 / −134.6 µs，与 `gap+mmio ≈ 5.2 µs` 的符号/量级**并不严格吻合**（1 MiB 点 +5.3 ✓ 对得上；32 MiB 点反号；64 MiB 点 −134.6 µs = −0.075%）。
**独立含量 = 两条**：① 每 read `Δdma×4 == chunk`；② `gap_us` 中位 0.1–0.7 µs（宿主账面可忽略）⇒ 空档确实落在 `read()` 调用内部、而不是两次 read 之间——**这条结论成立**，但它的证据是 ②，不是「三点全中」。（报告自己引的 64 MiB 例：`176357+2256=178613 vs 178747`，**差值 134 µs 被写成「三点全中」**。）

### 2.1 `--dual` 环安全（任务 3a）—— 【高-8】

- **代码里没有强制**：`stream_args_check()`（:1338-1350）只查 `buf/chunk≠0`、`chunk%64`、`want%8`、`want≤buf`；`--aio` 的专属几何门（:1536-1561，`depth×(chunk/4096) ≤ 1536`，越轨 FATAL RC=2）**只管 aio**；**`--dual` 无门** ⇒ `--dual 2 --chunk 33554432` 会被静默接受（无告警、无 FAIL），而报告 §3 与代码注释（:1080-1081）把「每块 ≤ 4 MiB ⊆ 1024 描述符 ⇒ 两笔在飞 ≤ 2048 = 环全宽」写成安全论证。
- **该论证本身与驱动事实不符**：`driver_libxdma.c:3553` `mutex_lock(&engine->desc_lock)`，其解锁只出现在**错误分支**（:3562/:3586/:3676）与 `while(sg)` 循环之后（:3680）；等待完成（`xlx_wait_event_interruptible_timeout(xfer->wq,…)` :3588-3597）**在持锁期间**。⇒ 同一引擎上**任一时刻只有一笔 transfer 链在环**（第二线程连建表都要等），**环不可能被 --dual 冲爆**，与块大小无关。真实的并发收益来自 **desc_lock 之外**的部分：`char_sgdma_map_user_buf_to_sgl`（GUP/SG）与 `dma_map_sg` 在 `xdma_xfer_submit` **之前**，`char_sgdma_unmap_user_buf`（逐页 dirty+put）在 `xdma_xfer_submit` **返回之后**（cdev_sgdma.c:414-422）⇒ 「A 的 epilogue/prologue 与 B 的传输重叠」成立，**报告 §3 的定性机制对，环安全的定量理由错**。
- 附带：`--dual` 的起步 δ 默认 2 ms **固定**且与 chunk/入口率无关（`dual_stagger_ms`），代码里没有任何「δ < 块数据时间」的检查或告警。在 4 MiB 档（块时 ~11 ms @370 MB/s）裕量充足；但真正决定提交序的是 desc_lock 先到先得 + 「B 已在锁上等」这一结构性偏置（A 必须先返回、做 epilogue、再发起下一笔才可能竞争），δ 只是加保险。**块序被静默交换的风险存在但小**；交换对**字节记账完全不可见**（pc = 前缀合并与块序无关），**只有内容判据能抓**——见 高-7。
