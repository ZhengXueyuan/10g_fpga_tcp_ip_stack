## ② RTL 逐项发现（`rtl/axis_c2h_stream.v`；全部附行号 + 方法）

**方法**: 除读源码外，我另写了一份**循环级模型**（逐行转写组合/寄存器语义）跑 300 段随机激励
（en/cap_en/clr/tready/grant 随机、含 clr 与 grant 同拍、含长背压），逐字节重建交付流并与"取走流 − 残拍"对账；
再用**定向场景**复现停流/背压组合。以下凡"模型"字样均指此。

**① 打包与字节序（自洽性）** — 【事实】
- `mv_data = mv_full ? {s1_data, s0_data} : {64'd0, s0_data}`（`:125`）：第 2 个 grant 在高 64 位。
- 上游口径：`app_rx_mirror` 的 `dma_data = {dma_w1, dma_w0}`（`app_rx_mirror.v:407`，`dma_w0` = 先出）；
  镜像内部 `acc_r[7:0] = 本字首字节`（`:188`）⇒ 逻辑字内**首字节在低位**。
- 工具口径：`--stream` 的 `verify_buf()` 是**纯字节序**比较（`p7b_mir_dump.cpp` 的 `verify_buf`：`got[i] == pat.next()^xorc`）；
  环路径（mock/`ring_read`）按"物理字递增 + 每字 4 B 小端"取字节 ⇒ 三条口径**互相一致**：
  `tdata[7:0] = 流第 0 字节`、grant1 的 w0 在最低 32 位。
- ⛔ **唯一的未证环 = "XDMA 把 tdata 小端写宿主内存"**（PG195 不写字节序；`IMPL_REPORT §8.1` 已登记）
  ⇒ 我判定：**镜像/环/工具三处自洽成立；宿主端口径 = 假设，只能板级判**（判法见 ⑦）。
- 失配形态的**先验候选 ≥3 种**（⚠️ 对 `IMPL_REPORT §8.1` 的"失配形态 = 整拍内 8 B 交换"作**收窄**，不是否定）：
  设宿主按小端把 `tdata[8i+7:8i]` 写在 byte i（= 现行假设），则错写的候选有：
  (a) **8 B 半交换**（两个 64 位组对调：`[g2, g1]` 而非 `[g1, g2]`）；
  (b) **16 B 整拍反序**（`tdata[127:120]` → byte 0）；
  (c) **4 B 字内/字序反序**（`tdata[31:24]` → byte 0 或四个 32 位字倒序）。
  三种在"首字节失配 + mism≈100%"上不可区分，**只能看落盘文件前 16 B 与图案的关系**（判法见 ⑦）。
  ⭐ "三条口径自洽"的经验底座：**环路径（P8/0x20/0x21 轮的 `--dma`）板级 `first_mismatch=-1` 已把
  "镜像字节序 == 图案字节序"钉死**；本刀新增的只有"打包成 128 位拍 + XDMA 落内存"这一段。

**② tkeep 规则** — 【事实】"只有最后一拍可以短"**结构性成立**：
- 短拍（`00FF`）只在 `mv_go = b_free && (mv_full || (stg_half && stop))` 且 `stg_half` 时成形（`:124,126`），
  而该路径 `mv_last = mv_full ? stop : 1'b1 = 1`（`:130`）⇒ **短 ⟹ last**。
- 整拍 keep 恒 `FFFF`（`:126`）。寄存器化（`:142-150`）⇒ `tvalid&&!tready` 期间 data/keep/last **不变**
  （模型 300 跑 0 次违例；单元门 G3e/G10a 亦断言）。
- **背压/多拍连发下不会出现"中间短拍"**：短拍需要 `stg_half && stop`，`stop` 不参与"正常流"。

**③ 停流 flush 触发式** — 【事实 + 两个未登记边界】
- `stop`（`:116`）电平/脉冲"或"，`clr` 与 `cap_en` 同拍时 `stop=1`（无优先级问题，三者同权）✓。
- **不会重复发**：`mv_go` 每次清两槽（`:159-161`），数据进 `b` 后只能经握手出（`:147-149`）；
  模型 300 跑**零重字/零丢字**（重建流 == 取走流的**前缀**，逐字节相等）。
- ⚠️ **边界 A（未登记）：flush 会被背压推迟，且 stop 若先撤销则该次 flush 永久不发生**。
  路径：`stg_half && stop && !b_free` ⇒ `mv_go=0`（残拍滞留）；此后 stop 回到 0 ⇒ 该半拍**不再**作为短末拍，
  而是等下一个 grant 补成整拍（`last=0`）送出。模型实测：300 段随机激励里此形态触发 **52 次**。
  影响：**不丢数据**，但"停流 ⟹ 关闭描述符"的语义在"停流窗口 < 背压窗口"时不成立。
  登记的依据：头注释 `:38` 只写"电平语义 ⇒ 先停后到的残拍也会立刻成形 (不会漏)"——**"立刻"有 `b_free` 前提**。

**④ 计数点与"内部不丢"的等价性** — 【事实 + 一个真孔】
- `dma_words`：`clr` 优先于 `gnt_go`（`:171-175`）⇒ **`clr` 同拍取走的 grant 不计**（每次 `clr` ≤2 字）。
  该孔在真 wrapper 里**可达**：镜像侧 `flush_r` 是**寄存器**（`app_rx_mirror.v:386-391`），
  `dma_gnt_i` 排除的 `flush_r` 在 `clr` 脉冲那一拍**仍为 0**（`app_rx_mirror.v:412`）
  ⇒ `clr` 拍可成交一次 grant。模型实测：300 段随机激励里 `clr` 与 grant 同拍 **223 次**。
- **取走但最终不交付**的路径（逐条找过）：
  ① `!rst_n`（`:143-156`）：槽/`b` 清空 + 计数归零（同时发生，账自洽）；
  ② `clr`：**不清**槽/`b`（`:153` 注释明写）⇒ 残拍照常送出、但计数已归零 ⇒
     宿主 post-clr 窗口头部最多 **32 B**（`b` 16 + 两槽 16）**pre-clr 字节** + 上述 **≤8 B 未计数** = **≤40 B**
     ⚠️ `IMPL_REPORT §8.4` 与头注释 `:44` 都写"≤16 B"（只数了那一拍短末拍）——**账目口径的界被低估**（登记）。
  ③ 计数器 32 位自然回绕 ⇒ 工具侧已按段 mod 2³² 处理 ✓（`dds` 侧 `dword_max_step` 见证）。
- ⇒ **结论**：设计口径"取走的字数 = 最终会交付的字数"在**稳态**成立（模型：交付字节 == 取走字节 − 残拍字节，逐字节相等），
  但在 `clr` 边界与 `reset` 边界有**明确定义过的**偏差；**"计数点 = aux"不等于"计数不含丢字节"**（见 ⑥-D1）。

**⑤ 背压与 `tready` 抖动** — 【事实】`tready` 长期低：`b` 被顶住 ⇒ `b_free=0` ⇒ `mv_go=0` ⇒ 两槽满 ⇒
`dma_req=0`（`:135`）⇒ 镜像 FIFO 涨满 ⇒ `W70` 记账（因果链与 `IMPL_REPORT §3` 一致）。
**拍级抖动**：无丢字/重字（每拍握手独立、槽清空只由 `mv_go` 发生）——【判断】依据 = 模型随机 tready（0.6 概率）+ 逐字节重建 0 违例；
⚠️ 但**门里没测过拍级抖动**（见 ⑤-未覆盖）。

**⑥ H2C 恒吞噬 + "永不 tlast" 的长期影响** — 【事实 + 引 PG195】
- H2C：`mir_h2c_tready = 1'b1`（真支 `:3873`）；`tvalid/tdata/tkeep/tlast` 接**显式声明**的悬空线（`:3760-3764`）
  ⇒ 无隐式网；数据被静默丢弃（沿用 P2 代价，已登记）。
- C2H "永不 tlast"：PG195 v4.1 **p.26-27** 逐字支撑**描述符可被"填满"关闭**（"When a descriptor is filled
  completely **or** closed due to an end of packet …"）⇒ 引擎语义上**合规**；PG195 **没有任何**"必须周期性 tlast"
  或看门狗条款（我把 pp.26-28 全文提出来核过）——但**文档同样不保证**长期无 EOP 行为 ⇒
  【无法判定】，与 `CONF §4.4/§7-④` 一致，**未因本轮实现而变化**。
- ⚠️ 与"永不 tlast"配套的**尾描述符问题**：若最后一拍未满描述符且不再来 EOP ⇒ 该描述符**永不回写**
  （`IMPL_REPORT §8.3` 已登记"只能等驱动超时"）；工具按"收满 count"完成 ⇒ 不依赖 EOP ✓。

## ⑥ 新发现问题（按严重度）

### D1【高 · 工具侧（`dd6fe3d`）· 跨件】工具闭合式与 FPGA 计数点**不同义** ⇒ 有丢字节的跑必假红

**事实链**（全部可回核）：
1. FPGA 计数点 = **aux 口取走**（`dma_gnt`，每 grant +2）——`rtl/axis_c2h_stream.v:169-175`。
2. **取走量不含丢字节**：P9-B-3 日志数字精确给出 `K(2880 B) − ΔW70(696 B) = 取走(2184 B)`
   （①#19 我的独立复算；`drop_now` 在报文进暂存前拒收，`app_rx_mirror.v:203-204,343-352`）。
3. 工具闭合式 = `交付字节(=ΔMIR_DMA_CNT×4) == pc + ΔW70 + 残余`，`残余∈[0,24]` 才 `closed=1`
   （`p7b_mir_dump.cpp` 的 `closure_eval` + `:1267-1292` 的 rc 逻辑：**不闭合 ⇒ FAIL + rc=1**）。
4. 工具的"板侧模型"把它自己钉死成**另一种语义**：mock 里逐字写
   "**源交付量 = 可见字节 + 丢字节 + 残余**"（`:494`，T9/T10 按 `delivered == K+D+R` 断言）
   ⇒ **自检结构上不可能暴露本不一致**。

**推导**：设 offered=K、丢弃=D、镜像侧残余=Rm（`acc+stg`）、成形器残余=Rp（槽+b ≤32 B）：
`取走 = K − D − Rm`；`pc = 取走 − Rp` ⇒ **`resid_implied = 取走 − pc − D = Rp − D`**。
⇒ `D > Rp`（只要有 ≥1 个 8 B 丢拍且成形器不全满）时 **`resid_implied < 0` ⇒ 判红**。
**逐位例（用门自己的数）**：`2184 − 2176 − 696 = −688`（B）。
**后果**：板级 `--stream` 只要出现丢字节（工具自己就说"每块之间采样 = 自造空档"，且无缓冲吸收），
就会打出 `闭合式不成立 … 可能 = 位流口径不同代 / 有未记账的丢字节` 并 rc=1 —— **诊断方向被带偏**；
⚠️ **订正（我自查）**：`MIR_STREAM_GAP … host_miss_bytes`（= `delivered − pc`）**不**因该口径而失效——
在 aux 口径下它 = 成形器残余 + AXIS/引擎在飞 + **已写进宿主内存但宿主还没 read() 的字节**，
即**恰好是"宿主跟不上的滞后"本身**（且不含 drop）⇒ 数值仍有意义；
**错的是它的注释口径**（工具 `:1266-1268` 写"与 dW70+残余 的差 = 在飞/未取走"，那是 offered 模型的话）。
⇒ D1 的实际受害面 = **闭合式判红**（唯一硬门）+ **一处注释**；`host_miss` 行可留着。
**正确式（两种等价写法，二选一）**：① `pc + Rp == ΔMIR_DMA_CNT×4`（残余带 [0,32]，ΔW70 单独成行）；
② `pc + ΔW70 + (Rm + Rp) == K`——但 **K 不可读** ⇒ 只有 ① 可直接用。
**登记口径**：这是**工具侧**缺陷（FPGA 侧实现与 TL 裁定一致）；我**不裁定**改哪边，只登记"两边必须统一"。
（注：`IMPL_REPORT §3` 的账目式用的是 `pc + ΔW70 + 残余 == K`（K = offered）——**FPGA 侧文本是对的**，
错的是工具把 `ΔMIR_DMA_CNT×4` 当成了 K。）

- 模型实测（②-⑥ 未覆盖 4）：`cap_en=0`、`en=1`、上游仍有数据 ⇒ **每个 grant 各自成一拍（`00FF`+`tlast=1`）**；

- 头注释 `:26-29` 写"唯一出 tlast 的时机 = **停流时把暂存残拍成形那一拍**" ——与实现（**停流期间每一拍**都打）
  **不完全一致**（`:127-130` 的注释其实写对了，两处注释互相打架）。
- 影响面：不丢数据；但**引擎/驱动的极小 EOP 包行为未证**（⑤-B12）⇒ 板级若在停流期观察回写/完成计数，需留意。
- 可修口径（二选一，均廉价）：① 把 `dma_req` 也纳入 `stop` 门（`dma_req = en && !stop && 容量`）⇒
  停流期不再取数、只送一次残拍（**这会改变"停流期继续排空"的语义**，须 TL 定）；
  ② 保持实现、把注释/口径改成"停流期每个取走单位各自收尾"。**我不代裁**。

### D5【低 · 覆盖】门/工具的"残余带"与本实现的上界**不齐**

- 成形器在飞 ≤ **32 B**（`b` 16 + 两槽 16），而工具的 `--resid-max` 默认 **24**（= 镜像 `acc+stg`）。
- 若跑结束时下游刚好停收（`tready` 低）且 `b` 满 + 两槽满 ⇒ `resid_implied` 可达 32 > 24 ⇒ **假红**；
  且工具注释"打包器残留**由 FPGA 侧停流 flush 清掉**"**只有在流程真写了停流时才成立**——
  现 `run_stream` 的 arm 序列（clr → cap_en）**结束时不停流**（只有起测写的 `0x2/0x9`；见 `p7b_mir_dump.cpp:569-577`）
  ⇒ 该前提在"正常收工"路径上**没有见证**（`level==0` 只证镜像 FIFO 空，**不证成形器空**）。

### D6【低 · 口径】`clr` 边界的字节账界被低估

- `IMPL_REPORT §8.4` 与头注释 `:44` 写"`clr` 之前的字节 **≤16 B**"；
  实际 = 成形器残余（**≤32 B**）+ `clr` 同拍未计数取走（**≤8 B**）= **≤40 B**（②-③/②-④ 模型实证）。
- 只影响 "mid-capture clr" 这类已声明为非常规的用法；**登记口径即可**。

### D7【低 · 证据口径】单元门 `G8a` 阈值带过宽（标签 1/2 拍·钟，断言 96/300）——见 ④-4.1。

## ⑦ 保留意见：要裁定"AXIS 在板上成立"，还缺什么

**⛔ 我这一轮没有、也不该有板级读数**（构建 `0x22` 仍在飞）。以下按"证据缺口 → 具体怎么补"列。

1. **（前置，最贵）先把 D1 的闭合式统一掉**——否则板级 `--stream` 的 rc/判据语义本身是错的：
   有丢字节的跑会假红（`host_miss` 行仍可用，只是注释口径要跟）。最小改法 = 工具一行公式 + 残余带改 32（或显式加 `Rp` 项）+
   `axi_regs.v:91` 一行注释；**改完先在 mock 上补一条"aux 口径"的 T 用例**（现 mock 的板侧模型必须一起改，
   否则自检继续掩盖）。**这一步不做，"板级逐字节对账"的读数会被污染在归因层。**
2. **CONF §7 的四条板级前置**（原样适用）：`identifier bit15`（`0x1000` 处应 `0x1FC0_8006` 形态，对照臂 = `0x21` 位流 bit15=0）、
   驱动 `dmesg` 出现 **`0-C2H0-ST`**、`alignments`（`0x104C`）读值决定"16 B 对齐是否消失"、
   `lspci LnkSta x4` + 2 个 Region（必要时设备级 `remove`+`rescan`）。
3. **字节序的三选一判别协议**（D-前身：`§8.1` 假设）：
   - 用已知图案跑 `--stream`（`K % 8 == 0`），落盘 `out` 文件；
   - 取 `out[0:16]` 与"期望图案前 16 B"和它的三个候选变换对照：
     (a) **8 B 半交换**（期望的 `[g1,g2]` 变 `[g2,g1]`）、(b) **16 B 全反序**、(c) **4 B 字内/字序反序**——
     三者互不等价，一眼可分（**别只按"8 B 交换"写先验**，见 ②-①）；
   - 判据用**三腿**：`first_mismatch`（形态）+ `ΔW70`（丢字节）+ 修正后的闭合式（账）；
     **只有三腿同时给出"整段一致的确定性变换"才判"就是字节序假设"，否则先按内容缺陷查**（全局 #93/#94 同族）。
4. **两条我发现的未覆盖路径要专门在板上取一次读数**（否则"未观测到"会长期混在"不存在"里）：
   - **D4 的停流喷发**：在 `cap_en=0` 且 FIFO 非空时示波器式观察完成/回写节奏（或对端 `dmesg`/`pcap` 看描述符节奏）；
   - **D5/D1 的"有丢字节跑"**：故意让宿主慢一拍（加长采样或人为停顿），验证"丢字节被正确记账且账仍闭"——
     这同时是 D1 修好后的**正控**。
5. **`pcie_axi_aresetn` 单独断言**（②-续）：板级不容易造，但至少在`0x22`构建的**时序/CDC 登记表**里补一行
   （它现在是"同钟不同复位源"，成形器在飞 ≤32 B 会丢、计数归零 ⇒ 见证断代）。
6. **两条"必须先有 EDA 面证据"的**（我未跑 EDA）：① 构建脚本 XDMA 断言段在**真构建**里的首跑
   （`0x22` 正在跑——**读数应以构建轮的归档为准，不要从我这份审查里推断**）；② D3 的 HEAD 臂重跑。

**我给本轮实现的总评（不代裁）**：FPGA 侧 RTL 的**数据通路**在我能做的全部检查下是干净的
（逐拍合同、字节流守恒、容量/背压、计数语义），门与突变臂的口径基本扎实（除 ④-4.1 阈值带与 ④-4.2 三类未排练）；
**风险不在 RTL，而在"读数面"**：D1（工具闭合式）会在板级第一跑就把"账"打成假红，D2/D3/D5/D6 是同族的口径/证据缝。
**这些必须在板级判据落地前收口，否则板级读数会被"诊断工具自身的口径"污染在归因层。**
