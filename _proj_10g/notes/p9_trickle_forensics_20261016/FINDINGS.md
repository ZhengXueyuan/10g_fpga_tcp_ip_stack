## 1. 覆盖限制（下文的【推断】皆由此来）

1. **full pcap 只含板→对端单方向**（`tcpdump … "tcp port 8080 and src host 192.168.100.2"`）⇒ **对端的 ACK/窗口字段全轮未被抓**（B4P_S2 的 pcap 抽查同样 0 个 P2B 包）。
2. ctl pcap 只含 FIN/RST（双向）。
3. 两条涓流的 FIN 段不可见：H3 臂抓包早停 ~5.5 s；N4H3 臂 FIN 于停抓瞬间**被计到未落盘**（ctl `.err` = `93 received / 90 captured`，差的 3 个 = 涓流 FIN 首 3 次发送）。nstat 只采 6 个计数器（无 H3 臂 post）。板 ISN 恒 `0x12345678`。

## 2. Q1 完整时间线

**2.1 先解决"这是谁的涓流"**：两臂各 2 只 sink 并行、每只 6 条**顺序**连接，但**板同一时刻只喂一条连接**——数据流像接力棒传递（`timeline_*_final.txt`）：

```
B4H3:  33444  SYN-ACK 0.277  数据[0.277,3.668] → 33456(0.679,0字节,从未被喂)
       →33464[3.682,6.669]→33478[6.671,9.658]→58278[9.671,12.659]→58294[12.661,15.653]
       →58298[15.663,18.638]→35050[18.656,21.630]→35064[21.641,24.622]→35080[24.633,27.606]
       →35096[27.624,30.599]→★55352[30.609,433.142*] （*抓包截止；sink 实际到 438.4 s）
N4H3:  59720→59732(0B)→59744→59748→49746→49756→49762(0B)→34758→34760→34770→★34778[27.613,456.140]
B4H2:  44854→44862(0B)→55248→40654→…→50212→★45956[150.555,353.950]（pilot，节奏 15 s）
```
每条连接的数据窗 = **[自己的 SYN-ACK，下一条连接的 SYN-ACK)**（例：33444 止 3.668 / 33464 起 3.682）。⇒ **涓流 = 接力棒传到最后、再无人来抢的那一条**，它不是"另一类连接"。

**2.2 涓流连接的段级时间线（B4H3-55352）**：
```
t=0.000000 SYN-ACK seq=0x12345678 win=49152（TCP options 只有 MSS=1460，无 WS、无 SACK）
t=0.000035 三个 1460B 新段连发（off 0/1460/2920，35 µs 内）
t=0.020123 burst#2 [2920(重放),4380(新)]；t=0.040182 burst#3 [4380(重放),5840,7300] …
每 20.05 ms 一轮，整整 402.5 s 同一个模子；t=402.532934 最后一个捕获段（★抓包截止）
```
**"崩溃点前 N 秒"的答案**：无崩溃点、无前兆——逐秒段数从第 0 秒即 130–137/s；隙分布 = `~0µs` 18,468 / `<100µs` 14,379 / `0.1–1ms` 938 / **`15–25ms` 20,021** / **1 ms–15 ms 之间 0 个**；板侧全轮**没发过任何一个纯 ACK**（flag 普查 B4H3=`{0x12:12,0x18:57,845}`，N4H3=`{0x12:11,0x18:88,909}`），无 dup-ACK 风暴、无可观测窗口塌陷。

**2.3 真正的崩溃点（与涓流同族的另两条，抓到了）**：N4H3-59720 以 856→791 Mbps 连续流跑 0.402 s 后、在**自身 t=0.4018**（run 时刻 0.670）出现第一个 20 ms 死寂、随后跌入爬行（崩溃前 10 ms 是全流最密的 701 段，**无前兆**）；B4H2-44854 同形（673→707 Mbps，崩溃于自身 t=0.4043 = run 0.504）。**两者都与"第二条连接建立"毫秒级重合**（§5-F2）。

## 3. Q2 "~1 Mbps + 37% 重复"的物理构成

**簇结构**：53,807 段 / 20,022 簇；周期 **min 20.017 / med 20.052 / mean 20.057 / max 23.491 ms**；每簇 = **[1 重放] + [1.687 新段]**（大小 3 段 13,000 次 / 2 段 6,811 次 / 5 段 203 / 7 段 2 / 9 段 2 / 13,15,21,89 各 1）。**逐分钟恒定到吓人：连续 6 分钟每分钟恰 2,984 簇**（=49.7/s）、~5,000 新段、2,984 重复段 ⇒ 无漂移、无自愈。

**① 在飞窗口**：板通告 win 字段——**55352 全 53,807 个数据段 win=0**（唯 SYN-ACK=49152）；而对端 34778 **全程 49152**、33444 是 0/49152 混用（54×0/397×49152）⇒ 该字段是**板侧 per-connection 状态探针**（收方向；对端不发数据故对流量无影响）。**对端 win 字段全轮未抓** ⇒ 由几何反推 **≈1460–2920 B（1–2 MSS）**：旁证 = 各 FIN 的 win（有数据 1460 / 0 字节 2920）、rcvbuf=2920 见证行、簇内结构。**在飞量（反推）**：每个 RTO 前恰 **1 段未确认**（20,021/20,021 簇 rewind=0），每簇结束后 2–3 段（2,920–4,380 B）。BDP 对账：1460 B 窗 / RTT 20–100 µs 理论 15–70 MB/s，**实测 0.12 MB/s 低 2–3 个量级 ⇒ 不是窗口/BDP 限速，是定时器锁步**。

**② 重复段性质**：**逐字节相同的真重传**。55352：20,021 重复、**内容冲突 0**；34778：22,719 重复、"冲突" **22** = 恰为那 22 个 1 B persist 探询。每簇恰 **1 个**重复（dup 总数 = 簇数−1），无第二种重复来源。

**③ 对端重传节奏**：**对端根本不重传数据**（它一个数据段都不发）。重传全来自板，节奏 = **板自身 RTO 定频**：实测周期 20.05–20.09 ms vs `rtl/tcp_tx_frame.v:220` `RTO_LIM = 12207`（r5 注释逐字"≈20ms @156.25MHz"；12207×256/156.25e6 = 20.000 ms 标称；偏移 +0.25~0.45% 未定位、不影响识别）。非 fast-retrans。对端唯一重传 = FIN 的 RTO 退避（§4）。

**④ 板的 ACK 行为**：**从不发纯 ACK、从不 ACK FIN**；数据段 ack 字段恒 = 对端 ISN+1。零窗/重复 ACK 不存在。唯一探询证据 = 34778 的 **22 个 1 B 段**（t=322.6–375.5 s，第 5–6 分钟）：seq=snd_una、payload 1 B ⇒ 形态 = **PERSIST 零窗探询**（0x1D 刀；武装条件 `snd_wnd==0 && snd_nxt!=snd_una`）⇒ **该连接在那 ~53 s 里进过 win=0 时段且探询确实发了**。探询间距（成对 0.2–0.6 s、对间数秒）与设计退避阶梯不能逐档对上——机理未定位，如实登记。

**⑤ 折算对账**：吞吐 = 新段×1460/时长 = **122,530 B/s = 0.980 Mbps**（sink 独立口径 0.980 ✓）；34778 = 116.7 KB/s = 0.933 Mbps（sink 0.933 ✓）。重复占比按段 = 37.2%、按字节 = 29.2/78.6 MB = 37.2%。**"~1 Mbps" = 1.687 新段×1460 B ÷ 20.05 ms ⇒ 由 RTO 定频 × 每 RTO 放行窗口额度两个因子构成，与 RTT 无关。**

## 4. Q3 FIN 段

**谁先发 FIN**：对端（sink `close()`）。板侧全轮 FIN=0。

(a) **非涓流连接（有完整 ctl）**：FIN+ACK 1 首发+8 重传（RTO 退避，见 §0-4），**每个 FIN 之后板侧 0 个包**（100+ 个 FIN 逐包核过三臂）⇒ **"FIN 重传未被 ACK"逐包成立**。**板的最后一条与该连接的包** = 最后一个数据段，时刻**恰在 FIN 前 3.002–3.004 s（H2 臂 15.01 s）**= sink poll 超时预算 ⇒ 顺序 = 被抢流→静默 3 s（sink 轮询）→close→FIN→板继续静默。FIN 的 win=1460（有数据）/2920（0 字节）；FIN 的 ack = ISN+1+已收字节（与 sink 自报 `got` 逐位一致，如 59720 ackoff=41,734,100）。

(b) **两条涓流连接：FIN 段未被捕获**——55352：两抓包都在 +433.1 s 停、sink close 在 +438.5 s；34778：sink 于 +456.26 s close，FIN 首 3 次发送**到了过滤器但未落盘**（`93/90`）；板对它的响应**未观测到**（板侧最后一包 = 456.140 数据段）。

**对 B4「FIN 未 ACK ⇒ 板已移除」推断的裁决**："板不 ACK FIN"=**已证**；"连接已被移除（TCB 删了）"=**未判定**（观测面只有"不 ACK + 前 3.00 s 静默"）；且 3.00 s 与 sink 自己的轮询预算严格相等 ⇒ 静默的**起因**是抢流而非 FIN。**建议口径：「FIN 无响应已证；'已移除'未证」。**

## 5. Q4 与"停滞域"的关系（本件最大改写点）

- **F1（已证）**：同臂"其他连接"不是正常连接——B4H3 **11/11 条**有数据的连接全是同一模子（133–136 段/s、36.6–37.3% dup、20.1 ms 簇）；N4H3 8/9、B4H2 10/11 同形。**"STALL"与"OK"只是谁被抢流、谁留到最后，不是健康与生病之差。**
- **F2（已证）**：抢流事件 = **下一条连接被建立的那一刻（毫秒级）**：59720 崩溃 run 0.6698 vs 59732 SYN-ACK 0.670（Δ0.2 ms）；44854 崩溃 0.5043 vs 44862 SYN-ACK 0.504（Δ0.3 ms）；各连接数据窗严丝合缝（上表）。
- **F3（已证）**：E12 事件与连接一一对应、紧随其 SYN-ACK +0.005~0.19 s（H3 12 事件/12 连接；ΔW71..74=+12/+10/+11/+1）。**第 2 条连接的事件 = ev+up_pend（无 sw_req、永不应用，up_pend 自此恒 2）；自第 3 条起 = ev+sw_req+apply（10 次换流）**。H3 臂 PRE 的 `up_pend=1`（H2 臂遗留）与"33444 出生即爬行"吻合（N4H3 是**新烧**的板，其首条 59720 就跑了快流）。
- **F4**：B4 §6-2 形态描述核实无误，但它描述的是**被抢流连接**的收尾；涓流连接恰是**唯一没经历抢流**的那条。
- **F5（新）**：涓流 = **"抢流接力棒传到最后"**（解释为什么它长跑）+ **"被喂连接全程 RTO 锁步爬行"**（解释为什么只有 ~1 Mbps）两件事的合成。

## 6. Q5 机理候选排位

标尺两条硬事实：**F-A**：同样对端、同样 rcvbuf=2920，健康臂稳定 890–930 Mbps（B4P_S2：6/6 连续流、隙全<100 µs、**整连接恰好 1 个重复段**、无 20 ms 簇）⇒ 爬行不是对端物理做不到。**F-B**：新连接一建立，在役连接毫秒级从满速跌入锁步，且**永不恢复**（55352 独占 370 s 仍 133 段/s）。

**候选 1【首选】"新连接建立 ⇒ 在役连接 TX 崩塌并锁进 RTO 步进"**（触发面已证；锁的物理位置部分推断）
- 支持：§5-F2/F3；微时序 = 重放→新段间隔 **0–5 µs（40%）或 31–100 µs（60%，一个 RTT 量级）**、**1 ms–15 ms 之间 0 个** ⇒ 新数据是在重放这一拍被判放行，不是随机到货；22 个 persist 探询证明板的 snd_wnd 确实会走 0。
- 物理像（推断）：对端(Linux, rcvbuf 2920) win≈1–2 MSS；板门 `wnd_open=(snd_nxt−snd_una)<min(snd_wnd,WIN_CAP)`（`rtl/tcb.v:152-158`）⇒ **恰在 (in-flight=1460, win=1460) 边界时门关**；对端推迟孤段 ACK（delayed-ACK ≥40 ms > 板 RTO 20 ms）⇒ **只有 RTO 重放（=重复段）能挤出那条 ACK** ⇒ snd_una 前进一格→门开→放行 1–2 段→又贴回边界 ⇒ 自锁。与"1 重放+1.687 新段/20.05 ms、每分钟 2,984 簇"完全一致。
- 反证/未闭环：快流为何能从同样窗口流出（B4P_S2）——该像要求"成对到达⇒立即 ACK"，自洽但**无独立见证**；76.7 s 处曾出现 **89 段（88 新）连发（20.9 ms、4.3 µs/段≈2.7 Gbps 瞬时）** ⇒ 锁可被瞬时打开又自行锁回（与"网络侧自持锁"相容）。
- 缺的见证：**对端 ACK 流（P2B 双向抓包）**＝唯一能钉死 delayed-ACK+窗口半边者；**板侧现成仪器 W66/W67/W68/W69**（0x28 窗口里就有）。

**候选 2 "app/槽位侧限流"**（切换机构把被喂连接压到 ~1.7 段/RTO）
- 支持：app 一次只喂一条连接；每次新连接伴随 sw_req/sw_apply；W51 增速=线速。
- 反证：微时序与 RTT 聚类不像"数据随机晚到"（若每 20 ms 随机产 1–2 段，应散布 0–20 ms，实测 1–15 ms 区间 **0 个**）；89 段连发证明 app 同一 RTO 窗内能产 88 段；长跑轮已证 app 可 9.1 Gbps。**W51/W52 是"按需产字"契约下的恒等式、信息量为零**。
- 缺的见证：app 侧环占用/等 tready 拍数（需**新建**一个字，吃 WNS 余量 1.02%）。

**候选 3 "板内 ACK 处理停滞"**：反证 = 每次重放确只重放 1 段 ⇒ snd_una 一直被正常推进；**无证据支持**，排最后。

**分级**：已证 = 爬行现象学全套 + 触发面 + FIN 无响应；未判定 = 锁的物理位置（板内 vs 对端 ACK 节奏）；未定位 = "第二条连接为何能改变第一条的 TX"、20.05 vs 20.00 ms、persist 间距、55352 全程 win=0 vs 34778 全程 49152。

## 7. Q6 下一步取证方案（零构建即可开局）

**实验 A（最高优先，零构建）**：重跑 B4H3 同构型（`nsinks=2 stagger=0.4 rcvbuf=2920 conns=6 secs=300 maxbytes=50000000` + `--poll-ms 1000 --stall-n 3`），两处改动：① 抓包**去掉 `src host`** ⇒ `tcpdump -i enp1s0f1np1 -s 0 -B 262144 -C 300 -W 8 -w /tmp/k0_XX_full.pcap "tcp port 8080"`（双向；量约 ×2 ≈180k 包/臂）；② 快照环 KW 改 `'66 67 68 69 20 43 51 52 55 57 58 5'`。**事前判据**：对端 ACK 在爬行期是否 ≈1 条/簇、紧跟在重放后、win∈{0,1460,2920}（候选 1 预测）；`ΔW68` ≈ **49.7/s**（候选 1）vs 数千/s（⇒ 候选 3 翻案）；`ΔW66` 占空≈100% 且 `ΔW66−ΔW67` 大头落**对端侧**（若落板帽侧则产品级意义不同）；`W69` = 等窗那一刻的 {win_inflight, win_wnd_eff} 原始二元组。**对照臂（同会话）**：① 单 sink 同构型（复现快流）；② 双 sink 但第二条连上 1 s 内主动 RST——判"抢流触发"是否要求新连接存活。

**实验 B（可选，需一次构建收口）**：把 app 侧 per-connection 环占用/等 tready 拍数接入快照（现无此仪器；W66 是帧器侧、不含 app 侧）。
