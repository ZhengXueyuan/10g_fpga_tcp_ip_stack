**本轮对派单描述的三条订正/追加（不是迁就，是现读结论）**：

1. **"小窗惩罚/大窗免疫"的物理量不是 rcvbuf，而是对端的有效通告窗。** 逐包：rcvbuf=2920 时对端通告窗 = **{0, 1460}**（90 s 内只出现 1 次 2920）；rcvbuf=1 MB 时 = **65535**。⇒ 实验设计必须以"对端通告窗（MSS 数）"为轴，rcvbuf 只是旋钮（§4-B3）。
2. **慢盆稳态的"重放"不是"对端 delayed-ACK 扣住一段"，而是"对端丢弃越窗段 + 板侧 RTO 全窗重放"。** 依据：慢盆里 37.4% 的数据段"覆盖 ACK 只在同 seq 重放之后才出现"（中位 20.1 ms）；健康臂 0/2997（§1.1）。
3. **`W63/W64` 的 PRE/POST 差值在长臂里 wrap-歧义**（W5 在 240 s 臂内回卷 8 次；W63 真值 ∈ {8.4%, 19.8%} 两解）。⇒ 下一次的**环 KW 必须包含 63/64/65**（工具支持 `KW=` 覆盖：`tools/arm_basin.sh:55`），不要再用 PRE/POST 读这两个字（§3.1）。

- ① **健康态是"1 段/ACK"节奏**：对端通告窗恒 1460（1 MSS），板每次窗开只放 1 段、从不突发（0% <2 µs），RTT 级 ACK 闭环 12 µs【已证（逐包）】。
- ② **慢盆态是"每 20 ms 一个 [重放 + 1–2 新段] 突发"**：<2 µs 的成对突发占 35.7%，20 ms 空档 49.6–49.8/s，每周期 2.67 段 = 1 重放 + 1.67 新段【已证（逐包）】。与 T1 取证轮的 20,428 簇 / 1 重放 + 1.687 新段逐位同构【已证】。
- ③ **被"扣住"的段其实是对端没接收**：G4b 的 t=0.0204 周期里，板发 D4=seq 305424277、D5=seq 305425737；对端 ACK `ack=305425737 win=0`，随后（app 读走数据后）的窗更新 `ack=305425737 win=1460`——**仍不覆盖 D5** ⇒ 对端 rcv_nxt 停在 D5 之前 ⇒ D5 未被收下（越窗丢弃）【已证（逐包）】。D5 只能靠 20 ms 后的板侧重放救回（重放后对端才 ACK 到 305427197）【已证（逐包）】。
  ⇒ 旧叙事"对端 delayed-ACK 扣住一段"**应改写为**"对端有效缓冲只有 1 段深（rcvbuf 2920 − skb truesize；truesize 机制 = 【推断】，通告窗序列 0/1460 = 【已证】），板的 2 段突发必然越窗丢 1 段"。
- ④ **进入签名（首发突发段数；口径 = 首段后 2 µs 内的同组数据段数）**：盆内 **2/2 连接首发 = 3 段**（G4b port 59648、G4w port 39106，均在**同一微秒内**发出 4380 B，超过 SYN 通告的 2920 窗）；健康态 **6/6 连接首发 ≤ 2 段**（G0 port 47964/47972/47984 = 2/2/2；重烧后 G3 port 38050/38060/38066 = 1/1/2）【已证（逐包，n 小）】。首发 3 段的第 3 段在盆内**永不被 ACK**（t=0.000284 的窗更新 ack 仍停在其前一字节）⇒ 进入 = **开局就丢一段 + RTO 环自持**【已证（逐包）】。
  ⚠️ 但"为什么盆内首发多 1 段"**未定位**（候选：窗门寄存器的 1 拍陈旧"误开 1 拍"`tcb.v:234-240` / snd_wnd 初值落地时延 / 槽残留）——这正是 H2 要分的格。
- ⑤ **反例（本轮新查，重要）**：G4a 盆内 10 条爬行连接里 **8 条板侧通告 win=49152**、2 条 = 0（逐包）⇒ **板通告 win=0 不是爬行的必要条件**，H1 只能降为"共标记"（§2.1）。
- ⑥ 快照/环的 `W66` 占空（环口径，可信）在盆内只有 **2.1e-5**（G 轮）/ 5.09e-4（T1）⇒ **帧器不在"数据就绪但等窗"这个点上等**（它的 10 个排除项把"app 没给字"和"重放/ACK/扫描占用"都排除了）——这一条决定了"窗口门"不是慢盆的可见等待点，也是 §2.6 盲区的引子【已证（环口径）】。

## §2 候选机理假设（H1–H5 + 一个跨切盲区 H6）

> 每条都写明：陈述 / 支持 / 反证或弱项 / **预测（板侧读数 + 线上行为）** / **证伪判据** / 所需观测量。
> 标 【推断】 的 = 有源码或逐包依据但**未直接测**。

### H1 — 信用池 / 窗口会计污染（`app_ctrl` 侧）【推断，降级为"共标记"】

- **陈述**：抢流事件（同槽存活 + 静默释放 + 槽偷取）破坏了 `app_ctrl` 的信用池归还链（`pool`/`winq`），
  盆内新连接 `winq=0` ⇒ 板在数据段里通告 `rcv_wnd=0`；若该路径同时影响 app 侧 `tx_ok` 的可见节奏，
  则新连接开局"更敢发"（首发 3 段）⇒ 越窗丢段 ⇒ 锁进 RTO 环。
- **支持**：① 盆内爬行连接数据段 **win=0**、健康臂 **49152**（§1.1 逐包）【已证】；② "配额泄漏 ⇒ winq=0 ⇒ 通告窗 0"
  是源码里**文档化的失效模式**（`app_ctrl.v:119-126`）【已证（源码）】；③ 静默释放 = 真功能缺失（C1 机制档）【已证】。
- **反证/弱项**：**G4a 盆内 8/10 爬行连接 board win=49152**（§1.1-⑤）⇒ win=0 对爬行**非必要**；
  且信用池与 TX 窗门在源码上**不相交**（`winq/pool` 只进 `rcv_wnd` 计算；`tx_ok` 只读 `c_snd_wnd`）【已证（源码）】
  ⇒ H1 不能单独解释 TX 爬行，最多是**共因/共标记**。
- **预测**：若 H1 真，盆内 `pool(0x97)` 显著低于 WIN_POOL（→0）、爬行槽 `winq(0x9A)=0`、`stat_pool_exhaust(0x98)` 增；
  对端侧无差异（peer 不发数据，board 的 rcv_wnd 对流量无直接作用）。
- **证伪判据**：盆内 `pool ≈ 49152 ∧ winq>0` ⇒ **H1 作为"TX 爬行原因"被否**（win=0 需另找解释，如 redge/occ 或 fc 写）。
- **所需观测量**：`pool` / `winq[crawl_slot]` / `redge` / `stat_pool_exhaust` —— **零构建读不到**（§1.3 末行），
  必须进快照（构建仪器 I6）或接 AXI-Lite 桥；pcap 的 board-win 是零构建可得的**共标记**。

### H2 — 槽残留 / snd_wnd 初值 / cfg 写落地时延（开局的"多放 1 帧"）【推断】

- **陈述**：新连接首帧发出时，板侧 `snd_wnd` 不等于对端 SYN 通告值（槽复用残留 / wscale 误用 / cfg 七字段写被
  `tx>rx>cfg>fc` 仲裁推迟落地 / 窗门 1 拍陈旧），使窗门在开局多放 1 帧（3 段 vs 2 段）⇒ 越过对端 2 MSS 初窗 ⇒ 丢段 ⇒ 锁环。
- **支持**：① 盆内 2/2 首发同组 3 段、健康 6/6 ≤2 段（首段后 2 µs 同组口径；§1.1-④）【已证（逐包，n 小）】；② ADD 的 TCB 六字段是逐拍落地、
  且要过 4 级仲裁（`slow_cfg_adp.v` 头注 + `:158-193`）；③ 窗门自认"可误开 1 拍/每次最多多放 1 帧"（`tcb.v:234-240`）【已证（源码）】；
  ④ 槽偷取会让新连接**继承同一槽的上一任状态**（`cfg_up` 清的是重传记账，ADC 写的是 TCB 字段——两者时序可交错）。
- **反证/弱项**：样本小（盆内 n=2、健康 n=6）；"3 段"的机制与"窗门 1 拍陈旧"未分离（两种机制都预测盆内 3 段）；
  且 G4a 的长爬行连接 39696 的出生瞬间不在 pcap 环内 ⇒ "盆内每条连接首发都 3 段"只有 n=2。
- **预测**：若 H2 真，首 3 帧的板侧 `snd_wnd` ≠ 对端最近通告值（2920/1460），或 snd_wnd 写落地晚于首帧；
  线上：第 3 段永不被 ACK（已观测）。
- **证伪判据**：首帧时刻板侧 `snd_wnd` == 对端最近通告窗 **且** 首 3 帧的窗门记录显示第 3 帧起于"窗门已关"（即 1 拍陈旧）
  ⇒ 初值不是原因、H2 降级为"时序竞态"（仍可能致命，但修法不同）。
- **所需观测量**：per-slot `{snd_wnd, snd_nxt, snd_una, win_open}` 在**首 3 帧每帧启动拍**的锁存（构建仪器 I5）；
  零构建只能拿"首发段数"与对端 SYN 窗（pcap）。

### H3 — RTO 回卷开门 + [重放, 新帧] 双段突发 = 自持极限环（**首选**）【推断，强】

- **陈述**：RTO 触发重传会话时 `svc_rewind` 把 `snd_nxt` 写回 `snd_una`（`tcp_tx_frame.v:622/:648-650`）⇒ 窗门看到"在飞=0"⇒ **开**
  （`tcb.v:151-157`）；app 的 `tx_ok`（同源扫描值，`app_ctrl.v:557-583`）也=1 ⇒ app 的新帧在重放帧之后**同微秒级**上线
  （`start_data` 门不含 `!retx_active`，`:679-682`；TX_OVL 允许重放与新帧并发）；对端有效窗只有 1 MSS ⇒ 双段必丢 1 段
  ⇒ 丢的那段只能靠下一次 RTO（20 ms）恢复 ⇒ **环闭合、周期 = RTO**。
- **支持**：① 逐包：盆内 37.4% 段的覆盖 ACK 只在重放后出现（中位 20.1 ms）、健康 0%【已证】；② 逐包：<2 µs 突发对 35.7% vs 0%【已证】；
  ③ 逐包：对端窗更新 ACK 的 ack **不覆盖**被丢段（§1.1-③）【已证】；④ 环周期 = RTO 20.0 ms + ~50–80 µs = 实测 20.05–20.08 ms【已证】；
  ⑤ 大窗免疫与"环需要窗容不下 [重放+新]"相容【推断】；⑥ 健康臂 `W55=0`（从无 RTO ⇒ 从无回卷 ⇒ 从不突发）【已证】。
- **反证/弱项**：**进入**（首次丢段为何发生）仍缺解释（H2/H6 的格）；"对端只缓冲 1 段"是**对端行为**（放大器，不是状态载体——
  重烧清的是板）。
- **预测**：盆内 `start_data ∧ retx_active`（新帧与重放会话重叠）≈ **50/s**；`svc_rewind` 且"回卷前在飞 ≥ 有效窗" ≈ **50/s**；
  对端有效窗 ≥ 约 2–3 MSS 时环消失（`W55→0`、held%→0、速率 ≥ 数百 Mbps）。
- **证伪判据**：① rcvbuf 阶梯在"对端通告窗 ≥ 8 MSS"仍爬（`W55 ≥ 20/s` 且 held ≥ 20%）⇒ **H3 被否**；
  ② 若 `start_data ∧ retx_active` 计数 = 0 而仍在爬 ⇒ 新帧不是搭重放车 ⇒ H3 被否。
- **所需观测量**：零构建 = rcvbuf 阶梯（对端通告窗为轴）+ pcap 的 burst%/held% + `W55`；
  构建 = I1（`start_data ∧ retx_active`）+ I2（回卷时"在飞 ≥ 窗"）。

### H4 — 冻结 / 最后一段不重传：`snd_wnd==0` 卸除 RTO 计时器（H4a）或槽偷取覆盖（H4b）【推断】

- **陈述**：被位移连接的最后一段丢（同 H3 机制）后，本应在 20 ms 后 RTO 重传；观测到**永不重传**。两条机制：
  - **H4a**：RTO 装订条件含 `rb_snd_wnd != 0`（`tcp_tx_frame.v:1249`）；对端窗在 0/1460 摆动（§1.1），若扫描拍采到 0 相则计时器清 0
    （`:1258-1259`）⇒ 0 相足够密时**永不倒数到 1**。
  - **H4b**：下一个 SYN 的同槽 ADD（静默释放后的槽偷取，C1 机制档）在 ≤20 ms 内覆盖 CAM+TCB + `cfg_up` 清 `rto_*`
    （`tcp_tx_frame.v:1101-1114`）⇒ 旧四元组不再命中 ⇒ 迟到 ACK/FIN 全被丢 ⇒ 板侧控制帧 = 0。
- **支持**：① E 轮 10/10 冻结在下一 SYN 前 8–15 ms（**< RTO 20 ms**）【已证】；② E12 `ΔW72`（同槽存活）= 10 = 偷槽【已证】；
  ③ 冻结连接最后一段 0 重传【已证（逐包，E 轮）】；④ `:1249` 的 disarm 条件【已证（源码）】。
- **预测**：**逐连接"冻结前最后一条对端 ACK 的 win 字段"是分水岭**——
  最后一个 ACK 的 `win=0` ⇒ H4a 可能（计时器被卸除）；`win=1460` ⇒ H4a **不可能**（计时器有装订）⇒ 只能是 H4b 或第三种（状态不一致）。
- **证伪判据**：若冻结前最后一个 ACK 的 win=1460 且 3 s 内板对该四元组发了 ≥1 个重传 ⇒ "永不重传"被否（观测错）；
  若 win=0 且 3 s 内 0 重传 ⇒ H4a 成立；若 win=1460 且 0 重传 ⇒ H4b（或状态不一致）成立。
- **所需观测量**：零构建 = pcap 逐连接（最后 ACK 的 win / 最后段 seq / 该 seq 的重传次数 / 冻结时刻）；
  构建 = I3（`scan: snd_nxt≠snd_una ∧ snd_wnd==0` 计数）+ per-slot 状态。

### H5 — 对端放大条件：有效通告窗 = 1 MSS【已证（对端行为），非状态载体】

- **陈述**：慢盆不是"对端有问题"，但对端在本构型下的**有效窗只有 1 MSS**（rcvbuf 2920 − skb truesize ⇒ 通告窗 0/1460，
  从不 2920）——它把"板侧多放 1–2 帧"从无害变成**必丢一段**。这是放大器，不是会话级状态的载体（对端进程每臂重启、内核参数相同）。
- **支持**：G0 健康臂同样 rcvbuf 2920 → 通告窗恒 1460；盆内 1460/0 交替；1 MB 臂 65535 且免疫【已证（逐包）】。
- **预测**：rcvbuf 阶梯的免疫阈值 ≈ 对端通告窗 **2–3 MSS**；对端换 1 MB 时板侧 `W67`（板帽侧等窗）>0
  （snd_wnd 65535 > WIN_CAP 61440）。
- **证伪判据**：rcvbuf=1 MB 仍爬 ⇒ H5 无关（已被 G4C 反证：不爬）【已证】。
- **所需观测量**：rcvbuf 阶梯 + pcap 对端窗直方图（零构建）。

### H6 — 跨切：app 侧"未计数等待"（影响**读数解释**，不是独立机理）【推断】

- **陈述**：盆内 `W63`（frm_wait）只有 8.4–19.8%、`W64`（背压）≈ 0.003%，而 app 每帧要等 ~10–11 ms ⇒ **app 的主要等待态不在两个计数器里**。
  最可能的载体 = `op_pend && !m_tready`（opener 进不去，因为帧器 S_IDLE 的 `s_axis_tready` 第二分支含 `wnd_open`，
  `tcp_tx_frame.v:674-678`；此态 `pw_valid=0` 不计 W64、非 frm_wait 不计 W63）。
- **支持**：源码链（`app_pattern.v:498-500` / `:1059-1080`）+ `W66` 占空极低（帧器不在"等窗点"）+ `W63/W64` 口径（§1.2）。
- **后果**：任何"app 是瓶颈 / app 没在等窗"的读书都会读歪；**下一轮必须补这个字**（I4）。
- **证伪判据**：若 `op_pend && !m_tready` 占空 < 5% 而 app 仍在等 ⇒ 盲区在别处（例如 `closing`/`!active`）。

## §3 观测方案

### 3.1 零构建（现有 75 字快照 + 对端套件；不碰 RTL）

**A. 快照环 KW 方案（改为 15 字；工具支持 `KW=`/`KW2=` 覆盖，`tools/arm_basin.sh:55-56`）**

```
KW_B = '5 20 43 51 52 55 63 64 65 66 67 68 69 57 58'     # 慢盆段（低速，采样慢可接受）
KW_A = '5 20 43 51 52 55 66 67 68 69'                     # 快相/健康对照（保持现役短表）
```
- 理由：慢盆速率低 ⇒ #67 的"高码率下 12 字快照 ~288 ms"**吞吐**代价不咬；但**时间分辨率**仍不够——20 ms 级现象需要 ≤1 ms 采样，
  而 15 字 ≈ 360 ms/点 ⇒ 约 2.8 Hz，**只能看秒级趋势、抓不到单周期** ⇒ **单周期证据必须由 pcap 提供**；快照环只做趋势/对账。
- 推荐做法：每臂两条环——**背景环 KW_B（2.8 Hz）** + **进入瞬间用 pcap**；不要指望环抓 20 ms 周期。
- `W57/W58` 加进环：`W58`（retx_active）在 2.8 Hz 下大多为 0，**不能当"无会话"的证据**；只在同一窗 `ΔW55>0` 时有解释力。
- `W63/W64/W65` 从 PRE/POST 挪进环（修 §0-③ 的 wrap 歧义；`W65` = `mac_tx_idle`，可给线空闲份额）。

**B. 对端套件（每臂必带）**
1. **pcap**（`tcp port 8080 -s 128`，双向）→ 派生量（一次性脚本即可，逻辑已在本轮验证）：
   - 每连接：数据段速率、`gap<2 µs` 占比（突发率）、`held%`（覆盖 ACK 只在同 seq 重放后出现）、首发段数（首个覆盖 ACK 之前）、
     对端通告窗直方图、最后 ACK 的 win、最后段 seq 的重传次数、冻结时刻。
2. `ss -tinH` 逐秒（每 socket 的 bytes / rtt / cwnd / snd_wnd 轨迹；补上 T1 未取的那一格）。
3. `nstat -az` pre/post（沿用 G 轮口径：DelayedACKs / DelayedACKLost / RetransSegs / TCPOFOQueue / PureAcks / HPAcks）。
4. `RUN_TIMEOUT` / 硬界 / `SINK_MD5` / `pcap` 三硬门沿用 `arm_basin.sh`。

**C. 零构建的边界（必须写清，别越界）**
- 能读：75 字快照（可选任意子集，每秒 1–3 点）+ pcap（µs 级，全量）+ 对端内核态。
- **读不到**：`app_ctrl` 的 `pool / winq / redge / 每槽 TCB`（总线静态钉死，`wrapper_p4.v:1345-1346`【已证】）；
  per-connection 的 retx 归属；`start_data ∧ retx_active`；`op_pend` 等待；回卷时的在飞/窗读数。
- ⇒ 零构建能**判** H3（rcvbuf 轴 + held%/burst%/W55）、H4（pcap 的 win 分水岭）、H5（窗直方图）、H2 的**现象层**（首发段数）、
  H1 的**共标记**（board-win）；**不能判** H1 的池值、H2 的内部机制、H6。

### 3.2 需一次构建（最小仪器清单；先做 3 字，按结果再加）

> ⇒ 下一构建**第一动作** = `.PERSIST_EN(1'b1)` + BID bump（建议 0x2A）；并遵守 `board/run_build_p7b_ku5p.bat` 单入口。

## §4 实验设计（三段式：进入 → 探针 → 清除）

**三段式的定义（本轮的骨架）**：
- **进入段** = 用 G 轮已证 ×2 的 T1 同构型造盆（B1）；进入判据 = 首连接"快相→崩"+ sink2 STALL + `ΔW72>0`
  （与前两轮逐项同构）。**不重烧**（进入的前提是板处于"刚烧过的干净态"，B0 先锚健康基线）。
- **探针段** = 盆在场后的全部观测（B2 核心探针 / B3 阶梯 / B4 冻结 / B5 大窗进入 / B7 无读对照）。
  每格都有"如果 A 真 vs 如果 B 真"的分离点（§4.2 表），读法只用 §4.3 的口径。
- **清除段** = 重烧 0x28（双锚 sha 门）→ B6 盆外同构对照（B0 + B3 两档）。清除只在"读数层"成立
  （G2 慢 → 烧 → G3 快的二值），**不解释**"为什么重烧能清"（本件把这一格留给 §2 的假设：状态的载体只能是板内寄存器/BRAM）。

### 4.3 判据事先钉死（读数口径，不是 PASS/FAIL 裁定）

1. **"爬行"** = 连接中位唯一速率 ≤ 5 Mbps **且** 同窗 `ΔW55/Δt ≥ 20/s`；**"免疫"** = ≥ 100 Mbps 且 `ΔW55 = 0`。
2. **held%** = "覆盖 ACK 只在同 seq 重放之后出现"的数据段 / 全部数据段（本轮的脚本定义，逐包可复算；G4b 37.4%、G0 0%）。
3. **突发率** = 相邻数据段发出间隔 < 2 µs 的对 / 全部相邻对（G4b 35.7%、G0 0%）。
4. **首发段数** = 第一个能覆盖首段的 ACK 之前、同一连接发出的数据段数（G 轮已用；本轮订正了"含首 ACK 之后段"的计数错误）。
5. **免疫阈值** = rcvbuf 阶梯上 `ΔW55` 首次跌到 0 且速率 ≥ 100 Mbps 的那一档；**同时记对端实测通告窗**（MSS 数）。
6. **回卷/32 位纪律**：所有计数器差一律 mod 2³² **并记 k**（`W5/W20/W43/W51/W52` 在 12 s 窗即回卷，门槛 2.8633 Gbps）；长臂（≥30 s）**禁用 PRE/POST 差值**做速率/占空，用环的逐点差。
7. **"未观测到" ≠ "不存在"**：若某读数在臂内 0 命中，只写"未观测到"，并附该读数的**覆盖/灵敏度**（例：2.8 Hz 环看不到 20 ms 周期）。

## §5 建议（首选 + 理由 + 排期/成本）

### 5.1 首选：**先打零构建探针轮（B0→B1→B2→B3→B4，B5/B6 视时间）**

理由（按信息量/分钟排序）：
1. **B3（rcvbuf 阶梯）是单个臂表里信息最大的一格**：它同时是 H3 的**唯一直接证伪器**（"对端窗 ≥2–3 MSS 时环消失"）、
   H5 的量化（免疫阈值）、以及**对用户最实用的缓解方向**（把 sink 的 rcvbuf 抬过阈值即可绕开）。成本 ~8 min。
2. **B2 + B4 的 pcap 派生量（held% / 突发% / 首发段数 / 冻结前最后 ACK 的 win）是零构建就能拿到的最硬证据**，
   且本轮已经用既有 pcap 验证了全部脚本逻辑（37.4% vs 0% 的两态分离极干净）。
3. **零构建不动 WNS 余量、不碰树态**（HEAD=0x29 幽灵配置的风险只在构建轮出现），且不消耗构建/门/矩阵的半天成本。
4. **一次构建的 3 个计数器（I1/I2/I3）只在零构建仍分不开 H3 时才值得**——按当前 37.4% vs 0% 的读数，H3 很可能在 B3 就被裁决。

### 5.2 决策树（零构建轮后的去向）

```
B3 结果：
 ├─ 对端窗 ≥2–3 MSS 时免疫、≤1 MSS 时爬（W55≈50/s、held≥30%）
 │    ⇒ H3 成立（回卷双段环为板侧机理）⇒ 修法方向（设计侧，另一轮）：
 │      ① 回卷期间**不允许** app 新帧启动（start_data 加 !retx_active，或加"回卷后 N 拍窗墙"）；
 │      ② 或回卷时**保留**在飞计账（snd_nxt 不写回；用独立 replay 指针），让窗门看到真实在飞；
 │      ③ 或在 1-MSS 窗下把重放与新帧串行化（一次窗开只放 1 段）。
 │     ⇒ 一次构建只做 **I1+I2** 当"修法有牙"的见证（可与修法同批）。
 ├─ 全档都爬（含 8 MSS 以上）、仅 1 MB 免疫
 │    ⇒ H3 被否 ⇒ H1/H2/H6 上位 ⇒ 构建 I5+I6（初值/池）+ I4（app 盲区）一次收口。
 ├─ 阶梯上"爬"与"快"混杂、与对端窗无单调关系
 │    ⇒ 进入/维持不是窗量级问题 ⇒ 回到 H4b（槽偷取）+ H1（池），把 B4 的冻结判据与 E12 摆到主判据。
 └─ B1 没进入（复现失败）⇒ 先重跑 B1 两次（进入已证 ×2，但需保证"真异槽并行"），
      再决定是否用 B5（大窗进入）作旁路猎场。
```

## §6 风险与登记（不许当已收口）

1. **进入的复现性**：进入【已证 ×2】，但两次都在"新烧后 + 小窗 T1 同构"下取得；**大窗进入【未测】**（B5）。若 B1 复现失败，
   先按 G 轮 §8 的偏离纪律登记，不得用"盆不在场"解释后续慢读数。
2. **快照读/寄存器写是否影响盆【未测】**（G 轮 §9-6）：本轮全部臂都带身份门读取 ⇒ 缺"无读取对照"（B7 可选）。引用任何零构建读数时必须带此行。
3. **C1 轮的三条新观测**（接收字节 +5.3–9.3% / 同连接 2920 B 重复 / 回跳段）与慢盆的关联 = **候选共因，未定位**：
   本轮在 T1 臂也复现到"对端收到字节 > app 产出字节 ~13%"（98.7 MB vs 87.2 MB；后者 = 环均速 `W51` × 臂长 437.7 s）
   【已证（本件复算；口径 = 环均速 × 臂长 vs sink 自报，两数都受环边界影响，量级可信、末位不可引）】。
   若 B2/B3 再次出现，登记为"板可能发出 app 未产出的内容"的独立挂账项（与慢盆机理分开）。
4. **`W55` 的全局性【未定位】**：`stat_retx` 是全局计数（`tcp_tx_frame.v:1195`），冻结连接与活动连接的 RTO 混在同一个数里；
   零构建无法按连接拆（构建 I 类可拆）。
5. **快照环的采样率**：KW_B（15 字）≈ 2.8 Hz ⇒ **抓不到 20 ms 周期**；单周期证据一律以 pcap 为准（#67 的教训反向适用：低速盆里慢采样可接受，但**别拿它当周期证据**）。
6. **对端放大条件**：本章所有"慢/快"判据都默认 sinks 的 `--rcvbuf/--poll-ms` 与 G 轮逐字一致；换 sink 二进制/换内核参数 = 换放大器，必须重锚（B4 的 C1 轮曾因 sink 二进制造过 5 Gbps 级差异）。
7. **不改树**：本件不产生任何 RTL 改动；构建轮必须在**新分支/worktree**或明确的单入口流程里做（"改 RTL 与在跑回归互斥"）。
8. **判据所有权**：本件只给读数口径与分离表；PASS/FAIL 与"收口"措辞的裁定权在 TL/用户。
