### 1.1 物理量与统计口径

| 量 | 定义 |
|---|---|
| **零窗 ACK** | 对端→板（src `192.168.100.100`，sport/dport 8080）且 **TCP ACK 标志置位、TCP 载荷 = 0** 的包中，**通告窗字段 `win == 0`** 的那些 |
| **`zw_pct`（主轴，PRIMARY）** | `100 × #win0 / #ACKs`，在一跑（一个臂）内**跨连接聚合**（每条 ACK 计一次）。ACK 基数 = 上述定义（含 FIN/RST+ACK），与探针轮 `probe_metrics.py` 的 `peer_win_hist` 同一基数 ⇒ 与 B3 阶梯可比 |
| **`zw_pct_pure`（SECONDARY）** | 同上，但只取**纯 ACK**（flags == 0x10，排除 FIN/RST+ACK 与 window-update 之外的带控制位 ACK） |
| 逐连接 `zw_pct` | 按对端临时端口分连接计算；`median_conn_zw_pct` = 有效连接（ACK ≥ 20）的中位 |
| **速率（PRIMARY）** | pcap 的 **unique-seq 速率**（`probe_metrics.py` 的 `uniq_mbps`；按 1460 对齐去重）——与探针轮同口径 |
| 速率（SECONDARY） | sink 自报 `SINK_CONN ... Mbps`（逐连接） |
| 分类阈值（沿用探针轮） | **爬行** `uniq ≤ 5 Mbps` · **中间** `5 < uniq < 100` · **快** `≥ 100 Mbps` |
| 簇钟 / IAT / held% | `probe_metrics.py` 的 `burst_pct` / `gap_*` / `held_pct` / `held_delay_med_ms` |
| 板侧环字 | `W5/W20/W43/W51/W52/W55/W63/W64/W65/W66/W67/W68/W69`（`parse_snap.py`，mod 2^32） |

### 1.3 判定规则（预注册）

**H_ZW（主轴假设）**：对端通告零窗 ACK 占比是盆内「快/慢」的分水岭。

按档位序列 `S = [2920, 6000, 7000, 8000, 8760, 10000, 12000]`（如触发 7500 则按数值序插入），每档取**跨跑的档中位**（med）：

- **(a) 跨档突变同序**：
  - **速率突变界** = 最早的相邻档对 `(b_i, b_{i+1})`，满足 `med_rate(b_{i+1}) / med_rate(b_i) ≥ 10` **且** `med_rate(b_i) ≤ 10 Mbps` **且** `med_rate(b_{i+1}) ≥ 100 Mbps`。
  - **零窗突变界** = 最早的相邻档对，满足 `med_zw(b_i) ≥ 5%` **且** `med_zw(b_{i+1}) ≤ 1%`（即下降 ≥5×）。
  - **(a) 成立 ⇔ 两个突变界存在且是同一对档**。若无速率突变界 ⇒ (a) = **【未观测到】**。
- **(b) 同档内负相关（旁证，低功效）**：对每个「`zw_pct` 跑间极差 ≥ 0.5 pp 且速率有差异」的档，**`zw_pct` 最高的那一跑必须速率最低**。≥2/3 这类档满足 ⇒ (b) 支持。n=3，明确登记为低功效，不作主判据。
- **(c) 盆外对照**：在 `2920 / 7000 / 8000` 三档，**盆外档中位 `zw_pct` 必须 ≤ 1%**；且盆内同三档中至少一档中位 `zw_pct` **≥ 5%**。两者同时满足 ⇒ (c) 成立。

**总体判定（预注册）**：
- **(a) ∧ (c)** ⇒ 零窗占比是分水岭：【支持】。
- **(a) ∧ ¬(c)** ⇒ 速率与零窗同序、但**不能归因于零窗**（盆态共因）：【同序但未归因】。
- **¬(a) ∧ (c)** ⇒ 盆内零窗是盆态特征，但**不是速率分水岭**：【盆态特征、非分水岭】。
- **¬(a) ∧ ¬(c)** ⇒ **【未观测到】**零窗占比作为分水岭。
- 任何一格如果数据不足以评估（如进盆失败、pcap 丢包、档位缺失），该格写 **【未判定】** 并给出缺什么。

## §6 偏离与未测（逐条）

### 偏离（按发生顺序）

1. **档位**：预注册 `{2920,6000,7000,8000,8760,10000,12000}` 全部执行。**预注册的条件性补充档 7500 未触发**（触发条件 = 7000/8000 中位速率差 <2× 且中位 zw 差 <3 pp；实测 490.8× / 38.6 pp，远过阈值）⇒ 不补档是**按预注册执行**，不是省事。
2. **新增探索臂（非预注册，判据不变）**：`Z10000r4/r5`、`Z12000r4` 三跑 + 盆外 `C12000r1/r2` 两跑。动因 = 12000 桶出现反转后，需排除"全局时间漂移"：**12000 之后立刻重跑 10000 仍全快（1452/1273/1568 Mbps，zw 0.09–0.12%）** ⇒ 不是全局漂移；12000 的慢是**该档与盆态的相互作用**（机理见 §5 限定 2【未定位】）。这些臂**不进 §1.3 的档序列**。
3. **慢臂样本窗 90 s**：`--seconds 60` 只挡新连接、不终止在跑连接；慢臂由 `RUN_TIMEOUT=90` 硬杀 ⇒ 连接样本窗 ≈89.8 s（探针轮 B3 同为 90 s 硬界）。
4. **`A0` 的 20 ms held 延迟**：3 连接 held%=0，`held_delay_med_ms=20.18` 是**单点噪声**，不作读数（§3.1 注）。
5. **快臂环点稀疏**：8000/8760/10000/盆外各臂墙钟 1–4 s，环只有 2–8 点；`W55`/`W63` 只作趋势参考，速率/零窗一律以 pcap 为准。C12000 两跑的环因 `GEN_FAIL` 只剩 2 点 ⇒ `W55` **未取**（如实登记）。
6. **每个环的第一个点必 `GEN_FAIL`（gen +2）**：34/34 臂同形（包括 A0/E1）；其后各点有效。影响 = 丢首点；对统计无影响。**归属未定位**（疑似与臂前 `SNAP_PRE` 的触发/完成位竞争；本轮未追）。
7. **从未跑通"盆外 6000/8760/10000"**：派单只要求 ≥2 档，本轮做了 **4 档**（2920/7000/8000/12000）；另三档未测（未测 ≠ 不需要）。
8. **12000 反转档的桶内 n=4**（预注册 ≥3 跑，满足）；但 12000 的逐连接形态差异大（2 条 ~90 Mbps、2 条 ~16–22 Mbps），**桶中位掩盖双峰**，逐连接表已列。

### 未测 / 未判定 / 未定位（不许当已答）

1. **零窗与慢的因果方向【未判定】**（§5 限定 3）；需要独立扰动（改对端通告窗/读侧延迟）而不是再扫 rcvbuf。
2. **12000 慢区机理【未定位】**：候选 ① 每突发段数超过对端有效缓冲 ⇒ 越窗丢段 ⇒ RTO 20 ms（与 2920/7000 同族，只是突发更大）；候选 ② 盆态随时间演化（阈值上移）—— 但 `Z10000r4/r5` 在 12000 之后仍快，**不支持"全局漂移"**；候选 ③ rcvbuf 12000 恰好落在某个对端窗/板窗门的不利组合。三轮均未分离。
3. **盆的时变【未测】**：本轮阶梯是**单会话 25 min 内**的顺序扫描；没有"同一档在不同 t 重复"的纵向设计（12000 反转无法区分时变 vs 档位效应）。
4. **`W55` 的全局 vs 逐连接语义【未定位】**（探针轮遗留）；本轮 12000 的 `W55≈100/s`（介于 50/s 与快重放 1000+/s 之间）再次说明它混合了不同事件。
5. **零窗占比的"充分性"【已否（读数层）】**：12000 的低零窗 + 慢 ⇒ 高零窗不是慢的必要条件（反过来，8000–10000 的低零窗 + 快也不证明低零窗足够）。**"零窗高是慢的充分条件"未测**（无法在不改变其他变量的情况下单独制造零窗）。
6. **板侧真实线占空/窗口门**：本轮未新增仪器；`W66` 仍是窗口门停顿拍的代理（快档 0.01–0.04，慢档 0.0003–0.004 —— 与"慢在更上游"一致，但不是直接测量）。
7. **`0x08` 写门/快照读是否扰动盆【未测】**（与探针轮同；所有权都在臂内）。
8. **12000 的 RTO 事件数**：`W55` 只给会话数；pcap 给出 20 ms 间隔的 IAT 计数（2.8%），但"每次 20 ms 停顿是否都由 RTO 触发"【未定位】（可能是窗关闭等待，不是 RTO）。
9. **盆外 12000 的 `W55`【未测】**（环点 <3）。
10. **本轮的 `W63/W5` 不是判别量**：盆内 2920 0.99 vs 快档 0.73–0.88 —— 与探针轮 §7-1 的"W63 盆内 0.9999"不完全一致（本轮 0.978–0.996）⇒ 该量的口径/采样仍不稳，**不作判据**。

## §7 下一步建议（零构建夹逼结论 / 是否值得上 I1/I2/I3）

### 7.1 零构建层的结论（可直接用于设计）

1. **分水岭已夹到单档宽度：`7000`（慢）↔ `8000`（快）**。7 档中位：2920 0.99 / 6000 18.3 / 7000 3.0 / **8000 1480.6** / 8760 1187.7 / 10000 1568.3 / 12000 16.7 Mbps；零窗 37.3 / 18.2 / 38.6 / **0.08** / 0.07 / 0.12 / 2.59%。
2. **盆外同 rcvbuf 全部快、零窗 ≤0.03%**（2920/7000/8000/12000）⇒ rcvbuf 本身不是原因；**盆态 × 小窗**才是。
3. **有效窗直方图给出机械联系**：盆内 8000 起主导窗 = 2920（2 MSS）且**零窗几乎消失**（0.1%）；盆内 7000 及以下主导窗 2920/1460 + **零窗 20–37%**。⇒ **"最小有效窗是否触 0"仍是最好的单一分离量**。
4. ⭐ **但单轴解释不完整**：12000 的反转（低零窗 + 慢 + 20 ms 周期）说明盆内至少还有**第二条慢路径**（每 20 ms 一大突发的周期态）。**"大窗免疫"不应写成普适结论**（1 MB 免疫是 G 轮读数；12000 在盆内被惩罚是本轮新读数）。

### 7.2 是否值得上 I1/I2/I3 三字构建

**建议：值得，但优先级/组合要改**。理由与建议顺序：

- **I1（`start_data ∧ retx_active` 计数）+ I2（回卷开门计数）**：能直接回答"8000 快档是否真的没有回卷会话、12000 慢档是否在回卷"——本轮只有 `W55`（混合量）与 held 延迟（间接），**分不开"窗关等待"与"RTO 回卷"**。这是把 §5 限定 3 与 §6-2 变成直接读数的**最短路径**。
- **I3（`stat_rto_disarm_wnd0` / 危险拍 `snd_nxt≠snd_una ∧ snd_wnd==0`）**：本轮 12000 的零窗只 2.2%，若 I3 计数高 ⇒ 说明"窗口扫描采到 0 相"与"实际 ACK 零窗占比"不是一回事（探针轮已提示最后数据后仍有 win=0 窗更新）；值得同批。
- **新增建议 I7（零构建替代不了的那一件）**：在 `tcp_rx` 加**逐槽"收到 win==0 的 ACK 计数"**（板侧直接测量，不依赖 pcap）。这样把本轮的核心轴搬进快照，避免每次都要抓包；代价 16×32 位或压缩到 4 个 8 位桶。
- **不建议**再做的零构建：继续扫 rcvbuf（已到单档宽度、且 12000 已暴露非单调）；再扫 `rcvbuf 10000..12000` 的每 250 B 步进（除非只想要"第二个拐点"的位置）。
- **建议的一个零构建补充（若还有窗口）**：**纵向设计**——进入盆后固定 12000 档，在 t = 5 / 15 / 25 / 35 min 各跑一次，判"12000 慢区是否随时间出现/消失"；这能直接分离 §6-2 的候选 ②（时变）与 ④。成本 ≈ 4 跑 × ~80 s。

### 7.3 给 TL 的三行摘要

- 盆内：**7000 慢（3.0 Mbps / 零窗 38.6%）vs 8000 快（1481 Mbps / 零窗 0.08%）**，单档夹逼成立；盆外同档 1308/1566 Mbps、零窗 ≤0.03%。
- 按事前判据 **(a)(b)(c) 全成立 ⇒ 【支持】零窗占比是 7000→8000 分水岭的分离量**；但 **12000 反转（16.7 Mbps / 零窗 2.6% / 20 ms 周期）** ⇒ 零窗不是唯一轴，因果方向未分离。
- 板已交还 **0x28 + 0x08=0 + carrier=1**（未烧 0x2A）；QSPI 零写入；对端无残留。
