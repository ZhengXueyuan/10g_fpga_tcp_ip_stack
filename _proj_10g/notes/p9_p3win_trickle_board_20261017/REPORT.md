## 5. P-3 实验（cfg A）核心

**前置门（P3A0，`runs/P3A0_0x28_READINGS.txt` §gates）**：

- **G1** `Δ(W72+W74) = 24+0 = 24 > 0` **PASS**（触发面被激励）；**G2** `W51`（RING 口径）= **5.318 Gbps ≥ 1 Gbps** **PASS**
  （⚠️ PRE→POST 裸差 163 Mbps 是 **32 位回卷伪影** —— 该速率下 W51 **每 6.46 s** 回卷一次〔2³² B / 664.7 MB·s⁻¹；按比特算的 0.81 s 是错值，D-4〕，一律 RING 口径，#55）；
- **G3** `ΔW71 = 36,809 == ΔW73+ΔW74 = 36,809+0` **CLOSED**（三态恒等式闭合）；
- **期望门 NOT MET**：`24 × P`，其中 `P = W51_Bps/(1460×156.25e6) = 2.914e-3` ⇒ `0.070 << 3`
  ⇒ 按 DESIGN §4，该臂登记 **"NO DISCRIMINATING POWER for the P-3 question"**（判据阈值不可达），**不是** "P-3 absent"（#92 空判据）。

**事件分解（E12，PRE = 21/9/16/5）**：`ΔW71 up_ev = 36,809`（每连接恰一）· `ΔW72 sw_req = 24`（0.065 % 落到"活着的 app"）
· `ΔW74 up_pend = 0` ⇒ **干净应用 = 36,785 = 99.935 %** ⇒ **H2 形态**。设计预期 200–500 事件/s；实测 **0.2/s**。
⇒ **H1（"ADD 落在 app 组装中"）本构型下未出现**；这是期望门失败的直接原因（abort-rst + 立即重连配方几乎全产出"app 空闲时到达"）。

**ctl pcap（H1/H2 直接见证）**：939,927 帧全为 peer→board；`{'RA': 36,799, 'R': 903,128}`；**板侧控制帧 = 0**（120 s 无 FIN/RST/FIN-ACK；与 B4H3 同形；每连接 ~25 个 RST 是对端应答已死四元组的后段帧）。

**P3A1（0x24）**：同一构型下 36,569 连接全洁、命中 0；`E12 NOT PRESENT on 0x24 ⇒ G1 not measurable here`（设计 §1.4）。

**两条登记（P3A1 件 §CAVEAT）**：

- **无判别力caveat 同适用于两臂**（继承 P3A0）：0 命中是**空判据**，非"缺陷不存在"。
