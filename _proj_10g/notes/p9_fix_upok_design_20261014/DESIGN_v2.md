## §1 机制复核（v2；与 v1 §1.1–1.3/1.5/1.8 **逐字相同**的部分只列结论）

### 1.1 事件源与接线（v1 未变，摘要）
`slow_cfg_adp` 每 ADD 记录末字段 gnt 拍发 1 拍 `ev_up`（`rtl/slow_cfg_adp.v:187-198`）→ `app_ctrl` **无条件转发** `o_ev_up`（`rtl/app_ctrl.v:973-978`）→ `app_pattern.ev_up`（`board/wrapper_p4.v:1211-1213`；接线链区域 = `:1255-1262` 的 `slow_cfg_adp` 例化，**v2 订正锚点标签**）。⇒ 源侧/接线侧无丢事件路径。

### 1.2 `up_ok` 的精确条件链（v1 未变，逐字）
```verilog
:504 up_ev = ev_up || up_pend_r;   :505 up_slot = ev_up ? ev_slot : up_pend_id;
:506-507 up_ok = !active || ((up_slot==act_id) && (frm_wait || seg_sent==0));
:508 up_do = up_ev && up_ok;       :514 ev_restart = up_do;
```
立即接受面 = `frm_wait` ∪ `seg_sent==0`（每帧 1–2 拍）；**在飞帧中段不接受换流**。
⛔ 订正（保留）：**"`TX_CONTINUOUS=1` 下 active 恒 1" 不成立**（`ev_down`→W3→`active=0` 在连续模式下活着）。

### 1.3 换流块 = 复位 TX LFSR 的唯一处（v1 未变）
`:713 if (up_do) … :736 active / :737 act_id / :738 remain / **:739 tx_lfsr<=SEED（全文件除复位 :676 唯一）** / :744-746 / :755-756 / :758-760 / :761-762 / :772 / :773`。
**"新连接流从 `pattern[0]` 起"全押在 `:739`** ⇒ 被盖/被延后/被丢 = 对端相位错。
对端签名（v1 未变）：`first_mismatch=0` · `mism ≈ bytes − bytes/256` · `K0` 恒为 1460 整数倍。

### 1.4 三条失效路径（**v2 重写**）

#### (P-1) 延后（A3 补做位）—— **后果精确化：一次"迟到的干净复位"= 相位断点，不是"整条沿用"**
- 机制（v1 已证，保留）：未立即接受的 `ev_up` 登记 `up_pend_r`（`:784-788`）⇒ 在其后**第一个帧间隙拍**（`frm_wait` 或 `seg_sent==0`）被 `up_do` 消费。
- ⭐ **v2 采纳 kimi 的强化**：**pending 的消费拍在结构上永远 `asm_go=0`**：帧首 `seg_sent==0` 的第一拍恒为 `op_pend=1`（收帧支 `:847-857` 置），而 `asm_go` 含 `!op_pend`；`frm_wait` 拍 `asm_go` 含 `!frm_wait`。**⇒ 由 pending 触发的复位必然干净**（`:739` 不被 `:916` 覆盖）。
- ⇒ (P-1) 的对端可见形态 = **"一段旧相位 + 一次回到 `pattern[0]` 的重启" = 一个相位断点**（align 工具会报 break；sink 逐字节在断点后整段失配）。**它不产生"整条连接 off≠0 且无断点"**。

#### (P-2) 撤销（`:789-790`）—— v1 分析保留：撤销判据分不出"新连接自己关了"与"旧连接 DEL 迟到"；后果 = 事件永久丢失（若该拍 app 仍 active，同一条 `ev_down` 还置 `closing` ⇒ 转 idle ⇒ A7 静默零数据形态）。**"迟到 DEL"的 HLS 侧产生条件 = 仍未复核（v1 附录 B 同款）**。

#### (P-3) ⭐ 同拍覆盖写（**静默丢复位**）—— v2 按复核精确化
- 机制（v1 已证 + 复核确认）：换流拍 `up_do=1 ⇒ a2_hold=1`（`:538`）⇒ **`a2_ldw=0`、`wc_go=0`** ⇒ 装配落入**逐字节支 `:916`** ⇒ `tx_lfsr <= xs_next(旧值)` **逐个盖掉 `:739` 的 `SEED`**，并把 1 个旧流字节预装进 `stg/bcnt`（`:914-915` 晚于 `:761-762` 的清零）。**净效果 = 行政副作用全生效、图案流没重开**。
- ⭐ **v2 采信两条更正**：① **覆盖者 = `:916`**；`:909`（a2 支）与 `:889`（wc 支）因 `a2_hold=1` **同拍结构性不可达**（v1 已如此写 `:909`，v2 把 `:889` 一并写明 ⇒ E9 对 `:889/:909` 是**永久冗余门**，保留作防御但须标注）；② **窗口宽度 = 构型相关（v1 写"每帧恰 1 拍"只对 A2 板构建成立）**：
  - **A2 板构建**（`P7B_10G` + `TAILCARRY=0`）：首字 1 拍装载（`a2_ldw`）⇒ 窗口 ≈ **1 拍/帧**；
  - **默认逐字节构建**（`TX_CONTINUOUS=0` 时也中招）：首字装配期 `bcnt:0→need`，**每拍 `asm_go=1`**（无 `a2_hold` 抑制）⇒ 窗口 ≈ **7-8 拍/帧**。
- ⭐ **v2 采纳 kimi 的"更强一层"**：**pending 事件永远到不了首字装载拍**（同 (P-1) 的证明）⇒ **P-3 只能由 raw `ev_up` 直接命中该装载拍触发**。
- **对端签名的强判别（v1 推演，复核保留）**：预装字节恰是"流的下一个字节"、LFSR 恰是"下一位置" ⇒ **逐字节无缝延续（无缺口）**——与"事件从未发生"在字节流上不可区分，与 (P-1)（断点）可区分。

### 1.5 相位错如何产生（v1 未变，摘要）

## §2 修法（**v2 重做**）：候选 ① 先收尾后换流（close-out-then-switch）

### 2.1 设计不变量（四条，全部可在门里断言）

| # | 不变量 | 为什么必须 |
|---|---|---|
| **I1** | **应用拍恒有 `active=0`** ⇒ `asm_go≡0` ⇒ **P-3 同拍覆盖写在结构上不可能** | 消灭"复位被静默丢掉"子类（不依赖 E9 的防御门） |
| **I2** | **受理 = 应用 ∨ 登记（无第三态）** —— 每个 `ev_up` 要么当拍应用、要么进 `sw_pend`/`up_pend_r` | 消灭 H-1 的两条静默丢弃（closing 态 / 空闲态） |
| **I3** | **应用拍槽源 = 事件拍锁存的槽**（`sw_slot`/`up_pend_id`），不是任何"当时现读"的值 | 消灭 H-2（应用到槽 0/陈旧槽） |
| **I4** | `sw_pend` 与 `up_pend_r` **至多一个非 0**（`ev_up` 登记时互相清；应用拍全清） | 最新事件优先；应用拍槽源单一 |

### 2.2 语义（三态 × 两槽）

| 事件到达时 | 同槽 | 动作 |
|---|---|---|
| 空闲（`active=0`） | 任意 | **立即应用**（`sw_apply`；旧 `!active` 臂语义，`asm_go=0` 保证干净） |
| 存活（`active=1`，**含 `closing=1`**） | 是 | **登记 `sw_pend/sw_slot`** + **触发收尾**（`closing<=1`；已在 closing 则同值）；收尾完成（`active` 落 0）的下一拍应用 |
| 存活 | 否 | **登记 `up_pend_r/up_pend_id`**（A3 原语义：等当前会话结束后再换） |

**在飞帧/半帧处置**：收尾恒走既有 W3 通路（`close_send` 0 载荷 tlast；`pw_valid` 在飞字被 `drop_pw` 撤 → 见 E8 扩项）⇒ 帧器不留 `S_RECV` 悬挂；`frm_inflight=0` 时 W3 的 `else` 支 1 拍直达 idle。
**残留（如实）**：已交给帧器的当前帧前缀（≤1 帧）+ 帧器队列 ⇒ 新连接首部可能有一段旧相位**前缀**（S0C 实测该点残差 = **0**，见 §1.6；上界按结构给，§5.1）。

## §5 板上判据计划（v2 修订）

### 5.1 口径（修订处已标）
- **旧口径**：sink `mism_bytes` 仅在"该连接相位 0"时有内容判别力（v1 未变）。
- **新口径（主判据）**：**每连接 `K0`（绝对）== 0**；`K0≠0` 时记 `prefix_len=K0` 并要求 `STREAM[K0..]=pattern[0..]` 且无断点。
- ⭐ **残差上界 R（v2 重定，M-1/M-2）**：v1 的"实测 2920 B"**撤回**（= conn0 伪影 + 算术错）。新口径：① **S0C 该点实测残差 = 0**（K0 与冻结相位逐位相等，§1.6）；② 结构上界 = "已交帧器的当前帧前缀（≤1460 B）+ 帧器队列"（**未定量实测**）；③ 修复臂判据 = `K0==0`，若 `K0>0` 则须满足 ①/② 并重测登记。

### 5.2 最小实验（同 v1 骨架；A 臂 = **0x27**）
S1 烧 0x27 + 身份门（`0x04==0x27`、几何、未实现地址）→ S2 顺序多连接（`--rcvbuf 2920 --conns 6 --maxbytes 200000000`，`--check lane8` 保留给 `mism_bytes`，**判决只用 K0 口径**）+ 环形 pcap → S3 单连接 400 MB → S4 对端就地分析（K0/breaks/prefix_len/mism）→ S5 **负对照臂 = 重烧 0x24（已在盘）同参同顺序**（S-0 同类已证 3/6 + 1/1）→ S6 读计数器 + `W51` 冻结见证。
**合格线（不裁定，只给判据式）**：修复臂**每条连接 `K0==0`**（或全落 `K0≤R` 且残差可解释）∧ 负对照臂**至少一条 `K0≠0`**（A/B 同会话同参同顺序）。
**判别力边界（v1 保留）**：缺陷是概率性的 ⇒ 负对照单轮可 0 条 ⇒ 判"无判别力"、不许判 PASS/FAIL；重跑或加 `--conns`。

### 5.3 工具口径（**v2 重写，M-6 采信**）
- ① **每连接起点相位 K0 本来就是绝对判定**：`align_check2.py:83-88` = `head = gen_pattern(0, 1<<22); K0 = head.find(w0)`（扫绝对偏移 0..4 MB）⇒ **主判据用现成工具即可执行**（v1 的"不修则判据是空的"说过重，撤回）。
- ② **真缺口 = 断点后的重对齐**（`:119-127`：`c = K0 + j ± d, d ∈ [0, 65536]`，且只在 `bp..bp+257` 窗口内找）⇒ 结构性到不了"绝对相位 0"（S0A 的 `UNALIGNED_REST` 即此）⇒ **修法 = 重对齐改绝对锚**（或 `d` 扩到含 `−(K0+j)` 的绝对扫描）+ 把搜索窗口从 257 B 放宽。
- ③ **头上限 4 MB**（`gen_pattern(0, 1<<22)`；`K0 > 4 MB` ⇒ `find` 失败直接返回）⇒ **登记**（大偏移工况会静默退化为"无读数"）。
- ④ v1 写的 `d` 枚举（0..4096 ∪ ±65536 ∪ ±131072）**错**（那是 `stream_zoom.py` 的列表）⇒ 撤回。
- 复算对照（保留）：改完先在旧 pcap 上复算 S0C（应重现 `K0=37960`）。
