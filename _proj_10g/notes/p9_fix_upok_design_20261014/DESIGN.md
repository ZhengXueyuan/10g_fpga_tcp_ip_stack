## §0 三行结论

1. **机制主体成立、但派单描述有一处必须订正的简化**：`up_ok` 的门结构逐字确认
   （`rtl/app_pattern.v:506-507`：`!active || ((up_slot==act_id) && (frm_wait || seg_sent==0))`）；
   连续模式下（会话存活期间）`!active` 臂不可用 ⇒ 换流只可能在"帧间隙"拍被**立即**接受。
   ⛔ **但"否则沿用旧 LFSR"不是今天的全部真相**：构建 E 起有 **A3 补做位**（`up_pend_r`，`:384-385/:777-790`），
   帧间隙外的 `ev_up` 是**延后**而不是丢弃 ⇒ 今天的失效形态是三条：
   **(P-1) 延后到下一个帧间隙**（⇒ 相位在**流中**跳变 = 对端看到 mid-stream break）·
   **(P-2) 被"撤销"丢事件**（`:789-790`，撤销判据分不出"新连接自己关了"与"旧连接 DEL 迟到"）·
   **(P-3) 被接受但复位被同拍装配写覆盖**（`:739` 的 `tx_lfsr<=SEED` 被同一 always 块更晚的 `:909`/`:916` 覆盖）
   —— **(P-3) 是本轮新发现的、默认构建（`TX_CONTINUOUS=0`）也存在的同门真缺陷**。
2. **S-0 板级读数与"P-1/P-3"自洽**（本件复算）：S0C 整条 400 MB = `pattern[37960..]`、`breaks=0`、
   无复位 ⇒ 属 **P-3 形态（复位被静默丢掉、永不再补）**；S0A 非零相位的 **4/6** 条中，
   conn1/conn2/conn5 = `off≠0 + break@1440` ⇒ 属 **P-1 形态**（延后的换流在"数据已开始流"之后的第一个帧间隙才落地），
   conn0（`off=2920`，无断点）与 conn5 的起点 = **P-3 形态**（无缝延续）。⛔ **最后一环（P-3 在冻结态为何能命中那个 1 拍窗口）
   未闭合** —— 见 §1.7/§7，本件**如实登记**，并把"用仪器把它判死"写进 §4/§5（新加 4 个观测计数器）。
3. **推荐修法 ①（先收尾后换流 close-out-then-switch）**：把"同槽 `ev_up`"做成
   **"立刻用 0 载荷 tlast 收掉在飞帧 → 下一拍（active=0 保证 asm_go=0）应用换流"**，并同批
   **换流收尾丢残字（`drop_pw` 扩一项）+ 换流拍禁装配**。该修法**同时消灭 P-1/P-2/P-3 三条路径**
   （结构上：换流应用拍 `active=0` ⇒ `asm_go≡0` ⇒ 覆盖写不可能发生），且**新行为全部包在 `CONT_OK` 常量里
   ⇒ 默认构建（`TX_CONTINUOUS=0`）逐位退化**（§2/§3 给论证与门）。

## §1 机制复核（全部现读自证）

### 1.1 事件源与接线（一句话）

`slow_cfg_adp` 每处理完一条 **ADD 记录**（8 词记录最后一个字段 wscale 的授权拍）发 1 拍 `ev_up`（`rtl/slow_cfg_adp.v:187-198`，
注释逐字 L43-45：`ev_up/ev_down = 1 拍脉冲 (ADD 收尾授权拍 / DEL state=0 授权拍)`）→
`app_ctrl` 的 `ev_up` 输入（`board/wrapper_p4.v:1257-1259`）→ **每个 `ev_up` 无条件转发**为 `o_ev_up` 脉冲
（`rtl/app_ctrl.v:973-978` 逐字 `if (ev_up||ev_down) begin … if (ev_up) begin stat_ev_up<=…+1; o_ev_up<=1'b1; o_ev_slot<=ev_slot;`，
无抑制条件）→ `app_pattern.ev_up`（`board/wrapper_p4.v:1211-1213`）。
**⇒ 源侧/接线侧无丢事件路径（本件现读结论）；EV 丢失若有，必在 `app_pattern` 内部（§1.4）。**

### 1.2 `up_ok` 的精确条件链（逐字）

```verilog
// rtl/app_pattern.v（行号现读 2026-10-14）
:504  wire        up_ev   = ev_up || up_pend_r;
:505  wire [3:0]  up_slot = ev_up ? ev_slot : up_pend_id;
:506  wire        up_ok   = !active || ((up_slot == act_id) &&
:507                                    (frm_wait || (seg_sent == 12'd0)));
:508  wire        up_do   = up_ev && up_ok;
:514  wire        ev_restart = up_do;
```

**三个臂的语义（连续模式下各自的可用性）**：

| 臂 | 何时成立 | 连续模式下的可用性 |
|---|---|---|
| `!active` | app 空闲（W3 收尾完成 / 非连续模式发满） | **会话存活期间恒假**（`active` 只在 W3 收尾 `:811/:819/:827` 与非连续的发满支 `:839-840` 落 0） |
| `frm_wait` | 帧**已整帧交付**、在等 `tx_ok`（信用/窗口） | 窗口受限时每帧都会进（"信用停顿"），可用 |
| `seg_sent==0` | 本帧**一个载荷字节都还没交付**（= 帧首 opener + 首字装载那 1-2 拍 + 整帧收尾后的重装拍） | 每帧一个很窄的窗（宽约 1-2 拍 / 帧周期 ≈ 193+ 拍） |

⇒ **"只在帧间隙成立"精确化**：连续模式下换流的**立即接受面** = `frm_wait`（可能很长，窗口停顿时）
∪ `seg_sent==0`（每帧 1~2 拍）。**在飞帧的中段（`seg_sent≠0 && !frm_wait`，即 app 正在逐字交付的绝大部分时间）
不接受任何换流** —— 这一半与派单描述一致。
⛔ **订正（派单/报告口径）**："`TX_CONTINUOUS=1` 下 `active` 恒 1" **只在"会话已建立且未被 ev_down 拆"的区间成立**；
`ev_down`（对端拆连/DEL）→ `closing` → W3 → `active<=0` 这条路**连续模式下依然活着**（S-0 报告 §2 的
"abort 不可达"说的是另一条源，**不是 DEL**）。这条订正不影响结论，但引用时不许写成"active 恒 1"。

| `:740` | `frm_idx <= 0` | |

⇒ **"新连接流一定从 `pattern[0]` 起"这个性质，全靠在 `:739` 这一拍把 LFSR 写成 SEED** ⇒ 该写被任何东西盖掉/推迟/撤销
= 对端相位错。**对端签名**（`tools/cpp_peer` 与 sink 的共同口径：连接偏移 `o` 的字节应等于 `pattern[o]`）：
`first_mismatch=0`（第 0 字节即错）· `mism ≈ bytes − bytes/256`（两段错流按 1/256 巧合率相符）·
对齐扫描 `K0 ≠ 0` 且 **`K0` 恒是 1460 的整数倍**（因为 app 的"流位置"在任意**帧边界**都是 `N×1460`——见 §1.6 复算）。

### 1.4 三条"事件不落地 / 落地无效"的路径（本件的核心）

#### (P-1) 延后（A3 补做位）—— **不是丢弃，是"晚一拍到一帧"**

```verilog
:777-788  if (up_do) up_pend_r <= 1'b0;
          else if (ev_up) begin up_pend_r <= 1'b1; up_pend_id <= ev_slot; end
:789-790  if (ev_down && up_pend_r && (ev_slot == up_pend_id) && !ev_up)
              up_pend_r <= 1'b0;                       // ← (P-2) 撤销
```

`up_ev = ev_up || up_pend_r`（`:504`）⇒ 未立即接受的 `ev_up` **每拍**重新参与 `up_do` 判定 ⇒
**pending 会在其后的第一个"帧间隙"拍被消费**（`frm_wait` 或 `seg_sent==0`）。
**后果（未闭合前的既有行为）**：若消费拍落在**新连接的数据已经开始流之后**（连续模式下完全可能：app 冻结在新连接
的 slot 上、窗口一开就恢复出数），**复位发生在流中** ⇒ 对端那条连接 = `[旧相位前缀][pattern[0..]]` = **一次 mid-stream 断点**。
**⇒ 与 S-0 的 `off≠0 + break@1440` 形态同构（§1.6 复算）。**

#### (P-2) 撤销 —— 判据分不出"谁关了"

`:789-790` 的设计意图（注释逐字 L780-781）："补做目标槽又来了一次 CONN_DOWN（新连接也关了）⇒ 不再补"。
**但这需要"同一个槽的 ADD 一定先于它自己的 DEL"**。同槽复用场景下（旧连接 DEL 迟到 / 或旧连接的 DEL 根本不发——
连续模式下 app 自己不 close、G2 关闭超时又要求 `fin_sent`（`rtl/app_ctrl.v:74-77`）⇒ **对端单方关闭的连接在本板没有
第二条 DEL 源**）⇒ **一条"旧连接的迟到 DEL"就能把新连接的 pending 撤销掉** ⇒ 事件永久丢失。
其后果分支见 §1.7-③（若该拍 app 仍在 `active`，同一条 `ev_down` 还会置 `closing`（`:797-799`）⇒ app 转 idle ⇒ **A7 静默零数据形态**；
若 app 不在该槽 active，则"丢 pending"无流面后果）。**⇒ 本路径 = 已知 A3/A7 家族，未被任何门覆盖。**

#### (P-3) ⭐ 同拍覆盖写（**静默丢复位**，本轮新发现）

单个 `always` 块内对同一变量多次非阻塞赋值 = **后者胜**。换流块在**前**，装配块在**后**：

```verilog
:832  if (asm_go) begin
:833      if (need == 4'd0) begin ... end                                // 收帧/起下一帧
:870/891  else if (wc_go) ... / else if (a2_ldw && !TAILC_OK) begin
:909          if (!bad_frm) tx_lfsr <= xs_next8(tx_lfsr);   // ← 覆盖 A: 整字路
:910      end else if (bcnt < need_a) begin
:916          if (!bad_frm) tx_lfsr <= xs_next(tx_lfsr);    // ← 覆盖 B: 逐字节路
:917      end
```

**触发条件（可逐项核的充要链）**：换流拍同时 `asm_go=1`。而 `asm_go`（`:540-542`）：
`active && (!pw_valid || (m_tready && !a2_hold)) && !closing && !frm_wait && !op_pend && (frm_inflight||tx_ok||remain==0)`。
结合 `up_ok` 三臂：
- `!active` 臂 ⇒ `active=0` ⇒ `asm_go=0`（**不可能覆盖**）；
- `frm_wait` 臂 ⇒ `asm_go` 含 `!frm_wait` ⇒ `0`（**不可能覆盖**）；
- `seg_sent==0` 臂 ⇒ **可能** `asm_go=1`。具体：`pw_valid=0 ∧ op_pend=0 ∧ op_sent=1`（opener 已交付、首字未装载）
  且 `(frm_inflight=op_sent=1)` ⇒ `asm_go=1`，而此时 `a2_hold = ev_restart = up_do = 1`（`:538`）⇒
  **`a2_ldw=0`、`wc_go=0`（`TAILC_OK=0`）⇒ 装配落到逐字节支 `:916`** ⇒ `tx_lfsr <= xs_next(旧值)`
  **逐个盖掉 `:739` 的 `SEED`**，并把 1 个旧流字节预装进 `stg/bcnt`（`:914-915` 同拍写，晚于换流块的 `:761-762` 清零）。
**净后果**：换流的**行政副作用全部生效**（`act_id` 改了、`pw_valid` 撤了、`frm_wait/closing` 清了），
**唯独"图案流没重开"** ⇒ 新连接拿到的是**旧流从当前位置续下去的字节** —— 正是派单要修的那个现象，
**且此后没有任何东西再补一次复位**（事件已被"接受"，不进 pending）⇒ **整条连接无断点、`breaks=0`**。
**窗口宽度**：首字装载拍每帧恰 1 拍（`a2_ldw` 在该拍必然发射，装载后窗口即闭）⇒ 从"冻结态"看这是**窄窗**；
**但本缺陷在默认构建（`TX_CONTINUOUS=0`）同样结构性存在**（非连续模式的同槽重连也会命中），属潜伏真缺陷，**与连续模式无关地该修**。
⭐ **对端签名的强判别（本件推演，可复算）**：(P-3) 的净效果 = 预装的 `gen_byte` 恰是**流的下一个字节**、
`tx_lfsr` 恰是**流的下一位置** ⇒ **对端看到的是逐字节无缝延续（无任何缺口）**——与"事件从未发生"在字节流上**不可区分**，
但与 (P-1)（断点）**可区分**。S-0 的 conn4→conn5 恰好就是"`off` 逐字等于前一条连接的流长、无缝"⇒ **与 (P-3) 相容**（见 §1.6）。

### 1.5 相位错如何产生（一行机理）

对端按"**每连接从 `pattern[0]` 起**"校验（sink/cpp_peer 的既有合同）。板上 `app_pattern` 是**单会话演示 app**：
它只在**换流拍**把 `tx_lfsr` 复位到 `SEED`。⇒ **任何一次"换流该发生而没发生/发生了但复位被盖"的连接，
都会拿到"旧 LFSR 当前位置续下去"的字节流**：对端第 0 字节即错、整条错、只有 1/256 巧合率相符。
**⇒ 在带 `TX_CONTINUOUS=1` 的位流上，"对端断开→重连"这一类多连接长跑里 `mism_bytes` 不再是内容判据**
（S-0 报告 §4.4 的原始口径：相位错时 sink 口径"对内容全盲"）。

### 1.7 与派单描述逐条对账（**核到不符就说不符**）

| 派单原句 | 判定 | 依据 |
|---|---|---|
| "`up_ok` 只在帧间隙成立" | **符（需精确化）** | §1.2：立即接受面 = `frm_wait` ∪ `seg_sent==0`；在飞帧中段不接受 |
| "`TX_CONTINUOUS=1` 下 `active` 恒 1" | **不符（简化）** | §1.2 订正：仅在会话存活区间；`ev_down`→W3 仍可落 `active=0` |
| "新连接沿用旧 LFSR" | **符（现象）；归因需改写** | 现象 = K0≠0 整条错（S0C 复算）；**"沿用"的通道 = (P-1) 延后 / (P-3) 复位被盖**，不是无条件丢弃（A3 已存在） |
| "连续模式位流上 `mism_bytes` 不再是内容判据" | **符** | §1.5 + S-0 §4.4 原口径 |
| "属已登记 A3/A7「`ev_up` 被吞」家族" | **部分符** | A3 家族 = 事件被吞；**本轮新增 (P-3) = "事件被接受但复位被覆盖"是一个新子类**（且默认构建同样中招） |
| （隐含）"修它 = 改 app 换流门" | **符** | 但**仅改门不够**：必须同批修 (P-3) 的覆盖写，否则修复仍有静默失效路径 |

### 1.8 RX 校验侧影响（上下行语义）

- **TX 侧** = §1.4 三条路径（本轮缺陷在 TX）。
- **RX 侧**：`rx_lfsr` 在 **raw `ev_up`**（`:704-712`）复位、且**与 TX 换流解耦**（A3 注释 L707-711 的理由：
  上行图案按连接起点认，补做拍不得再重置 RX 期望序列）。**⇒ 修法的 TX 侧延后/收尾不得动这条**
  （否则把 raw `ev_up` 之后收到的合法上行字节误判成失配）。**本设计件的修法保持 RX 复位在 `:704-712` 一字不动。**
- 对板侧 `stat_mismatch`（W54）的影响：RX 失配计数与 TX 相位错**无关**（W54 只统计 app 自己的 RX 校验器），
  所以"修复前 W54 是否恒 0"**不能**用来反证 TX 相位错——板级判据必须走**对端**（§5）。

### 候选 ②（备选，改动更小但**不完整**）：只修 (P-3) 覆盖写 + 把 `seg_sent==0` 臂的立即换流改成"等到 `op_pend=0 ∧ pw_valid=0` 的帧首拍"

- **优点**：+3 行；不动 W3。
- **缺点**：**不修 (P-1)/(P-2)** —— pending 仍会在流中落地（断点形态保留）、ev_down 撤销仍能丢事件。

### 候选 ③（不推荐）："种子重锁"（把复位挪到下一个帧首）

- 即"记 pending、在下一帧的第一拍再复位" —— **本质上就是今天的 (P-1) 行为**（延后到帧间隙），
  已由 S-0 读数证明会留下 mid-stream 断点。**不推荐**（仅登记为对照组的自然语言版本）。

## §5 板上判据计划（`mism_bytes` 恢复为内容判据）

### 5.1 口径转换（先说清楚旧口径为什么失效）

- **旧口径（现役 0x24 / S-0 用的）**：sink 的 `mism_bytes` —— **仅在"该连接相位为 0"时有内容判别力**；
  相位错时对内容全盲（S-0 §4.4 原文口径）。**相位校正口径**（`align_check2.py`：先扫 `K0` 再全流比对）
  能补，但它**只证"流 = 图案的一段"，不证"起点正确"**（S-0 §4.4-4 原件逐字）。
- **新口径（本设计件的判据）**：**每连接先定 `K0`，再判 `K0==0`（或以残差上界判"合格前缀"）**：
  ① 取该连接线上载荷 `STREAM[0..]`；② 用**绝对**相位搜索（见 5.3 工具修正）求 `K0`；
  ③ 判据 = `K0 == 0` ∨（`K0 ≤ R` 且 `STREAM[0..K0)` = 旧流残差、`STREAM[K0..] = pattern[0..]` 且全流无断点），
  `R` = **残差上界**（初值取 S-0 实测 **2920 B ≈ 2 帧**，见 §1.6；修复后应重测并登记）。
  ④ **派生判据**：sink 自报 `mism_bytes` —— 若 `K0==0` 则应与 `mism_bytes==0` **同时**成立（两条独立口径）。

### 5.2 最小实验（单轮 ≈ 8-10 min，零构建改造；A/B 两臂）

| 步骤 | 内容 | 时长 |
|---|---|---|
| S1 | 烧 **A 臂**（修复位流 0x25）→ 身份门（`0x04==0x25`、几何、未实现地址、`LnkSta x4`） | ~2 min |
| S2 | 跑**顺序多连接** sink（承 S-0 的 S0A 构型：`--rcvbuf 2920 --conns 6 --maxbytes 200000000`；`--check lane8` **保留**（它给 `mism_bytes`），但**判决只用 `K0` 口径**）+ 环形 pcap 抓 `tcp port 8080` | ~1 min + 抓包开销 |
| S3 | 跑**单连接长流**（S0C 构型：`--rcvbuf 49152 --conns 1 --maxbytes 400000000`） | ~1 s + 开销 |
| S4 | 就地分析（对端）：每连接 `K0`（绝对搜索）+ `breaks` + `prefix_len`（= `K0`，若非 0）+ sink `mism_bytes` | ~1 min |
| S5 | **负对照臂 B** = 重烧 0x24（已在盘），**同参同顺序重跑 S2-S4** ⇒ 预期：至少 1 条连接 `K0≠0`（S-0 同类已证 **S0A 4/6 · S0C 1/1**；⚠️ 单轮可出现 0 条——见下"判别力"）| ~2 min |
| S6 | 读四个机制计数器（若同批构建）+ `W51` 冻结见证 | ~1 min |

**合格线（本件**不**裁定，只给判据式）**：修复臂 **每条连接 `K0==0`**（或全部落 `K0≤R` 且残差可解释）
∧ 负对照臂 **至少一条 `K0≠0`**（A/B 同会话、同参数、同顺序）。若修复臂出现 `K0>R` ⇒ 按
§7 的"未闭合项"处理（先查 (P-1) 是否仍在：读 `sw_apply`/`up_ev` 计数器）。

⚠️ **判别力边界（不许省）**：缺陷是**概率性**的（S0A 有一轮 4/6、另一轮的同类连 1/1，但同轮里 conn3/conn4 是坏的 0/6 形态）
⇒ **负对照臂单轮可出 0 条**（那不等于"缺陷不存在"，也不等于"修复无关"）。规程：
① 负对照臂若 0 条 ⇒ **该轮判"无判别力"**（登记，不许判 PASS/FAIL），加跑一轮或加连接数（`--conns 12`）；
② 两臂必须**同会话、同参数、同顺序**；③ 每个 `K0` 读数必须与 sink 的 `mism_bytes` 同读（§5.1-④）。

### 5.3 工具修正（**必须**，否则判据是空的）

- `align_check2.py` / `stream_zoom.py` 的重对齐搜索是**相对**当前偏移的（`c = cur + (j-st) + d`，
  `d∈0..4096 ∪ ±65536 ∪ ±131072 ∪ 65536±8`）⇒ **结构性地搜不到"绝对相位 0"**（这就是 S-0 里
  `UNALIGNED_REST` 的来源）。**修法**：新增"首 32 字节对 **绝对偏移 0..2^22** 扫描"的直通分支
  （每连接同时输出 `K0_abs` 与 `K0_rel`），并**把 `d` 列表扩到含"−（当前相位）"**（等价于绝对搜索）。
- sink 侧：`--check lane8` 的逐字节口径**保留**（它给 `mism_bytes`），但**判据必须与 `K0` 同读**（§5.1）。
- ⚠️ 工具修正属于本轮的"仪器"改动：**改完先在旧 pcap 上复算 S-0 的 S0C（应重现 `K0=37960`）**——
  复算不出 ⇒ 工具改动有误，判据作废。

## §7 未闭合项 / 边界（**不许当已收口**）

1. ⛔ **(P-3) 在"冻结态"为何能命中那个 1 拍窗口：未闭合**。本件证到"覆盖写窗口 = 每帧 1 拍（帧首字装载拍）"，
   而 S-0 的 S0C 冻结态（`W51` 40 s 不变）**必落在某个确定的冻结拍**——它是否恰为装载拍，本件**无法从源码单独判定**
   （需 §4.3 的计数器 + 一条 ILA/快照序列）。**⇒ 修复设计对"是哪条路径"不敏感（三条全灭）**，但**归因**仍欠一格。
2. ⛔ **S-0 从未做过"同会话 A/B"**（0x24 只有一轮数据，无修复臂）；§5.2 的 A/B 是**第一次**给这条缺陷的板级判决。
3. ⛔ **残差上界 `R` 只有单点实测（2920 B）**；修复后必须重测并登记（这是"修复臂 `K0==0`"判据的容差来源）。
4. ⛔ **`up_slot ≠ act_id`（新连接落到**别的**槽）不在本修法范围**：单会话演示 app 的既有语义 = "其它槽的新事件挂 pending，
   等当前会话结束后再换"（本修法保持）。**若产品目标变成"最新连接优先"，那是另一刀**（改语义，非本缺陷）。
5. ⚠️ **`frm_wait` 在 W3 收尾后不被清**（`:806-829` 无 `frm_wait` 写入；**现读**）——本修法的应用拍恒有 `frm_wait<=0`（换流块写），
   故不受影响；但这是与 `up_ok` 交互的一个**潜伏状态残留**，登记（不在本刀修）。
6. ⚠️ **本件未跑 xsim/Vivado**：所有"预期"均为纸面；**行号、逐字引用与读数复算**为本次现读/现算。
7. ⛔ **引用纪律**：① `P7B_OPEN_ITEMS.md` §0-32 的 `:742 一带` **已过时**（现读 `:735/:739`）；
   ② "`active` 恒 1" 不许照抄（§1.2 订正）；③ 引用相位错必须带"两类形态（断点/无断点）"，
   不许笼统写"app 不重启图案流"。
