## §1 N-1（新洞）登记与修复 —— 折进修法

### 1.1 机制（逐行现读）

- **竞争面**：`rtl/app_pattern.v:922` `if (frm_wait && tx_ok) begin`（块体 `:923-934`：清 `frm_wait`、重装 `seg_len/seg_sent/bcnt`、**`op_pend <= 1'b1`**、`if (cont_reload) remain<=TX_BYTES`）——**该块无 `closing`/`sw_apply` 守卫**。
- **块序**：`:713-775`（换流块）→ `:806-829`（W3 收尾）→ **`:920-934`（本块，在后 ⇒ 同拍重叠赋值它赢）** → `:940-943`（opener 交付）→ `:945`（装配）。
- **其它相关面（无守卫）**：`:476 op_beat = op_pend && !pw_valid && !closing && (seg_len != 12'd0)`（不判 `active`）· **`:671 assign m_tid = act_id`（组合）** · 换流块的 `act_id <= sw_slot` 在**拍末**才落。
- v2 的设计让它成为**换流路径可达面**：v2 把"同槽事件（含 frm_wait 冻结态）"一律改走"收尾→应用"（E6/E7）⇒ **事件落在 frm_wait 冻结态（= S0C 场景同面）时，收尾完成拍与 `:922` 的触发条件天然同面**。

### 1.2 精确时序（v2 无 E13 时）

| 拍 | 发生 |
|---|---|
| **E** | 同槽 `ev_up` 到达（app 在 `frm_wait`：`pw_valid=0 / op_sent=1 / seg_sent=seg_len≠0 / frm_wait=1 / active=1`，`tx_ok=0`）⇒ E6 `sw_pend<=1; sw_slot<=ev_slot`＋E7 `closing<=1`（拍末） |
| E+1… | W3：`close_send=1`（`op_sent=1`）⇒ 0 载荷 tlast 字；`m_tready` 时收尾完成 |
| **T**（收尾完成拍） | W3 拍末置 `active<=0; closing<=0; op_pend<=0; op_sent<=0`；**同拍 `:922` 的条件成立**（`frm_wait` 仍 1——W3 不清它；`tx_ok` 恰在本拍回升 = N-1 条件）⇒ **`:922` 抢置 `op_pend<=1`**（块序在后 ⇒ 覆盖 W3 的 `op_pend<=0`），并用**陈旧 `remain_nxt`** 派生 `seg_len`（换流块的 `remain<=TX_BYTES` 同样拍末才落） |
| **T+1** | `op_beat=1` ⇒ `m_tvalid=1 / tkeep=0 / tlast=0`（早 opener）；而 **`m_tid = act_id` 仍是应用前的旧值**（换流块在 T+1 拍末才 `act_id<=sw_slot`）⇒ `m_tready=1` 时 **opener 以旧 `act_id` 被消费** |

### 1.3 危害（两条）

1. **（采信 kimi）跨连接污染**：opener 在**应用之前**打开帧（帧的连接绑定/seq 取于 opener 拍）⇒ 应用生效后，新会话载荷（新槽）被追加进"应用前那一刻打开的帧"。`sw_slot ≠ 应用前 act_id`（异槽延迟换流）时 = **真跨连接污染**；同槽时至少**违反"opener 只允许在应用拍之后呈现"这条时序不变量**（I3 的时序面）。
2. **（我方补充，同根）帧长污染**：同一抢置用陈旧 `remain_nxt` 派生 `seg_len` ⇒ 新会话首帧长可能 = 旧量子的残余长度（线上帧长异常；量级小但确定性）。

### 1.4 修复 = 新增 **E13**（一行、常量门；v2 表无此项）

```verilog
:922  - if (frm_wait && tx_ok) begin
:922  + if (frm_wait && tx_ok && !(SWC_OK && (sw_pend || sw_apply))) begin
```

**论证（可逐拍核）**：① 拍 E（事件）起 `sw_pend=1` **直到应用拍**（E6 的 `if (sw_apply)` 才清）⇒ 守门覆盖 `[E, 应用拍]` **全程**；② 应用拍后 `frm_wait` 已被换流块清 0（`:755`）⇒ `:922` 的条件自然为假（不需要额外状态）；③ **`SWC_OK=0` ⇒ 门恒真 ⇒ 折叠** ⇒ 默认构建**逐位不变**（§4.3 等价锚不变）。
**⚠️ legacy 同款实例（登记不修）**：`SWC_OK=0` 路径下 `:922` 同样无守卫（kimi 指认"legacy 同款"）⇒ 既存潜伏竞争（`frm_wait`＋W3 收尾＋`tx_ok` 恰在完成拍回升）。**不修**的理由 = 修它即在默认构建引入行为变化、作废"默认逐位退化"锚（本仓纪律：行为变化须独立刀 + 独立锚）⇒ 列入 §7 未闭合项，待"允许默认构建变化"的独立刀处理。

## §2 N-2 处置：**恢复撤销**（删 `!SWC_OK` 门）

- **问题（kimi ✓ 现核）**：v2 的 E6 把撤销行整体加门 `if (!SWC_OK && ev_down && …)` ⇒ SWC 模式下**异槽** `up_pend_r` 失去 A3 撤销，与 v2 §7-4"别的槽 = A3 原语义保留"自相矛盾。
- **裁定 = 恢复原行**（理由三条）：
  1. **撤销对换流路径结构性够不着**：SWC 模式下同槽事件**完全不经过 `up_pend_r`**（走 `sw_pend`）⇒ v2 当初加门想防的"旧连接迟到 DEL 杀掉新连接 pending"**在新结构下不可能再发生**（这正是 v2 的 I2/I4 带来的红利）；
  2. 异槽 pending 的撤销 = **A3 原语义**（"目标槽后来也关了 ⇒ 不再补"）⇒ 保留即一致；
  3. 撤销行是**原代码**（`:789-790`）⇒ 默认构建零影响、且**减少**一处新门。
- **修正后（v2 E6 的撤销行）**：
```verilog
if (ev_down && up_pend_r && (ev_slot == up_pend_id) && !ev_up)
    up_pend_r <= 1'b0;      // = :789-790 原行，一字不动（SWC_OK=1/0 同一份代码）
```

## §6 门计划增量：**u_swc5**（激励 = "frm_wait 冻结态事件"，kimi 点名）

- **构型**：`TX_CONTINUOUS=1` + `TX_SWCLOSE=1`；**与 u_rec 同族（A2 与逐字节两构型各一版**，逐字节构型用于对齐默认构建面）。
- **激励（精确，须写进 TB 注释）**：
  1. `app_tx_ready[slot]=0` 把 app 停在 **frm_wait**（等信用；`m_tready` 保持 1，避免混入背压态）；
  2. **该冻结态**发同槽 `ev_up`（= S0C 场景同面：事件落在 frm_wait 冻结窗内）；
  3. **`app_tx_ready` 的上升沿做 ±2 拍扫描（3 个变体）**，使 `tx_ok` 恰在 W3 收尾完成拍附近回升（覆盖 N-1 竞争窗）；
  4. `m_tready` 全程 1。
- **判据（新增 P-C）**：**自事件拍起至 `active` 回升拍之间，不得接受任何 `(tkeep==0 ∧ tlast==0)` 的字**（= opener 不得早于应用拍呈现）；**P-A ∧ P-B 同判**（新会话载荷仍须自 `8'h9E` 起、自 `up_w` 拍起逐字节 `M_orc==0`）。
- **预期**：**v2 无 E13 实现 ⇒ 红**（`:922` 抢置 ⇒ T+1 早 opener）；**E13 落地 ⇒ 绿**；旧 RTL(HEAD) 该臂**绿**（A3 面，角色 = 锁契约/抓实现回归，与 u_swc3/4 同款如实标注）。
