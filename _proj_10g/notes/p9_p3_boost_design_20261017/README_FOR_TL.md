## §0 三行结论

1. **Q1 根因（一句话）**：**`TCP_RTO_MIN` 的 10,000,000 计的是 HLS 顶层的"主循环 pass"、不是时钟拍** ——
   现网表每 pass ≈ **40 拍**（`dp_clk` = 156.25 MHz，`board/wrapper_p4.v:2498`）⇒ 静默释放周期
   `T = 10^7 × II / 156.25e6 ≈ **2.6 s**（II≈40；不是注释臆想的 80 ms）；而 **P-3 危险事件率 = 1/T（与槽数无关）**
   ⇒ 现 RTL 不变时封顶 **≈0.385/s**。三个槽只是 `MAX_TCP_CONN=3` 的**聚合**准入上限（`3/T ≈ 1.15/s`），
   **加槽不提高同槽事件率**（§1.3 有证明）。
2. **Q1 首选提速候选 = S0「周期性强制静默释放」**（wrapper 宏内把 `hls_rst_n` 按固定周期打脉冲；HLS 复位对
   app 无 `ev_down` ⇒ 3 槽全静默释放 ⇒ 洪水里的 SYN 立即偷槽）**+ S2「C1′ 单 current-fd 读法」**
   （把 app 帧率从实测均值 3.45e-4 拉回窗限峰值 3.35e-3）：**λ = 50/s、P ≈ 3.35e-3 ⇒ E[命中]/120 s ≈ 20**
   （≥3 的 6.7 倍）；臂时长 120 s；**工具 delta = 仅 S2（60–80 行）**，S0 = 一次 wrapper 构建（§3.1/§3.3）。
3. **Q2 判据（一句话）**：**"候选连接全流无针" + "前持有者全流扫描的最后一个重启位置 = `P.bytes − K0`" ⇒ 退化；
   "候选全流无针" + "`K0 = P.bytes − P 的最后重启偏移`（等价 `K0 = P 自上次重启以来的字节数`）" ⇒ 命中相容。**
   ⚠️ **C1 轮 `2/40` 的两条其实已经可以离线分开**（不靠新 dump）：`conn7506` 的前持有者 `conn7501`
   **bytes=1460 且 `restart@off=0`**（= 恰一帧、且流自图案原点起）⇒ **`K0 = P.bytes` ⇒ 命中相容**；
   `conn237` 的前持有者 `conn0` bytes=2.2 GB ⇒ `K0=1460 ≠ P.bytes` ⇒ **退化**（§4.0 详解）。
   命中相容的判据基础 = **`K0` = 前持有者自上次重启以来的字节数**（不是"尾部有没有针"——见 §4.0 的推导）。
   Q2 的工具 delta = **全流滚动针扫描（决定性仪器，比"末 64 KB 环形 dump"更便宜且更强）** + 末 64 KB 环形 dump（字节级复核/前持有者留证）。

## §1 Q1-A：事件率提不上去的根因（逐条源码级 + C1 轮读数闭合）

### 1.1 三个槽 = `MAX_TCP_CONN=3`；16 槽（CAM/app 表）**不参与**这个循环

| 层 | 容量 | 现读锚点 | 与本问题的关系 |
|---|---|---|---|
| HLS 慢路径连接槽 | **3** | `hls/src/layer_tcp.cpp:10-12`（`#ifndef MAX_TCP_CONN` / `#define MAX_TCP_CONN 3`）；`tcp_conn[MAX_TCP_CONN]` `:127` | **唯一准入闸**：新连接必须先有 HLS 槽（收 SYN ⇒ ADD + SYN-ACK），第 4 个 SYN 命中 `tcp_find=-1` 后**静默丢弃**（`:142-148`、`:585` 的 `tcp_stat_no_slot++`，该计数**无端口、不进网表** ⇒ 板上不可见） |
| 快速路径 CAM | 16 | `rtl/tcp_cam.v:7`（`parameter N = 16`） | 只装"已 ADD"的四元组；同时最多只有 3 条 HLS 槽在循环 ⇒ **永远用不到 16** |
| app 侧连接表 | 16 | `rtl/app_ctrl.v:539`（`c_state [0:15]`） | 同上，非约束 |

- 【已证】`tcp_find` 取**最低空闲槽**（`:142-148`）⇒ 槽释放后，下一个到达的（任意源端口的）SYN 立刻偷走它。
- 【已证】churn 工具侧：120 s × 100 连/s = 12,000 次 connect，**只有 140 条进入 ESTAB**（`CHURN_SUM estab_rate_per_s=1.167`，C1a），其余 11,953 条一个字节都没收到（`nodata=11953`）。
  ⇒ 板侧准入率 ≈ **1.15/s = 3 槽 / 2.6 s**（实测 1.17/s，C1a）。

### 1.2 静默释放的唯一通路 = RTO 超时（五条释放路径枚举）

| # | HLS 槽 `state=T_FREE` 的路径 | 是否发 `CFG_DEL`（⇒ app 收 `ev_down`） | 位置（现读） |
|---|---|---|---|
| 1 | **RTO 超时（`T_SYN_RCVD`）** | **不发 ⇒ 静默** | `hls/src/layer_tcp.cpp:514-535`（`rto_timer++` `:515`；`>=c.rto` `:516`；`c.rto*=2` `:519`；`c.state=T_FREE; c.retrans_pending=false; continue` `:531-535`） |
| 2 | 同四元组 bare SYN（P5d-D6 背靠背） | 发（`:609`） | `:608-612` |
| 3 | RST（四元组命中任一槽） | 发（`:637`） | `:631-641` |
| 4 | FIN（`T_SYN_RCVD` 支） | 发（`:699`） | `:696-708` |
| 5 | 复位（`!rst`） | — | `:503` |

⇒ **P-3 危险族（"ADD 落在 app 组装中且 app 未被 `ev_down` 逐出"）只可能走 #1**。C1 的三臂读数支持这一点：
**板侧 FIN/RST = 0**（三臂 ctl pcap）、app 会话跨偷槽存活（handoff 链零间隙，§4.0 的 conn0/conn237 链）。

### 1.3 ⭐ 根因：RTO 计的是 **HLS 主循环 pass**，不是时钟拍（单位错 32–40×）

**机制链（全部现读）**：

1. 被动连接走"**乐观建连**"：`T_LISTEN` 收到 SYN 的**同一 pass** 就 `cfg_write(ADD)` + 发 SYN-ACK
   （`layer_tcp.cpp:668-679`，注释逐字"乐观建连"）；第 3 个 ACK 走快速路径 ⇒ **HLS 永远停在 `T_SYN_RCVD`**
   （`:681-684`）。⇒ 每个被接受的连接 = 一个 `T_SYN_RCVD` 槽 + 一个 `retrans_pending=true`（`tcp_send` 的
   `flags&TCP_SYN` 支 `:307`）+ `rto=TCP_RTO_MIN`（`:619`）。
2. `TCP_RTO_MIN = 10000000`、`TCP_RTO_MAX = 80000000`（`:39-42`，注释"~80ms min RTO"）。
3. RTO 扫描 `rto_timer++` **每 pass 只加 1**（`:514-516`），且只在 `!ip_rx.valid||ip_rx.protocol!=6`
   的调用里跑（`:505`）。
4. **现网表的两条 `tcp_rx_process` 调用点都带"有效的 TCP 帧"**（`hls/src/udp_echo.cpp:181` 与 `:249`-系）⇒
   扫描分支结构性够不着；**唯一的空闲 tick 在 `#if ACTIVE_CONNECT` 里**（`udp_echo.cpp:254-267`：
   `if (!do_process && !tcp_proc_pending && !mac_tx_busy && !tx_req.request) tcp_rx_process(idle)`）。
5. ⭐⭐ **现板级 netlist 就是 `ACTIVE_CONNECT=1` 那一版**（详见 §1.4）⇒ **空闲 tick 在** ⇒ RTO 扫描活着。
6. HLS 时钟 = `dp_clk` = **156.25 MHz**（`board/wrapper_p4.v:2498` `.ap_clk(dp_clk)`）；ap_ctrl_none 自由运行，**一个 pass = 顶层的 II 拍**。

**计算**（唯一未知量 = pass 拍数 II，由实测反推）：

```
T_release = N_rto × II / f_clk
实测 T_release ≈ 2.6 s（见下读数），N_rto = 10^7，f_clk = 156.25 MHz
⇒ II = 2.6 × 156.25e6 / 1e7 ≈ 40–41 拍/pass
```

**两条独立实测读数（C1 轮，0x28 与 0x24 两代、两个时长）**：

| 臂 | 同槽事件计数 | 时基窗 | 速率 | 反推 `T_release` |
|---|---|---|---|---|
| C1a（0x28，E12 直读） | **`ΔW72`=47** | `ΔW5` = 124.907 s（C1 §2 时基自证） | 0.376/s | **2.66 s** |
| C1b2（0x24，**无 E12**，工具侧"收到数据的连接数"） | **116**（= off0 84 + offk 4 + cand 28；`CHURN_SUM`） | 300 s 连接窗 | 0.387/s | **2.58 s** |

（两臂 ~2.6 s；II = T×f/N = 2.6×156.25e6/1e7 ≈ **40–41 拍/pass**。）

**与"3 槽"的闭合**：聚合 `ev_up` 率 = `3/T` ⇒ C1a `ΔW71` = 144/124.9 s = **1.153/s** vs `3/2.66` = 1.128/s ✓；
C1b2（`0x24` 无 E12）用工具 `estab` = 299/300 s = **1.00/s** 作聚合代理（落在"2–3 槽有效"的 0.77–1.15 档 ⇒
**不能排除偶发一槽退出循环**，见 §1.5）。
C1a 的 `ΔW72 : ΔW74 = 47 : 96 ≈ 1 : 2` ⇒ **app 的会话只钉在一个槽上，另外两个槽的偷槽 = 异槽事件（`W74`）**。
⇒ **同槽事件率 = 1/T，与槽数 N 无关**（`N` 只抬高 `ΔW71/ΔW74` 的聚合背景）。**⇒ 把 `MAX_TCP_CONN` 从 3 提到 16 对 P-3 无效**（§3.4）。

**历史旁证（同一 s 级 wall time）**：`agent_docs/PORT_NOTES.md:768-769`（P4b-5 板测，2026-08-30）逐字
"**RTO = 10M pass ≈ 2.6s (@~32 拍/pass)**"——125 MHz 时代 32 拍/pass、156.25 MHz 现网表 40 拍/pass，
**wall time 都是 ≈2.6 s**。⚠️ 该句所在的 P4b-5 era 与"扫描可达性"的源码链有一处**未解矛盾**（那一代
`udp_echo.cpp` 只有两条带有效 TCP 帧的调用点，见 §6-U1）——**只作 wall-time 旁证，不承重**。

### 1.5 槽是否被"慢路径 ACK 推进 `T_ESTABLISHED`"而退出循环（C1 研究件风险 r1 的现读确认）

- **路径在**：`layer_tcp.cpp:680` `case T_SYN_RCVD: if((flags&TCP_ACK)&&ack==c.seq){c.retrans_pending=false;c.state=T_ESTABLISHED;…}`。
  一旦进入 `T_ESTABLISHED`，该槽**没有静默释放路径**（只有 FIN/RST 的 DEL 支）⇒ 永久退出循环。
- **为什么板上够不着**【推断（源码链）】：`rtl/rx_classify.v:110-118` 把纯 ACK 送快速路径；而 ADD 在 SYN-ACK
  **之前**就写进 CAM（`layer_tcp.cpp:677-678` 注释逐字"cfg 必须先于 tcp_send"）⇒ 第 3 个 ACK 必然命中 CAM ⇒ 不进 HLS。
- **读数侧上界**【已证（减法）】：若有一个槽永久卡在 `T_ESTABLISHED`，聚合准入率会掉到 `2/T` ≈ 0.77/s；
  C1a 实测 1.153/s（≈3 槽）、C1b2 1.00/s（≈2.6 槽）⇒ **整体按 3 槽在循环**；300 s 臂的 1.00/s 已略低于
  `3/T`=1.15 ⇒ **"偶发一槽退出/被复位"不能排除**（见 §2/§3.1 的复位讨论），但**不影响同槽率**
  （同槽率只由 app 所在槽的 T 决定）。

## §2 Q1-B：≈2.6 s 周期的来源 / 能否缩短（现读 + 计算）

**来源（三层）**：
1. `rto_timer` 的步进 = **HLS 顶层 pass**（`layer_tcp.cpp:515`，每 pass 一次），不是时钟拍；
2. 触发值 = `c.rto` 初值 `TCP_RTO_MIN = 10,000,000`（`:619` / `:39-41`）；
3. pass 拍数 II ≈ **40**（§1.3 反推；历史 125 MHz 版 ≈32，`PORT_NOTES.md:769`）。

**计算**：`T = 10^7 × II / f_clk`；II=40、f=156.25 MHz ⇒ **2.56 s**；实测 2.58 s（C1b2）/ 2.66 s（C1a）
⇒ II ≈ **40–41**（§1.3 两臂）。

**能配置/缩短吗**：

| 旋钮 | 现状 | 可行性 |
|---|---|---|

**做法**：`hls` 以 `-DTCP_RTO_MIN=<N>` 重建 netlist（`#ifndef` 缩比入口现成，`:39-41`），再走一次板级构建。

### 3.3 S2（与 S0/S1 相乘的 P 杠杆）C1′ 单 current-fd 读法

**做法**：churn 工具新模式（≈60–80 行）：连接仍以 100/s 洪流建立并**持有不关**，但**只把"最新建立且已收到数据"的 fd

**推算**：app 帧率从实测均值 54.7k/s 回到窗限峰值 ≈ 524k/s ⇒ **P：3.45e-4 → 3.35e-3（×9.7）**；
事件率不变（仍 = 1/T 或 1/周期）。
**风险**：① 旧 fd 不读 ⇒ 旧连接窗口关闭（**无影响**：app 只向 current 发）；② "current 切换"判据要稳（收到 ≥32 B 才切）；
③ fd 数仍随臂长增长（`ulimit` 照旧）；④ **C1′ 是工具行为差异 ⇒ 必须带 `CHURN_OPTS current_only=1` 见证**，且 C1 臂的 P 口径不可与它混用。

### 3.4 S3（**否**）`MAX_TCP_CONN` 3→16

**证明为什么不提同槽率**：同槽事件 = "app 所在槽被偷"。app 只钉一个槽（`act_id` 单值，`rtl/app_pattern.v:549-554`），
该槽的循环周期 = `T_release`，与 N 无关；N 只抬高**聚合** `ΔW71 = N/T` 与背景 `ΔW74`。**⇒ S3 对 P-3 无效，
且把背景事件率抬高 5.3×（增加 app 收尾/背景负载）⇒ 不采用。**

### 3.5 S4（理论极限，工程否）事件与帧循环"锁相"

**建模**：P = (每帧危险拍数 = 1)/(帧周期) = fps/f_clk（均匀相位）。若事件周期 ≡ 帧周期的严格整数倍且帧周期
零漂移，则相位可固定 ⇒ **P → 1**（上限；相当于把命中率抬 193×，S0@50/s 时 E/120 s → 6,000）。
**为什么不做**：① 帧周期不是常量（§1.7 实测 765→30 MB/s 漂移，窗口/重传随时改变帧周期）；
② 锁相需要闭环相位观测（板侧没有"帧相位"计数器）⇒ 只能开环猜周期；
③ 收益放大器已经由 λ（S0 的周期）提供，代价远低。⇒ **不采用；仅登记为"若将来 app 有固定 gap 模式（TX_GAP）可再议"**。

## §4 Q2：2/40 分离实验（把"真命中"与"退化情形"分开）

### 4.0 ⭐ C1 原始数据里已经有"退化"的指纹 —— 先把已能离线定的部分定掉

C1 轮把 2/40 的两种解释判为"字节级不可分"（`p9_c1_board_20261017/README_FOR_TL.md` §4.5）。
**本件现读三臂的逐连接行（`raw/C1{A,B,B2}_churn.txt`）后发现：其中至少两条可以用"前持有者的字节账"直接分开**：

| 候选 | K0（离线 align） | 前持有者 P（窗链，`t_last(P) ≈ t_first(C)`） | P 的 `bytes` | P 的 `restart@off` | 判定 |
|---|---|---|---|---|---|
| **C1b `conn7506`** | **1460** | **`conn7501`**（last_rx=48,966.657；按 conn7506 的 43.4 MB/≈26 MB/s 反推其窗首 ≈ 同一时刻 ⇒ 零间隙【推断（窗口对账）】） | **1460（= 恰一帧，`reads=1`）** | **0** | ⭐ **`K0 == P.bytes`** ⇒ **"交接未重启"相容（命中相容）**；退化要求 `P.bytes > K0`（旧流+一帧）——**被 1460 的上界排除** |
| **C1b2 `conn237`** | **1460** | **`conn0`**（首持有者，窗 0→2.37 s；C1 轮 §5-④ 已证该臂 handoff 链零间隙） | **2,208,803,640** | 0 | **`K0=1460 ≠ P.bytes=2.2e9`** ⇒ 若为命中，K0 应 = P 自上次重启的字节数（2.2 GB）⇒ **命中被排除 ⇒ 退化**（重启帧在 P 流末尾） |

⚠️ **conn7506 的残余第三解释**：也可设想"交接重启帧被**丢弃**（既不入 P 也不入 C），C 恰从第 2 帧接入"——该形态与
hit 在字节上同形，**本判据不覆盖**（登记为 §5-U11；若需要，用 app 发帧计数 `W52` 与对端接收帧数的差证伪/证实）。

**判据的物理基础**（本件核心推导，逐条可核）：
- **命中（0x24 覆盖）**：事件在装载拍应用，`tx_lfsr<=SEED`（`rtl/app_pattern.v:832`）被同拍装配写
  （`:1034`，逐字节支，块序在后）盖掉 ⇒ **图案流不重开** ⇒ 新连接的 `K0 = 交接时的流位置`，
  而 `交接时的流位置 = 前持有者自上次重启以来累计收到的字节数`（流连续、每帧 1460 B、装载拍相位必在帧边界 ⇒ K0 必为 1460 的整数倍）。
- **退化（干净重启+首帧发旧持有者）**：重启发生在交接前 ≤1 帧 ⇒ 前持有者流 = `[旧流…] + pattern[0..K0)` ⇒ **P 的最后一个重启位置 = `P.bytes − K0`**。
- 两者**都由 `K0` 与 `P` 的字节账判定**——前提是**知道 P 的最后重启位置**。C1 的 64 KB 前缀 dump **只测候选、不测前持有者** ⇒ 缺的正是这一格（不是"尾部字节"本身）。

### 4.1 工具 delta `p7b_tcp_churn` v3（规格；未实施）

**A. 全流滚动针扫描（决定性仪器；默认开 `--scan-all 1`）**
- 每个连接的**全部**接收字节都过滚动扫描（32 B 针，跨 chunk 保留 31 B 重叠；针由 `P7bPat(0)` 生成，不手抄常量），
  记录：`needle_first_off`、`needle_count`、`needle_last_off`、**每次出现的偏移（≤ `--needle-max` 条，默认 64，溢出记 truncated）**。
- 报告行新增：`full_scan=1 first_needle=<off|−1> hits=<n> last_needle=<off|−1> scanned=<bytes>`。
- 语义升级：**`hits==0` ⇒ "该连接全流无重启"**（把 C1 的"首 4 KB"升级为"全流"；这是 Q2 判据的承重件）。
- 成本：流式 memchr 首字节（0x7F）过滤 + 32 B memcmp ⇒ 在 765 MB/s 下可忽略（【推断】；v3 自测里加吞吐见证）。

**B. 末 64 KB 环形 dump（`--tail-kb` / `--dump-tail-dir`；字节级复核 + 前持有者留证）**
- **环形缓冲**：每连接首个数据字节到达时懒分配 `tail_cap = tail_kb×1024`（默认 64 KB）的环形；写指针回绕；
  只保留**最后** `tail_kb` KB。总量上限 `--tail-total-mb`（默认 256 MB）⇒ 超限打 `CHURN_TAIL_LIMIT` 并响亮计数（`tails_skipped`）。
- **落盘触发**：① 连接结束（EOF/RST/err）；② 臂结束（`--hold-s` 窗口末，仍打开的 fd 全落）；③ 供链分析用，
  **每个"收到过数据"的连接都落**（不只候选）——C1 的教训：关键证据在前持有者身上。
- 文件与清单：`<dir>/churn_tail%06lld.bin`（按时间正序的**最后** min(bytes, tail_kb) 字节）+ 清单行
  `CHURN_TAIL conn=<k> file=… bytes=<total> tail_len=<n> t_first=<s> t_last=<s> first_needle=<off|−1> hits=<n>`。
  ⚠️ `t_first/t_last` 用**进程启动起算的绝对秒**（现役 `last_rx_ms` 字段的语义是 `t_fin − t_last_rx`，**不是绝对时刻**，
  见 `p7b_tcp_churn.cpp:739-742` 的 printf 实参——v3 必须新增 `t_first_rx` 字段并写绝对时刻）。
- **与 `--dump-prefix-dir` 的关系**：两条**独立**；prefix 仍只落"候选（`restart@off=-1`）的首 64 KB"（现役行为不变，
  下游解析不受影响）；tail 落"所有有数据连接的最后 64 KB"。二者合用 = 候选的首与尾、前持有者的尾三件齐。
- **默认值**：`--tail-kb 64 --dump-tail-dir 无 --scan-all 1` ⇒ 不给目录则不落盘（与现役 `--dump-prefix-dir` 同纪律）。
- **自测（v3 必须过）**：① 环形正确性（构造 >2×cap 的流，落盘 == 流的后 cap 字节，含回绕点）；② 针扫描（针在 0/中段/跨 chunk/无/半针/翻 1 bit，与现役 11 条单测同构）；
  ③ 清单时刻的绝对性（与 `--selftest` 自带时钟对账）；④ 边界值（tail-kb 越界、目录不存在、总量超限、`--needle-max` 越界）⇒ RC=2；
  ⑤ **不改现役行格式**（`CHURN conn=` 前四字段与 `CHURN_SUM` 的既有键不动）。

### 4.2 判定算法（离线 `p3_sep.py`；规格）

**输入**：per-conn 行（bytes、`t_first`、`t_last`、`restart@off`、full_scan 字段）+ `CHURN_TAIL` 清单 + tail 文件 + 图案生成器（`P7bPat`）。
**步骤**：
1. **链**：按 `t_first` 排序，对每个"有数据"连接 C 找前持有者 P = `argmax t_last(P)` 且 `t_last(P) ≤ t_first(C)` 且
   `t_first(C) − t_last(P) ≤ --chain-gap`（默认 5 ms；C1 实测 gap 多为 0）。无 P ⇒ **未判定（链断）**。
2. **全流无针**：C 的 `hits` 必须为 0；否则 **非命中**（事件被延后应用 ⇒ 该连接有自己的重启）。
3. **K0**：由 C 的 prefix（或 tail 若 prefix 不可用）离线 align 求 `K0`（现役 `c1_align.cpp` 语义，任意偏移）。
4. **分类**（**事先钉死**）：
   - **J-退化**：`P` 的全流扫描显示其**最后一次针出现**在偏移 `o`，且 `P.bytes − o == K0`（等价：**重启发生在交接前恰好 K0 字节**），
     且（可选）tail 的末 K0 字节逐字节 = `pattern[0..K0)`。⇒ **"干净重启，首帧（K0 字节）落在旧持有者"**。
   - **J-命中**：`P` 的全流扫描**在近端无针**（最后一次针若存在，则 `P.bytes − o` ≠ K0 且远大于 K0），
     且 **`K0 == P.bytes − (P 的最后重启偏移)`**（即 **K0 = P 自上次重启以来的字节数**；P 无针时取 `P.bytes`），
     且 tail（若已落）的末 `min(L, K0)` 字节逐字节 = `pattern[K0−L..K0)`（`L=tail_len`）。⇒ **"交接未重启"相容**。
   - **未判定**：链断 / tail 不足 / P 的扫描 truncated / 两者都不满足。
5. **汇总**：逐候选一行 `SEP conn=<k> K0=… P=… P.bytes=… P.last_needle=… class=HIT|DEG|UNDET reason=…` + 类别计数。

### 4.3 臂表（哪个位流/构型复现率最高）

### 4.4 事先钉死的判据与两种结局的含义

**判据（Q2-A，逐字，先于跑）**：
> 对每个候选 C（`restart@off=-1` 且 `hits==0`）按 §4.2 分类。
> **判定式（不裁定）**：Q2-A 全部候选的 `class` 分布 = 读数；
> **"退化解释成立"** ⟺ 对 C1 的两条 `K0=1460` 候选（若在 Q2-A 复现）分类为 `DEG`；
> **"命中相容"** ⟺ 存在候选分类为 `HIT`。

**两种结局的含义（写死）**：
- **全部 DEG**：`2/40` 的"字面命中" = **退化背景**（干净重启首帧落旧持有者）；P-3 命中在 0x24 上**仍无正见证**
  ⇒ 0x24 的 P-3 复资格问题继续挂账；下一步只能靠 Q2-C（S0 提速臂）做统计判别。
- **存在 HIT**：**首次拿到 P-3 窗口的直接字节级正见证**（`K0 = P 自上次重启字节数` + 全流无针 + P 尾逐字节 = 流前缀）
  ⇒ 0x24 的判别力恢复；且 P-3 的"覆盖写"从 xsim 正控升为板级观测（⛔ 仍不写 PASS；裁定权在 TL/用户）。
- **混合**：按类计数报出（这是最可能的结果形态）。

### 4.5 要不要与 Q1 的提速臂同批（一次板级轮）？

**建议：工具同批、臂分批（同一窗口内可做两臂）。**
1. **v3 工具是两条线的公共前置**（Q2-A/B 与 Q2-C 都要它）⇒ **先做工具（零构建、纯工具自测）**。
2. **Q2-A（0x24）不需要任何构建**（位流在盘、C1 轮已烧过两次）⇒ 可立即执行（300 s + 离线 ≈ 1 h）。
   **先把 2/40 分类掉**，避免把"提速臂"与"一个未解释的背景"绑在一起。
3. **S0 构建**与 v3 工具可并行（不同 owner、不同文件面：wrapper vs `_proj_pcie/p7b_biz`）；**板级臂必须串行**
   （两次烧录：0x24 → S0；且构建期间不得烧位流——全局纪律）。
4. **不建议把 Q2-A 与 S0 臂合成一个构型**：S0 改变了事件发生器与事件率（50/s），**候选背景率也会变（未测）**，
   Q2-A 的价值恰在"与 C1b2 逐字同条件"的可复现性；混批会让"2/40 的类型"失去对照。
