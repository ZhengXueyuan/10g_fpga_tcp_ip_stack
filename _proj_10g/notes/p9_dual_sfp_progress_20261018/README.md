## 3. 关键设计结论（截至 2026-10-17）

- **ch0 不是 PCS/GT 死端口【已证·源码】**：`pcs64` 是 2 通道核（`NUM_OF_CORES=2`，LANE1=X0Y4 / LANE2=X0Y5）；ch0 TX 由**常量 IDLE 寄存器**驱动（`board/wrapper_p4.v:601-608`）；ch0 RX 数据 `rx_mii_d_0/rx_mii_c_0` **无消费者**（仅状态 XOR 折叠成 W39[30]）；数据面单实例只挂 ch1。所谓"死" = 数据面未接，不是 PCS 能力缺失。
- **P1 范围（两模式共同基础）**：给 ch0 挂**第二只 `mac_rx_10g`**（`_proj_10g/p7b_mac/rtl/`）+ 固定 76 位 RX tap + 真实 sink；**PCS/GT/参考钟/复位序列零改动**；**ch1 数据面零改动**；不改流宽/CAM/TCB；ch0 TX 保持常量 IDLE。
- **观测面** = **+7 字（W76..W82）**：ch0 PCS 状态 / PCS 事件（BER 代理）/ LOS+模式 / RX 好帧 / 载荷字节 / FCS 错 / 丢帧 ⇒ **83 字 / UNIMPL `0x17C`**（以 0x2A 的 76 字为基）；纸面成本 ≈ **+1.5k LUT / +1.8k FF / 0 BRAM / 0 URAM**。
- ⛔ **P1 必需的新机制 = 快照汇合超时**：ch0 计数束 `clk_b = rx_clk_out_0`（CDR 恢复钟）；拔线/LOS 停钟时若无超时，整个 83 字窗口会永久不可读 ⇒ 逐代 arming + 4096 拍超时 + `SNAP_STATUS[7]` 标"ch0 束陈旧"。（既存 `u_snap_p7bfe` 有同类风险，P1 不修、登记。）
- ⭐ **甲模式 = 无标签路线**：用户"甲方案单独 IP"使**帧的 IP 头天然携带端口身份** ⇒ RX 侧不需要 77 位端口标签、CAM 不需要 +1 位；出向按 CAM 的 `dip`（本地 IP）选口。同 IP 双口/未来 N 口才回到 plan §2-S2 的端口标签方案。
- **模式开关与 BID**：单开关 `SFP2_MODE_B`（甲 = 未定义 / 乙 = 定义）+ elaboration 硬门；BID 甲 = `0x2B`、乙 = `0x2C`；**P1 建议只建甲**（乙位流等 P3 有镜像通路再建）。
- ⛔ **门覆盖盲区【已证·源码】**：矩阵 `p5_wrapper` 只编 `APP_MODE`（不编 `P7B_10G`）、`p6e` 不编 `P7B_10G` ⇒ **P1 的 ch0 逻辑只有 `_proj_10g/p7b_chain/` 门能看见**；建议注册为矩阵第 20 门。
- **P1 基代 = 0x2A**（用户 2026-10-17 18:38 裁定 0x2A 转现役；19:17 已烧录）。

## 4.1 P1 审查结论（2026-10-18 00:41，红队；全文 = `p9_review_dual_sfp_p1_design_20261018/FINDINGS.md`）

- **分级**：阻断 0 / 高 7 / 中 20 / 低 10；**事实核严格不一致 11 项**（含 plan 的 **17 处行号 = 0x28 树**、对 HEAD 漂移 +35…+110）+ 需限定 6 项；TL 抽核 **9/9** 与报告一致。
- **最重要 3 条**：
  1. **高-3/4**：TX **端口位没有物理通路**（两级 `tx_arb` 73 位硬编码，split 在其后）；**A-1 需把 `tcp_tx_frame` 的 `cfg_src_ip` 6 组用途**（帧头 / IP 校验 / TCP 校验种子；`TCP_TX_OVL` 双体）改成 per-connection；且 **A-1 与用户 §0.5「其余按推荐（CAM+1 位）」冲突 ⇒ 需重裁**，"最小改动"口径不成立。
  2. **高-1/2**：S2 单栈 + 单条 10G 线 + 共享 `WIN_POOL` ⇒ **聚合上限约 9.5 Gbps**，"每口满速"判据结构上不可满足；RX 合并器若照抄严格优先会**饿死低优先口**（合并前 FIFO 256 字 = 1.36 帧）。
  3. **高-5/6**：快照超时机制必须**把 `ch0_busy` 排除出 `snap_busy`** 并在 `snap_req` 清 `snap_main_seen`；**DP 域 FF 预算实为约 223**（非 ~110）、pcie 域 **448**（非 320）——0x2A 全局 WNS 宿主正是 DP setup（0.61%）。
- **空判据 E-1…E-10**：`vcc_cyc` 饱和（W77 必增）、`carrier_changes +1`（P0 实测 +3）、LOS 沿极性未定义、温度/功耗无板上仪器、P2 守恒律计数未同批、NIC pad 口径未核、`snap_take` 无失败判据等。
- **新增待裁 7 条**：A-1 冲突 · S2 聚合目标口径 · 共享 `WIN_POOL` 代价 · `cfg_src_mac` 是否 per-port · 乙镜像是否含 FCS/元数据 · 乙背压语义（丢整帧 vs 停 RX）· 第二 IP 地址值。
- **下一步**：**用户裁定**（A-1 路线、S2 目标、乙目的地、HLS 两 IP 授权、观测档位等）→ **设计修订轮**（修 3 类高优先 + 中项 + plan 行号/判据重写）→ 复审 → P1 实施。

## 6. 待用户裁定（2026-10-18 更新：已裁 5 条 / 在分析 2 条）

**已裁（用户 2026-10-18）**：
1. **观测档位**：功能开发期间 **7 字（W76..W82）全部实现**；功能测试完成后拆掉、只留最小集（最小集内容待定）。
2. **乙模式口径**：只镜像第一个口的 RX、从第二个口发出；**不转发 TX**；与 PCIe 无关。
3. **HLS 两 IP 改造**：**已授权**，但必须同时支持 **1 个或 2 个端口**（单口零回归）。
4. **目标 = 2×10G 同时满速**（与 §0.5 不做 S1/独立池冲突，等双栈代价分析后重裁）。
5. **甲模式出口身份**：要求比较 CAM+1 与 A-1 的**流程/耦合/延时**后定（两方案均可建连时绑定出口）。✅ **已裁（2026-10-18）：采用 A-1（IP 即身份）** —— S2 单栈下需完整 A-1 改造（wrapper 16 槽端口位 + `tcp_tx_frame` 源 IP/校验和 + 74 位 arb/前移 demux）；S1 双栈下退化为"每实例接自己的常量 MAC/IP"。

**分析结论（2026-10-18，两件均已完成）**：
- `p9_dual_sfp_exit_identity_compare_20261018/` —— CAM+1 vs A-1。✅ **推荐 A-1**（流程更短 / 耦合更低〔≈9 vs 14 个 RTL 文件、~11 vs ~20 接口点〕/ 延时打平〔稳态 0 拍〕/ 1-2 口更自然）；**决定性证据**：CAM+1 的"物理口"在本架构没有现成写入源（HLS 记录只有 `w2=local_ip`、`tcp_synp` 已废除）⇒ 从 IP 派生则与 A-1 冗余，要真物理口需新增 SYN 标签表。**共同结构债**：TX 侧 1 位必须穿过两级 `tx_arb`（74 位或前移 demux）。**门债**：`p7b_chain` 不编 `TCP_TX_OVL`、OVL 门跑不通 ⇒ TX 改动目前无门覆盖。
- `p9_dual_sfp_s1_cost_20261018/` —— S1 双栈代价。✅ **推荐 B/C2**（双快路径 + 单份双 IP HLS + 每口 8 连接×64 KB 分区），增量 **+32–34k LUT / +19–20k FF / +19 BRAM / +0 URAM / +0 DSP**（纸面）⇒ 总计 ~110–112k LUT（51%）/ ~94–95k FF（22%）/ **367/480 BRAM（76.5%）**；**头号风险 = 时序 0.61%**；关键订正：**双栈下 `cfg_src_ip/mac` 每实例接自己的常量 ⇒ 不需要 per-connection 校验和改造**（S2 审查高-4 在双栈下消解）。
- ⭐ **两件交汇**：若选双栈，出口身份退化为"每套实例接自己的常量 MAC/IP"（最短路径）；A-1 的完整改动只在 S2 单栈路线下需要。

**仍待裁/确认**：
- S1 双栈 vs S2 单栈（取决于 2×10G 代价结果）。
- BID `0x2B`（甲）/ `0x2C`（乙）。（可由构建纪律决定）
- `p7b_chain` 是否注册为常驻矩阵第 20 门（门所有者可定）。
- LOS 负对照方式（物理拔 AOC vs 对端 `ip link down`）。
- 乙位流是否暂缓到 P3（建议暂缓）。
- ch0 TX MAC（甲不建；乙必需）。

## 7. 风险登记

- **时序**：0x2A 余量仅 0.61%；P1 新增 ch0 时钟域 + DP 域 ~110 FF + pcie 域 7 字阵列 ⇒ 一次构建收口，backstop 顺序已预登记。
- **空判据**：LOS/停钟/无流量计数类判据必须先审"是否有判别力"（审查轮专项）。
- **门覆盖**：P1 的 ch0 逻辑在现有矩阵里不可见（只有 `p7b_chain`）；未入册前构建通过 ≠ 逻辑被门覆盖。
- **双口共存（P2/P3）**：合并器帧序/守恒律、双板 IP、HLS 两 IP 改动的真实成本未测。
- **乙模式**：镜像源范围/目的地未定；无 IP 与慢路径的隔离边界需 P3 设计。
- **既存同险**：`u_snap_p7bfe`（ch1 停钟）同类风险未修、仅登记；ch0 超时机制若验证有效可考虑泛化。
