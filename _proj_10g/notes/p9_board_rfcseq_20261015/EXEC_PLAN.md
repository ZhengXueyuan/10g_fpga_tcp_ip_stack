## 0 §7.2 现读摘录（逐字，执行依据）

- **分歧域（v3 双侧/真差口径）** = 真差 `D = seq − rcv_nxt`（普通整数）**∉ [−2³¹, 2³¹−1]**。
- **注入两条配方（任选一；已逐例复算 ⇒ 目标向分歧 + `seq_lt_rfc=1` + 旧式 `seq_lt_abs=0`）**：
  - **配方①（减式）**：`seq = (rcv_nxt − Δ) mod 2³²`，**`Δ ∈ (0, 2³¹)` 且 `rcv_nxt < Δ`** ⇒ `D = 2³² − Δ > 2³¹`。
  - **配方②（加式）**：`seq = rcv_nxt + Δ`，**`Δ ∈ [2³¹, 2³² − rcv_nxt)`**（上限防 mod 回绕）。
- **⭐ 全局可行性注（v3r2 新增 / v3r3 订正不等号）**：**目标向注入存在 ⇔ `rcv_nxt < 2³¹`**（两条配方都受此约束）。
  **实操 = 开新连接即可满足**（新 ISN）；若 ISN 落上半环 ⇒ 重开连接（或让板先收 ≤2 GiB 越过 2³²）。
  ⛔ **两条都没做就注入 ⇒ 只能构造反向域（`D < −2³¹`）—— 那不是目标向 A/B 的判别，别读成"修复未生效"（防伪阴性）。**
- **段本身必须合法**：同 4 元组 / flags=ACK / doff=5 / IP csum / FCS 正确 ⇒ 过 `base_ok`；payload 100 B（"数据段"支）。
- **两臂**：
  - **负臂 = 修复前（设计件原文 = 现役 `0x24`）**：预期 **静默** —— 线上**无**板侧 ACK，`ΔW23`（`rx_stat_nonmatch`）**+1**；
  - **正臂 = 修复位流（设计件原文 = BID `0x26`）**：预期 线上**出现**一个板侧 ACK（`ack = rcv_nxt`），`ΔW23` **不增**（该类改落 `stat_drop_seq`）。
- **承重件（防"静默"是空判据）**：负臂的 `ΔW23 +1` 同时是"注入帧真被板收到并分类"的见证；正臂的 ACK 见证 = 对端嗅探器抓到板侧帧（`stall_probe` 已有 `POST_INJECT_BOARD_FRAME` 日志）。
- **前置**：`0x08 = 0`（`carrier=1`）· 一条 ESTAB 连接 · 对端 raw 注入路径可用（`AF_PACKET`）· 注入帧 `rcv_wnd` 无关但必须过 `base_ok`。
- **③**：注入不可行/不可复现 ⇒ 板级口径 = **"未观测到"（空判据）**，不许记 PASS/FAIL。
- **④**：本实验**只证分支选择**（回 ACK / 不回），**不证**"回卷长流不再受伤"。

## 0b 注入器现读（设计件附录 A 逐字指定）

- 设计件附录 A：**`p7b_persist_board_20261011/_tools/stall_probe.py` = 板测注入器原型（§7.2）**（md5 `2274c15975e78307dc9d9b286da03ffb`，本机现核）。
- 原型能力 = 帧构造（`AF_INET/SOCK_RAW/IPPROTO_RAW` + `IP_HDRINCL`、doff=5、TCP/IP csum、伪头）+ 嗅探器（`AF_PACKET`）+ `POST_INJECT_BOARD_FRAME` 见证；**但其 `inject()` 把 `seq` 写死为 `isn+1`**（= 等价域），**不能直接实现 §7.2 的两条配方**。
- ⇒ **本轮的注入器 = 原型的「逐字帧构造 + 发送路径 + 见证格式」+ §7.2 配方的 seq 参数化**（新件 `rfcseq_inject.py`）。**不是自创配方**：配方（两条式子）、判据（线上 ACK + ΔW23）、前置全部按 §7.2；新增的只是"把 seq 从写死改为按配方计算"以及"取 rcv_nxt 的嗅探方向"。
  ⚠️ **取 rcv_nxt 的方向说明**：原型嗅探的是「对端→板」帧的 `(ack,win)`（= 对端的 rcv_nxt，用于 dup-ACK 注入）；本轮需要的是**板的 rcv_nxt（对端→板流）** = **「板→对端」帧的 `ack` 字段**（同一 TCP 语义：一帧的 ack = 发送方的 rcv_nxt）。故嗅探方向取反（含每帧见证，两向都记）。

## 1 臂定义（与派单/设计件的差异，如实登记）

| 臂 | 位流 | sha256（现核） | 与设计件原文的关系 |
|---|---|---|---|
| **P27（正臂-现役）** | `0x27` | `5c17b14f…3385` | 设计件写正臂 = `0x26`；**`0x27` = `0x26` + 换流门 R5**（同一 RFC 修复在内）⇒ 作为"现役位流"正臂一并跑（板已在位，零烧录） |
| **N25（负臂）** | `0x25` | `faefa444…4c85` | 设计件写负臂 = `0x24`（当时的"现役修复前"）；**`0x25` 同为 pre-RFC** 且与 `0x26` **只差 RFC 那一刀**（F-3 只动 `vlan_strip.v`+wrapper；tcp_rx 逐字 = 冻结前缀 `7517c949…`）⇒ 取 `0x25` 作**单变量**负臂（比 `0x24` 更紧） |
| **P26（正臂-单变量对）** | `0x26` | `34e553ee…4202` | 设计件原文的正臂 ⇒ 与 N25 构成"只差 RFC 一刀"的 A/B |

⇒ **主 A/B = N25 ↔ P26**（单变量）；**P27 = 现役位流复核臂**。三臂同构型同配方。

## 2 每臂步骤（同构型；`rfcseq_arm.sh` 逐字同一脚本，仅 EXPECT_BID/位流不同）

1. 前置闸：identity（`p7b_snap.sh id` + BID）+ `0x08 == 0` + `carrier=1` + 无残留进程（p7b_*/tcpdump）+ tcpdump 版本/md5 见证。
2. **快照 S_pre**（`p7b_snap.sh snap <TAG> 5 20 22 23 51 53 54 55 68 70`；W5 时基 / W23 = 判据 / W22 pass / W51·W53·W54 app 对账 / W68 ack_adv）。
3. **SYN 捕获**（小抓包，取对端 ISN，供 rcv_nxt 的**对端侧独立见证**）。
4. 启 `p7b_tcp_src --seconds 300`（单连接，peer→board 数据流；`--no-verify-down` 不用 ⇒ 保留下行核对作健康见证）。等 `SRC_CONNECTED` + 数据流动 ~3 s。
5. **`kill -STOP` src**（冻结上行 ⇒ `rcv_nxt` 静止；对端停读 ⇒ 板下行窗口关 ⇒ 下行转静）。等 ≥0.5 s 静默。
6. **启主抓包**（armed 门：等 `listening on`；`-s 96`；两向 + 端口 8080；本窗口体量小 ⇒ dropped 必须 0）。
7. 跑 **`rfcseq_inject.py`**（对端 root）：
   - 发现 4 元组（lport = 板→对端帧的 dport）+ **rcv_nxt = max(板→对端帧的 ack)**；**同步自检**：`peer_snd_nxt == rcv_nxt`（两向独立见证）。
   - **可行性自证**（设计件 R8）：`rcv_nxt < 2³¹`？否 ⇒ 退码（驱动重开连接，≤5 次）。
   - **安静门**：等"无板侧帧"空档 ≥0.5 s（上限 5 s），记录 ambiente 窗读数。
   - **阳性对照注入（dup 生命探针）**：`seq = rcv_nxt − 1`、1 B 数据段 ⇒ **两臂都应回 ACK**（`ackresp` 在两版本同为 1）；证明"注入帧真达板 + 板可回 ACK"。
   - **目标注入 ×3**（同 `rcv_nxt`，冻结）：
     - **T1** = 配方② `Δ = 2³¹`（**边界行** `d_mod = 0x80000000`，与 xsim F5 同形）；
     - **T2** = 配方② `Δ = 2³¹ + 1 MiB`（内点，与 xsim F1 同类）；
     - **T3** = 配方① `Δ = 0x40000000`（`rcv_nxt < 0x40000000` 时；否则**响亮登记 SKIP** 并改跑配方② `Δ = 2³¹ + 2 MiB`）。
     - 每帧 100 B payload、flags=ACK、doff=5、win=65535、ack = 对端最近一次 (ack,win)。**注入前先打印三行自证**（`D` / `d_mod` / `old=0` / `new=1`）+ 断言 `D ∉ [−2³¹, 2³¹−1]`。
   - 每次注入后 1 s 内逐帧记录板→对端帧（`POST_INJECT_BOARD_FRAME`，含 seq/ack/flags/plen）。
8. **快照 S_post**（同字表）⇒ **ΔW23** 等。
9. 停 tcpdump（`kill -INT` 优雅停）+ 记录 tcpdump 自报（captured/received/dropped**必须 dropped=0**）。
10. `kill -KILL` src（结束连接）；记录 `SRC_SUM`（健康见证）。
11. 落盘：`runs/<TAG>_{inject.txt,src.txt,snap_pre.txt,snap_post.txt,tdump.err,syn.pcap,pcap}` + nstat 前后。

## 4 与派单描述的核对（**与描述不符处，如实说**）

1. **注入器**：派单说"若 §7.2 要求的注入器在盘上缺失 ⇒ 停下回报"。**现读**：§7.2 指定了**原型**（`stall_probe.py`，在盘、可执行），但原型的 `seq` 写死 ⇒ **必须**按 §7.2 配方参数化（否则构造不出目标向）。本件按"原型 + 配方参数化"实现，并在报告里逐条登记。**未自创配方**（式子/判据/前置逐字照抄 §7.2）。
2. **正臂位流**：派单写"板在 `0x27`（若设计件要求另一正臂位流则按件烧）"；设计件写明正臂 = **BID `0x26`** ⇒ 本轮**两者都跑**（P27 零烧录 + P26 按件烧）。
3. **负臂位流**：设计件写 `0x24`；派单允许 `0x25` 或设计件指定者 ⇒ 取 `0x25`（单变量，理由见 §1）。
4. **抓包**：B1 是全窗环形抓包；本轮为控体量取"**静默窗抓包**（`-s 96`，注入前后）+ SYN 小抓包"。偏离已登记（不进判据链：判据 J1/J2/J6 的分帧证据全在静默窗内）。
