## 0. 一句话结论（观测，非裁定）

1. **镜子的内部丢字节计数器（`W70`）在 TCP tap 上 8 跑全 `0`**（合计约 **2.92 MB** TCP 上行）；同一批跑的**板上 TCP app 自己的校验器 `ΔW54 ≡ 0`**（10 跑全，含正控/BAR 臂）。
2. **`MIR_VERIFY rc=0 / first_mismatch=-1` 拿到了**：K = 8192 / 8192 / 16384 三跑 = **从偏移 0 起的逐字节全等**（工具侧 + 离线独立复算**两条路径同值**）；另有一跑**中流 256 KiB 连续段**（离线定位 = 图案流偏移 **535,072**，唯一命中 + 整段逐字节全等）。
3. ⛔ **本镜像读路径有硬上界**：`--dma` 的 16 KB 环 + 每次 C2H 读 ~0.1–1 ms ⇒ **K > 16 KiB 的"从偏移 0 捕获"结构性拿不到**（T1/T2/T3 三跑都在工具侧**响亮** FATAL：计数器跳变 4716–5110 字 > 环容量 4096）；**中流捕获也不可靠**（M1 成 / M2 FATAL）。
4. ⭐ **对 91.9% 那档的拆解（本轮的意外收获，见 §6）**：0x1F 轮 TCP 臂走的是 **user-BAR 路径**（无排空器，主机逐字 mmap 弹出）；**在 0x21 上用同一条读路径复现同族现象**：`pc=48,176 / ΔW70=213,968（81.6%）`。⇒ **那 91.9% 的主因是"读侧/突发容量"，不是镜像写侧的相位缺陷族**（写侧那一族在 UDP 0x20→0x21 A/B 里已单独收口）。
5. **`W70` 的正控拿到了**：cap_en=1 / dma_en=0 / 主机不读 ⇒ `ΔW70 = 63,464 = K(65536) − (FIFO 2048 + acc 8 + stg 16)` **逐位精确**（PC1）⇒ "八跑 0"不是坏计数器。

## 1. 与派单描述不符/需细化的点（如实报，未迁就）

1. **端口：派单写 `8081`，实测 + 源码 = `8080`（TCP）**。板上 TCP 服务端口 = **8080**（`hls/src/layer_tcp.cpp:17` `#define TCP_PORT_ECHO 8080`；历史全部 `p7b_tcp_src` 用法也都是 `--port 8080`）；
   `8081` 是 **UDP app** 端口（`board/wrapper_p4.v:2319` `UDP_APP_PORT = 16'h1F91`，且 8080 在 UDP 侧被 `udp_split.EXCL_PORT` 排除留给 HLS echo）。
   **实测**（收尾件 §A）：`CONNECT_8081 = RC=124`（3 s 超时，无服务）、`CONNECT_8080 = OK`；本轮 **10 跑全部** `SRC_CONNECTED 192.168.100.2:8080` + `ss` 采样里 `ESTAB ... 192.168.100.2:8080`。
   ⇒ 全部测量按 **8080** 跑（派单的 8081 建不起 TCP 连接）。
2. **`--pat-off` 的语义与 UDP 臂不同**：UDP 路要用 `OFF := W11`（app 的**跨帧累计**图案流位置）；**TCP 路是"每连接从偏移 0 起"**（两侧都对：`rtl/app_pattern.v` 的 RX LFSR 在 `ev_up` 重置 ⇒ 板侧期望偏移 0；`p7b_tcp_src` 也是每连接 `P7bPat(0)`）。
   ⇒ 本轮的 `--pat-off` **取 0**（不是 W11）。判据 = 工具自报 `pat_off_eff = 0 + 4×cnt0`，而 `cnt0 == 0`（起测前 arm，连接晚 2 s 才建）⇒ `pat_off_eff = 0` 逐跑自证。
3. **"每配置最多 3 跑"的落法**（事前定，非"重跑到过为止"）：C1 = `--dma` K=256 KiB 全流（T1、T2 两跑）/ C2 = C1 + `fq initial_quantum` 压到 1 MTU（T3 一跑，**证伪"突发来自 fq 初始信用"**）/ C3 = K=8192 全流（T4、T5 两跑）/ C4 = K=16384 全流（T6 一跑）/ C5 = 中流捕获（M1、M2 两跑）/ C6 = user-BAR 路径（BAR1 一跑）/ C7 = W70 正控（PC1 一跑）。共 **10 跑**，每配置 ≤ 3 跑。
4. **`rate_Bps` 不是速率读数**（工具自述）；`secs=2.006` 是"等发端起流"的等待时间。判速只用 `ss` 的 `pacing_rate / delivery_rate` 与发端 `SRC_SUM`。
5. **派单说"TCP 会话由对端发起（板是服务端）"成立**，但**板侧是 `TX_CONTINUOUS=1`（永不主动 close）**，且板 app 还会**持续下发**自己的图案流（对端 `rx_bytes` 每跑 43–1969 KB）——上行测试只依赖"连接不被拆"。

## 6. 【观测】vs【期望】vs 与 0x1F 那档的对打 + 分类

**期望（构建轮 §7-2 的口径）**：0x21 的 STG 修复 = 消掉"相位 ≠ 0 的恒丢失"；TCP 路若同源 ⇒ 应 `ΔW70 == 0` + 内容干净。

| 量 | **0x1F（旧镜像 v1，user-BAR 路径）** | 0x21 · DMA 路径 | 0x21 · user-BAR 路径（BAR1） | 分类 |
|---|---|---|---|---|
| `ΔW70` | **240,932**（= K 的 91.9%） | **0 ×8 跑**（≈2.92 MB） | **213,968**（81.6%） | **读路径决定** |
| `pc`（抓取字节） | 21,212 | 8,192–262,144（见 §3） | 48,176 | 读路径决定 |
| `MIR_VERIFY` | `rc=1 fm=8` | **`rc=0 fm=-1`**（T4/T5/T6） | `rc=1 fm=2076` | — |
| `ΔW53`（app 收字节） | 262,144 = K | = K（逐跑） | 262,144 = K | 两轮一致 |
| **`ΔW54`（板 app 自检）** | **0** | **0** | **0** | **两轮一致：镜像吐不出来的那些字节，app 是全收到的** |
| 账 | `21,212 + 240,932 = 262,144` 闭合 | 闭合 | `48,176 + 213,968 = 262,144` 闭合 | 两轮一致 |

**分类（我的判断，供裁定；非 PASS/FAIL）**：**既不是"与 UDP 那两族严格同源"，也不是"新的独立缺陷"，而是第三类 —— 读侧/突发容量（台架面）**。依据：
1. **读路径就是主因**：把读路径换成与 0x1F 轮 TCP 臂**同一条** user-BAR 路径，同 K、同 pace、同工具，在 **0x21** 上复现同族丢失（81.6%）⇒ 0x1F 的 91.9% 里"读侧/突发"占绝对多数。
2. **镜像写侧的相位族是另一条**：它在 UDP 0x20→0x21 A/B 里单独收口（49.883% → 0）；本轮的 **8 跑 `ΔW70 = 0`（DMA 路径）**说明：**只要消费者跟得上**，TCP 路 1460 B 段的**相位 4** 也不再丢（T4/T5/T6 逐字节全等 = 直接证据）。
3. **不是数据面/协议/内容缺陷**：两轮的 `ΔW54 ≡ 0` 一致；本轮 T4/T5/T6/M1 的抓取内容和图案流逐字节全等。
4. ⚠️ **两轮之间不是严格单变量 A/B**：至少 3 个变量在动（位流 0x1F↔0x21 · 镜像 v1↔STG · **读路径 BAR↔DMA**）⇒ §6 表只作"整体对打"，**逐因归属靠上面第 1/2 条的拆刀**（BAR1 = 只把读路径换回 BAR；UDP 0x20→0x21 = 只换位流）。

## 7. 未定项 / 未观测到（不许当已答）

1. **"读侧/突发容量"的分解粒度**：BAR1 只给了**整条读路径**的证据（主机弹出速率 + FIFO 深度 2 KB + TCP 窗口突发的合成）；**哪一项占多少未分离**（未做"只换环深度 / 只换弹出速率"的臂）。
2. **启动突发的来源未定位**：T1/T2/T3 的跳变 4716–5110 字 ≈ 18.9–20.4 KB ≈ 13 个满段；`initial_quantum 1514` **未缩小**它（T3 反而 5110）⇒ 候选（TCP 初始 cwnd/ACK 时钟、qdisc 信用累计、工具读延迟）**一项都没被单独证实**。**未观测到** ILA/逐拍时间轴见证。
3. **中流捕获不可靠**：M1 成（lag 3286）/ M2 败（4410）⇒ **n=2 的一成一败**，"稳态是否可整段捕获"**判不了**（只有形态登记）。
4. **没有跑线速/不定速的 TCP 上行**：本轮 10 跑全在 **1.5–2.5 MB/s 定速**下（读路径只支持这个量级）。**TCP 线速（~9 Gbps）下镜像的环会被持续回绕覆盖**这件事**未测**；⚠️ 环覆盖**不进 `W70`**（板侧无此计数）⇒ 那条路上"丢"只能靠工具的 `clobber`/FATAL/离线判，**不许把 `ΔW70 == 0` 外推到未测速域**。
5. **`W70` 的第二类（`admit` 上限）**板级**未激励**（正常态结构性不可达）；本轮正控命中的是**FIFO 满**那一类。
6. **相位只覆盖"1460 B 段"（相位 4）这一种**；逐相位矩阵（0..7 的板级扫描）本轮**没有**做（xsim 侧扫描是另一条链）。
7. **端口 8081** 只做了"连不上"的负向读数（RC=124）；**没有**去查板上 8081 上有什么（UDP 8081 是 app 口，属另一条已验收通路）。
8. **收尾探测连接**：§A 的 `CONNECT_8080=OK` 是一次"建连即关"的探测（0 字节、对 `W53/W54/W70` 无痕迹，已由 §5 总账核对）；它带来的板侧连接事件**未单独取证**。
