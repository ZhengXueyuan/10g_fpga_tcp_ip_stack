## 0. 一句话结论（观测，非裁定）

1. **0x23 已上板、身份全中**：`0x04 = 0x00000023` · 71 字窗口（NFF=0）· `0x14C = 0xffffffff` ·
   `LnkSta x4` · `2 BARs` · **`ver=4`**；烧后清零核对全 0（`W11/W13/W70`、`MIR_CTRL`、`MIR_DMA_CNT`）。
2. **P2 干净抓取（回归）**：`--paylen 1472` 与 `--paylen 1470` 两配置**均有全绿跑**（式A=式B=ΔW70=0、
   `pc=taken=K`、`level_end=0 / premise_level0=1`、逐字节 0 失配 + 16/16 车道恒等）。
   ⚠️ **1470 配置的第一跑失败**（`ΔW70=3314` ⇒ 第二次 `read()` 10 s 超时），重跑**逐项全绿且时序与上轮 S2 逐字同**
   —— 形态与候选机理见 §3.3（**不归因**）。
3. ⭐⭐ **P3-① 起测（`clr → cap_en=1`）：上轮那条形态的四个后果在本轮构造下全部未出现** ——
   头 8 B **不是**上一会话残拍（而是新窗口首字节，逐字节 MATCH）；`[8,4096)` **非**全零（全流最长零游程 **2 B**，
   上轮同构造 = 4,088）；抓满 K（`pc = 1,048,576`，上轮 1,044,488）；**无读超时**（`reads=1 partial=0`，上轮 read#2 10 s 超时）；
   `式A = 0`（上轮 4,080 判红）；主体逐字节 = **新窗口** `[5,107,720, 6,156,296)` 全等。
4. ⭐ **P3-② 停流（`MIR_CTRL=0x8`）：恰一拍短尾把残拍交付** —— `dma_from_device -s 8` ⇒ **8/8、RC=0、
   ELAPSED=0 s**（上轮 `-s 16` ⇒ `underflow 0x8/0x10`），内容 = 源流最后 8 B **逐字节 MATCH**；
   闭式 `抓取 K + 短尾 8 = 1,048,584 == K_src − ΔW70` 成立；读后 `level=0`；**无新 dmesg 报错**。
5. **P4（第二优先）已做**：烧 `0x21`（`fbb6fca8…892c`）跑**同参数** `--dma` 一条（MM 臂全绿：
   `bytes=1,048,576 / words=262,144 / clobber=0 / short_reads=0 / fm=-1`），**已烧回 `0x23`**（身份复中）。
6. ⚠️ **P2B 首跑的失败是"宿主空档 ⇒ 镜像丢字节"这一已登记危害的一次现场捕获**（工具自带 `MIR_STREAM_NOTE`
   就写着"宿主空档直接变丢字节"）；**0x23 相对 0x22 的 RTL 差异在"无 clr/无停流"的采集期逐条等价**（§3.3 列证）
   ⇒ 该失败**不作为 0x23 的行为差异证据**；但它的**窗口位置不可观测**（`W70` 无位置）、机理候选**未分离**。

### 3.3 ⚠️ P2B 首跑失败：形态、机理候选与"为什么不当 0x23 的差异证据"

**形态（原始读数）**：read#1（1 MiB）正常返回；**read#2（n=456,704）`Connection timed out`（10 s）**
⇒ `read_error=1 / short=1`；`pc=1,048,576 / taken=1,501,960 / ΔW70=3,314 / 式B=6`；
逐字节账：`1,048,576 + 453,384 + 3,314 + 6 = 1,505,280` ⇒ **read#2 短 3,320 B 永远凑不齐**
（3,314 被镜像丢 + 6 镜像残余）⇒ **read#2 无法完成**。dmesg 包级证据：
`xdma_xfer_submit: xfer …,456704, s 0x1 timed out` + `transfer_abort … desc 112, engine desc queued 0`。
**内容侧无损**：已落盘的 1 MiB 逐字节 0 失配、无洞。

**机理候选（未分离）**：
- (i) **宿主侧描述符空档**：read#1 完成 → read#2 描述符投递之间若停顿 ~ms，引擎无描述符 ⇒ `tready=0`
  ⇒ 成形器停 ⇒ 镜像 FIFO（64 bit × 256 = **2 KB**）溢出 ⇒ 丢字节。按 2.25 MB/s 与观测 drop 反推，停顿时长约 **2.4 ms**。
- (ii) **工具采样突发**：`sample()` 走 AXI-Lite（含 `SNAP_CTRL` 触发 + 最多 1000 次 `SNAP_ST` 轮询 + 3 次寄存器读），
  可能与 C2H 抢 PCIe。
- 工具自带注记原文就写着这一类：`MIR_STREAM_NOTE 采样本身在流上=自造空档 … 宿主空档直接变丢字节`；
  0x22 轮的未定项 §7-7（"采样自造空档的影响未测"）**本轮抓到了它的一次现场**。

**为什么不归因给 0x23**（三条并列，逐条可核）：
① **RTL 结构性等价**（现读 `rtl/axis_c2h_stream.v`）：采集期（`cap_en=1,en=1,clr=0`）内
`stop=0` ⇒ 旧/新 `mv_go` 同为 `b_free && mv_full`、`mv_last` 同为整拍 0、`dma_req` 同式（新式只多一个 `!clr_drop`，
采集期恒 1）；其余差异（`clr_drop` 三处、`qcnt/quiet`）**只在 clr 拍或停流期活动**。
② **同配置重跑全绿**（P2B2：`ΔW70=0`、`reads=2 partial=0`、`secs=2.639` 与 0x22 轮 S2 的 `2.639` 逐字同）；
③ **0x22 轮同一配置、同一工具、同一机器**上也是 `ΔW70=0`（旧 S2 原始件）。
⇒ 结论措辞只到：**"本失败与宿主-描述符/采样时序相关"**；**"哪一种是主因"未分离**（无逐间隙仪器）。
⚠️ 因此**不许**把 P2B 首跑读成"0x23 引入了丢字节"；**也不许**把 P2B2 全绿读成"该危害不存在"（它是概率性的，本轮 n=2）。

## 6. 未定 / 未观测（不许当已答）
