## 1. 逐条发现

### F-1【中】B2 §5-8：`SYNC_CHECK … MISMATCH` 归因（"嗅探器高码率丢帧"）不成立；"+60–75 MB 交叉核"是 1 Hz 采样假象
- **位置**：`p9_board_rfcseq_20261015/REPORT.md:103`（§5-8 及其旁证 (a)/(c)）。
- **三条独立论证**：
  1. **方向性**：`peer_snd` = 嗅探器观测的 `max(seq+plen)`（`rfcseq_inject.py:151-155`），丢帧只能让观测最大值**偏低**——构造不出正的 `peer_snd − rcv_nxt`。要得正 MISMATCH 须 `rcv_nxt` 观测滞后（丢板帧）；但那样注入时刻的 rcv_nxt 会陈旧 ⇒ 板侧响应 ACK 的 `ack` 必 ≠ 注入器 rcv_nxt —— 而这条（承重旁证 (a)）**7/7 跑逐位相等**。⇒ "丢帧"自相矛盾。
  2. **量级不可能**：内核 send 队列受 `SO_SNDBUF` 约束（本工具未设 sndbuf；典型 ≤4 MB），**承载不了 60–75 MB**。
  3. **正解 = 采样滞后**：src 每秒才打印一行（`_proj_pcie/p7b_biz/p7b_tcp_src.cpp:196`）。按每跑自报速率（169–185 MiB/s）反推，**7/7 跑的 SIGSTOP 时刻都落在 3.33–3.39 s**（= 末次 `t=3.000` 打印之后 0.33–0.39 s），差额被精确补上。
- **独立复现**（`rv2_b2_sync.py` → `rv2_B2_SYNC.txt`）：N25 `ISN=0x5518D696`（`syn_2.pcap` sport=43594 = DISCOVER lport，同连接确证）、`rcv−ISN−1 = 592,510,976 B`、src 末次自报 `506.000 MiB = 530,579,456 B`、差 +61,931,520 B；7 跑逐跑 3.33–3.39 s（563.6/168.8、565.1/169.4、562.6/169、564.6/169、625.8/184.9、625.2/184.6、636.1/188.8）；`main_2.pcap` 内对端数据帧 `seq=0x7869D696` 与 `ISN+592.5 MB` 逐位吻合。
- **影响面**：**不影响** J1–J5 的方向与读数。但报告把"嗅探器在高码率下会丢帧（见证只在静默窗内满信度）"登记为仪器缺陷——**缺乏支持**（(a) 反而证明其观测是当前的）；且 MISMATCH 是**结构性**的（对端内核 snd_nxt 领先板 rcv_nxt = 窗口抑制下的在缓存尾），不是异常。
- **建议方向**：§5-8 成因改写为"对端 snd_nxt 领先板 rcv_nxt，真实状态关系、无害"；(c) 改为"1 Hz 采样滞后"口径；"嗅探器丢帧"登记降级为未证实/撤回。

### F-2【低-中】B2：注入器"自捕排除"按 IP-ID 段**不分方向** ⇒ 每跑静默丢弃 ~64–128 条**板侧帧**（本轮逐窗核验 = 零实质影响）
- **位置**：`rfcseq_inject.py:134-136`（`on_pkt` 顶部 `if ID_BASE <= p["ident"] < ID_BASE + 0x40: return`，不分方向）；报告 §5-11 只登记了对端侧版本。
- **问题**：**板侧 IP-ID 是 16 位递增计数器**（实测同窗连续 `0xF4AD/F4AE/F4AF/F4B0`），必然周期穿过标记段 ⇒ 嗅探器对板帧的记账（`board_n`/`rcv_nxt`/quiet 门 `last_board_t`）也按 64/65536 静默漏计。后果面：① 若"响应 ACK"恰带标记 ID ⇒ 漏报（假阴性）；② quiet 门被拖旧 ⇒ 可能把"仍有帧"判成安静。
- **独立复现**：每个 pcap 里板帧落标记段 = **64–128 条**；**逐注入窗核验 28/28**：窗内板帧 IP-ID 全在标记段外（0x424A/0x7024/0xF4AD–B0/0x54DD–E0/0x9E47–49/0x525F–62/0x6DC4–C6）⇒ 本轮零实质影响（与 tcpdump 独立口径逐条一致）。⭐ **旁证**：报告 §5-11 自己的"P27 一跑 77 帧'假标记'"——我复算 P27 main_1 恰 **13 对端帧 + 64 板帧 = 77**，即该数字本身就含 64 条板帧，报告只归因了内核侧。
- **建议方向**：排除条件加方向（只排 `src==MY_IP`）；把"板帧 IP-ID 也可落标记段"并入登记。

### F-3【低-中】B1：`align_check2_fixed.py` 重对齐搜索宽 257→65536 ⇒ "落两个搜索面之外"的断点最坏代价放大约 256×（实测 >600 s 未完成）

### F-4【低】B1 §4.3"三条独立口径互证（每跑都在）"未量化覆盖差异（两处真实缺口）
- **位置**：`p9_board_0x27_k0_20261015/REPORT.md:119`（与 §4.2 表、§6 尾损条并读）。
- **问题**：② pcap 相位口径只覆盖 `[0,n)`：K0P_S3 `n=399,963,935 < sink 400,000,435`（差 **36,500 B = 25 段**，落在 §6"42 包落盘截断"内）；K0P_S2 conn5（dport 34006）`n=199,782,020 < 200,001,020`（差 **219,000 B = 150 段**）。③ 板侧快照覆盖：S2 全跑（`ΔW51=1,200,014,880`、`ΔW20=821,945`，我复算 ✓ 且 = tcpdump received）；**S3 只框住尾部 ~0.16 s**（`ΔW51=111,971,780 ≈ 112 MB` = sink 400,000,435 的 **28%**；`ΔW20=76,806` vs 抓包 274,210）⇒ S3 的"第三口径"名存实微。
