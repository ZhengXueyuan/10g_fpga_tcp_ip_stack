**事实核：45 项中 39 项相符；5 处 ±1 行号漂移、1 处章节归属错、1 条机制措辞需限定（合计 7 条不一致/需限定）**。未发现数值/架构层面的实质错误——设计件的源码锚点整体质量高。

**最重要 3 条：**

1. **D4（`WIN_Q_MAX=0x6000`）与 P2-1（单口零回归）结构性冲突**：同一双口位流无法同时给"单连接 48 KB 窗"和"两连接各 24 KB"；该参数还是 `app_ctrl` 明文禁止的"wrapper 传参"形态；HLS SYN-ACK 仍通告 0xC000 而配额只有 0x6000。

## 2. 分级发现

### 2.1 阻断（1）

**B-1. D4（`WIN_Q_MAX=0x6000`）与 P2-1（单口零回归）结构性冲突，且与 `app_ctrl` 的"不做 wrapper 传参"纪律相抵。**
- 位置：设计件 §4.5 / §5.1 P2-1 / §6.1 D4；`rtl/app_ctrl.v:276-296`、`:283-290`（逐字"**不做成 wrapper 传参**…漏一个就是门与板两个配置"）；`board/wrapper_p4.v:1461-1469`；`hls/src/layer_tcp.cpp:277`（SYN-ACK 通告窗硬编码 `0xC000`）。
- 依据：
  1. P2-1 要求"**双口位流只插 J8**…与 0x2B 同会话 A/B 同档"，但 DUAL 下 `WIN_Q_MAX=0x6000` ⇒ 单连接最大只拿 24,576 B；0x2B 单连接配额是 0xC000（池 49,152、`WIN_CAP_5=0xF000`）。**单口在双口位流里被减半**。
  2. 已入库窗口结论：线空闲 ~88–90% 是窗口门；窗口 ≳30 KB 时板 `WIN_CAP` 咬合、≲20 KB 时对端接管。实测 `minrtt 6–8 / srtt 16–27 µs` ⇒ 24,576 B 的 BDP 只支持 RTT ≤ 19.7 µs，P2-1 的"同档"落在 srtt 上沿之外，可能直接不成立。
  3. 设计件"单口构建不传 ⇒ 零回归"只覆盖**非 DUAL 构建**；P2-1 用的是 DUAL 位流，两者不是同一配置。
  4. `app_ctrl.v:283-290` 明文反对 wrapper 传参；任何 DUAL wrapper TB（G6）都必须镜像 0x6000，否则坑 11。设计件未列这条镜像义务。
  5. HLS `tcp_send` SYN-ACK 仍通告 `0xC000`，fast path 配额只有 0x6000 ⇒ **初始窗 > 配额**（window shrink 场景），接收缓冲影响未登记。
- 建议（需用户裁，不能由实施者默认）：
  - (a) 保持 0xC000：P2-2 只要求两口"各自能建连/身份正确"，不要求两口同时有数据流（第二连接零窗是既有 P5d 语义）；P2-1 字面成立。
  - (b) 采用 0x6000：把 P2-1 改写成"有文档记录的窗口上限回归"，两臂都现取 `ss -ti`，单口速率只要求"24.6 KB 窗口下的可解释值"，并保留一个 `WIN_Q_MAX=0xC000` 的对照构建臂用于归因；同时显式改写 `app_ctrl` 的纪律（或改用别的机制）。
  - (c) 运行时 0x0C 写口需接 app 寄存器总线（板上钉死，`wrapper_p4.v:1547-1549`），不在 P2。
  - 无论哪条，SYN-ACK 0xC000 与配额不一致必须在 P3 前登记。

### 2.2 高（8）

**H-1. 新增输入端口在既有直接例化 TB 中悬空为 Z；"新增端口默认常量 ⇒ 全绿"在 Verilog 里不成立。**
- 位置：设计件 §2.4/§2.7/§5.2 G1；`rtl/udp_rx.v:180-181`、`rtl/udp_split.v:215`、`rtl/udp_tx_cfg.v:124-127`；直接例化点 `tb/tb_app_udp.v:219`（udp_split）、`:311`（udp_tx_cfg）、`tb/tb_udprx_chain.v:232`、`tb/tb_udprx_rate.v:327`、`tb/tb_app_udp_rate.v:162`。
- 依据：输入端口无默认值，未接 = Z。`cfg_dual && (dst==cfg_dst_ip1)` 在非匹配帧上变 X ⇒ `ip_match` X；`cfg_sync` 无条件加入 `peer_my_ip` ⇒ Z==reg 为 X ⇒ `deny` X ⇒ TX 门不可判。设计件只对 `tcp_tx_frame` 写了 Z 论证（那里成立，因为 `PER_CONN_SRC_IP` 是编译期参数），对这三个模块完全没有。
- 建议：`cfg_dual` 做成编译期 parameter（或比较项由参数门控）；`cfg_sync` 新项必须用"后 mux 的期望值"且参数门控；G1 显式列出上述 5 个 TB 例化点并逐个接常量/参数；加"新端口无 Z"断言。

**H-2. P2-3 缺静态邻居前置：SYN 可能根本发不出，判据红在 ARP 而不是错口。**
- 位置：设计件 §5.1 P2-3/§5.4 B-3/§6.1 D1；`hls/src/layer_tcp.cpp:314-315`（`tcp_send` 用 `arp_lookup(peer_ip)`、未知则广播）；`hls/src/layer_arp.cpp:194-201`（ARP 应答 SPA = `board_src_ip(target_ip)`）。
- 依据（源码链）：p1 发 SYN 到 IP_B 前必须解析 IP_B 的 MAC；p1 的 ARP 请求到达板 ch1，HLS 应答 SPA=IP_B ⇒ `slow_tx_adp` 提取端口位 1 ⇒ **从 ch0/J7 发出** ⇒ p1/J8 永远收不到 ⇒ ARP 解析失败 ⇒ SYN 不发出。反向 p0→IP_A 同理。两条错口负对照都会因 ARP 不通而超时，**与出口选口是否正确无关**。设计件说的"ARP 预热"只让板学到对端 MAC，不给对端提供 IP_B/IP_A 的 MAC。
- 建议：nsA 加 `ip neigh add 192.168.100.4 lladdr <BOARD_MAC> dev <p1>`，nsB 对称加 `192.168.100.2`；判据拆两段：① 身份（p1 对 IP_B 的 ARP who-has 无应答）；② 出口（p1 pcap 见 SYN + p0 pcap 见 SYN-ACK 且目的 MAC=p1 MAC + p1 收不到 SYN-ACK）。不做静态邻居时，P2-3 只能叫"ARP 层隔离"，不能冒充出口判据。

**H-3. `slow_tx_adp` 端口位 side FIFO 深度 16 的容量论证错误 ⇒ 慢路径长时阻塞时端口位与帧流永久错位。**
- 位置：设计件 §2.5（"深度 16 ≥ `frame_fifo` 512 字能容纳的最大帧数"）；`rtl/slow_tx_adp.v:80-88`（512×73）、`:136-197` 边收边写、`:199-224` 播放器。
- 依据：512 字 / 最小帧 7 字 = **约 73 帧**（HLS pad 到 60 B、FCS 剥离 ⇒ 56 B），不是 ≤16；`committed` 是 8 位。TCP 泛洪时慢路径 `m_axis_tready` 可长时低（历史实测饿死窗口 ≥33 µs ≈ 5156 拍，足够提交 ~73 个 7 字帧）⇒ side FIFO 在 `frame_fifo` 满之前溢出。溢出后 push 丢位、pop 照常 ⇒ **此后所有帧端口位整体错位**，`side_ovf` 只计数、无恢复。
- 建议：side FIFO ≥128（LUTRAM 便宜）；或在 commit 门加 `almost_full` 时不 commit（走 `wf_rlbk`/`stat_purge` 并计数）；或把端口位塞进 `frame_fifo` 的未用位；单元门断言 `side_fifo_level == committed` 且 `side_ovf==0`（有牙负对照）。

**H-4. 构建 tcl 显式导入清单漏两个新 RTL 文件；缺模块在本流程是"黑盒静默失效"先例。**
- 位置：设计件 §5.3；`board/build_p7b_ku5p.tcl:84-116`（显式 `import_files`，不是 glob）。
- 依据：`build_p7b_ku5p.tcl:96-107` 注释逐字记录"缺它 = 该模块是黑盒（Vivado 对未导入的被例化模块不报硬错…= 安静失效）"。新件 `rtl/rx_merge2.v`、`rtl/tx_demux2.v` 在 DUAL 构建被例化；不导入就不编译。
- 建议：在 `P7B_ADD_DATAPATH`（或新 `P7B_ADD_DUAL`）加两行 import；构建日志加模块解析断言；`elab_files.f` 与 G6 manifest 同步；§5.3 把"新增源文件导入"列为构建前置硬项。

**H-5. `tb_p7b_chain.v` 硬编码 0x2B 几何，但不在 G9 几何更新清单 ⇒ G1 第 20 门必红。**
- 位置：设计件 §5.2 G9；`_proj_10g/p7b_chain/sim/tb_p7b_chain.v:1641-1649`（`0x154/0x158/0x15C/0x160/0x164/0x168/0x16C/0x17C` 硬编码）。
- 依据：NW 83→86 后 W79..W82 移到 `0x16C..0x178`，MIR_STATUS 移到 `0x178`，UNIMPL 移到 `0x188`。现 TB 在 `0x16C` 断言 MIR_STATUS、在 `0x17C` 断言读 0——新几何下 `0x16C` 是 W83、`0x17C` 是 MIR_DATA，必红。P1 轮已手工同步过一次（P1 REPORT §3），P2 必须再做。
- 建议：把 `tb_p7b_chain.v` 加入 G9 清单；G1 改称"编辑后回归"（不是"零编辑"）；构建前置核 `grep -n 0x17C tb_p7b_chain.v` 为空。

**H-6. G6 若沿用 `force txsrc_*`，A-1 TX 全链（`cam_rd_dip→o_port→demux→每口 arb`）无行为门。**
- 位置：设计件 §5.2 G6；`tb_p7b_chain.v:1353-1354` 逐字"注入源 = `txsrc_*`…不测 `u_tx_arb` 内部"；P1 REPORT §2"chain TB 只 force `txsrc_*`，不驱动 `tcp_tx_frame`"。
- 依据：板上生效的 TX 路径是 `tcp_tx_frame → tx_demux2 → 每口 tx_arb → 每口 txcdc → mac_tx_10g`；既有门在 `u_tx_arb` 之后 force，上游零覆盖。G5 只覆盖单元。
- 建议：G6 在 app/UDP/HLS 生产者入口驱动真实帧（或 force 在 `txin_*`/`app2_*`），断言每口 W83/W84、每帧 `o_port` 与帧头源 IP 一致、跨口不串；force 臂只能测 MAC 接线。

**H-7. 观测仅 3 字与"开发期全量"裁定偏离；每口修正项被压成一个数。**
- 位置：设计件 §3.4/§3.5/§3.3；台账 §10-119/§10-123（用户：观测开发期 7 字全量、功能测试后拆最小集）。
- 依据：ch0 TX MAC 计数器明确不进快照；`W28=max`、`W45=ovf0+ovf1` 压掉端口维（单口溢出不可归因）；`rx_merge2` 无 per-port 帧/丢帧计数；W83/W84 是 pre-FIFO。
- 建议：把"P2 开发期只上 3 字"作为**偏离**显式报用户；或加便宜分口观测（如 W45 扩成两个 16 位域/新增一字），至少让 P2-2 有修正项。

**H-8. P2-2 的 W83/W84 对账缺回卷与 pre-FIFO 修正项。**
- 位置：P2-2/B-2；W83/W84 定义；`mac_tx_10g.stat_abort`；W45。
- 依据：W83/W84 32 位 @156.25 MHz ⇒ **27.487 s 回卷**（与 W43 同域）；双口 TCP 测试很容易 >30 s。W83/W84 计数点在 arb 输出（= 交 FIFO），`txcdc` 可能拒写（W45）、MAC 可能 abort（ch1 的 `stat_abort`；ch0 未进快照）⇒ 与对端 `port_rx_*` 的等式需修正项。
- 建议：差值 mod 2³² 记 raw+k；窗 <27 s 或记回卷；对账式写成 `Δpeer ≈ ΔW83 − Δtxcdc_ovf_p0 − Δmac_abort_p0`（ch0 abort 只能写"未观测到"）；若 W45 不能分口读，先按 H-7 加分口计数。

### 3.2 空判据/弱判据清单

1. "对端 carrier up"——空（ch0 常量/IDLE 就能起块锁）。

7. G2 STRICT 负对照——FIFO 不溢出则无牙（M-10）。

9. P2-6 "W83 平"——周期 HELLO/ARP 会打破。
10. "HLS 单口等价"——只证 `dst=IP0`；对 IP_B 的额外接受是设计意图。
11. "WNS 预测"——设计件已声明不可给，正确。
12. `port_rx_*` 与内核计数——同源，只能当跨系统口径。
